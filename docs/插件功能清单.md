# 插件功能清单（Tool 与 Action）

> 适用版本：宿主 `dsh-workbench` 0.6.7；任务插件 5.2.7；标签插件 1.7.0；站点插件 1.10.0；储物插件 1.5.1；消息插件 0.1.0；凭据保险箱插件 0.1.0；连接器插件 0.1.0。
>
> 本文只列 **DSH agent 可调用的 tool 与 action**；客户端按钮、视图内部函数不在范围内。字段级 schema 以运行时 `actions.help` 为准。

## 1. 调用链

```text
DSH Agent
  └─ Workbench（唯一 tool）
       ├─ capabilities.list / capabilities.get   宿主元 action：插件记录什么
       ├─ actions.list / actions.help            宿主元 action：action 的真实字段
       └─ <plugin>.<action>                      业务插件注册的 action
            ├─ tasks.* / taskNodes.*
            ├─ tags.*
            └─ sites.* / siteTags.* / siteNodes.*
```

关键点：

- 业务插件不各自注册 DSH tool，只向宿主注册 action；DSH 只看到 `Workbench` 一个工具。
- `Workbench` 的 `action` 是命名空间字符串，`args` 是该 action 的入参。
- action 名稳定；字段可能演进，调用前用 `actions.help` 确认，不要按旧顶层 schema 猜。

## 2. Tool 清单

### 2.1 `Workbench`

| 项 | 内容 |
| --- | --- |
| 名称 | `Workbench` |
| 注册方 | 宿主 `dsh-workbench` |
| 用途 | 个人工作台统一入口：任务、标签、站点、能力发现 |
| 超时 | 60s |
| 入参 | `action`（必填）、`args`（对象，选填） |
| 返回 | `{ text }`，agent 直接读文本 |

调用示例：

```js
Workbench({
  action: "tasks.create",
  args: { title: "整理发布清单", tablePath: ["开发", "发布管理"], priority: 7, difficulty: 2, targetDate: "2026-11-10" }
})
```

注意：

- 参数必须放 `args`。旧版顶层字段仍兼容，但会按 action 的真实 schema 校验；`due_at` / `tags` / `parentId` 等假字段会明确提示“已忽略”。
- 不带命名空间的旧 action 会映射到 `tasks.*`；新调用请写全命名空间。
- 插件安装/卸载不在本工具里做，走 DSH 插件管理。

### 2.2 为什么没有“每个插件一个 tool”

如果 tasks/tags/sites 各注册一个 tool，DSH 会同时看到三个大 schema，参数重叠且难以维护。现在用一个 `Workbench` + 每个插件自己的 action：

- `capabilities.*` 回答“这个插件记录什么、首选哪个 action”；
- `actions.*` 回答“这个 action 的真实字段是什么”；
- 业务 action 只负责执行。

### 2.3 审计日志（`audit.*`，宿主元 action）

宿主在唯一的 action 分发点记录本机行为账本：谁（`agent` / `ui` / `sync`）在何时调了哪个 action、成功与否、耗时、目标与（脱敏后的）参数。只读 action 默认不记，`capabilities.*` / `actions.*` / `audit.*` 自身不记。

| action | 用途 | 关键参数 |
| --- | --- | --- |
| `audit.list` | 查询审计记录（按时间倒序分页） | `action` / `actionPrefix` / `actor` / `domain` / `ok` / `q` / `target` / `since` / `until` / `page` / `pageSize`（≤200，默认 50） |
| `audit.get` | 单条详情 | `id`（必填） |
| `audit.stats` | 近 N 天汇总（总数/失败数/按 action/按入口/按天） | `rangeDays`（默认 30） |
| `audit.prune` | 清理早于保留期的记录 | `retentionDays`（1~3650，缺省读 `meta.audit.retentionDays` 或 90） |

约束：

- 表 `audit_log` 是平台表，不登记进任何业务域，**不参与同步与备份**；
- 参数中的密码、token、cookie、API key、保险箱/密文等键名一律写成 `***`；单字段超 2000 字符截断，参数整体超 12KB 折叠为 `{"truncated":true,...}`；
- 只读 action 需要留痕时设置 `meta.audit.recordReads=1`；
- 默认保留 90 天，启动时清理一次，之后每 200 次写入惰性清理。

客户端首页「管理」区有「审计日志」卡片（`GET /workbench/api/audit`，支持 `stats=1&rangeDays=30`）。宿主 0.6.4 起，筛选变化立即查询，过期响应不能覆盖当前结果；默认全部且不持久化。结果筛选有明确标签、当前筛选反馈和清除入口，查询按钮保留用于重试。近 30 天统计为独立全局口径，界面明确注明不受筛选影响。

## 3. 能力发现顺序

1. `Workbench({ action: "capabilities.list" })` — 所有插件的能力摘要；可传 `kind` 过滤（`task` / `site` / `tag`）。
2. `Workbench({ action: "capabilities.get", args: { domain: "tasks" } })` — 单插件完整清单：字段字典（方向/范围/默认值）、记录时机、不要记录、去重、关系、示例、action 列表。
3. `Workbench({ action: "actions.list", args: { domain: "tasks" } })` — action 参数与必填项。
4. `Workbench({ action: "actions.help", args: { action: "tasks.create" } })` — 完整 JSON Schema 与示例。
5. 调 `primaryAction`。

`domain` 可写完整 id（`wb-addon-tasks`）或短名（`tasks`）。未声明能力的插件仍会在 `capabilities.list` 中出现，`source` 为 `fallback`，此时直接用 `actions.list`。

## 4. 宿主能力与动作发现 action（5 个）

| Action | 说明 | 入参 | 返回重点 |
| --- | --- | --- | --- |
| `capabilities.list` | 列出各业务插件“记录什么、首选哪个 action” | `kind?` | `domains[]`：summary、records、source、actionCount、warnings |
| `capabilities.get` | 查看单个插件完整能力清单、字段字典与 action 列表 | `domain` 或 `id` | `capability`（fields/records/when/notFor/dedupe/relations/examples）+ `actions[]` + warnings |
| `capabilities.setTaskTarget` | 显式设置业务域对应的开发任务表；null 清除配置，不猜测、不自动建表 | `domain`, `tableId` | 返回配置状态与有效目标路径；失效映射明确提示未配置 |
| `actions.list` | 列出 action、参数与必填项 | `domain?`、`detail?` | `domains[]`、`actions[]`；`detail:true` 带 input schema |
| `actions.help` | 单个 action 的完整 schema、参数说明、示例 | `action`（或 `name`） | `input`、`params`、`examples` |

> 注意：站点插件还有一个业务 action `sites.capabilities`，返回 `tags`（标签子插件是否可用）、`overviewAction: "siteNodes.overview"` 与 `placementGuidance`（先看目录概览再创建站点的归属引导）；它不是宿主元 action `capabilities.*`。

## 4.1 自描述约定（字段字典）

agent 只能看到 tool 自描述，所以每个插件必须在 `capability.fields` 里声明字段字典：`{ name, type, description }`，`description` 要说清**方向 + 取值范围 + 默认值 + 特殊值含义**。`capabilities.get` 会把字典渲染成「字段字典（方向/范围/默认值以此为准）」，并在缺失时给出 warning。

约定：

- 方向必须写死（例如 `priority` 已开启任务是 `1..10`、关闭/完成为 `0`，**数值越大越紧急**，`>=6` 进紧急页签；不要指望 agent 从 “priority” 猜方向）；
- 枚举必须列全（`status` 0=已开启 / 1=已关闭 / 2=已完成 / 3=已重启 / 4=已接取；`statuses` 是 0..4 的整数数组，缺省不过滤状态）；
- 高风险语义写进 **action 描述**，而不是只放文档：`tasks.bulkUpdate` 的 `tags/tagIds` 是整体替换、`tasks.update` 的 `type` 是更新模式而不是任务类型、`tasks.list` 不传 `statuses` 且不传 `urgent` 时返回全部状态（含 3 已重启）；
- 返回结果必须回显生效条件（`filter`）与排序方向，agent 才能自查。

## 4.2 依赖降级（requires）

任务与站点都依赖标签插件提供 `tag` / `tag_mapping` 表，但**表归标签插件所有**：两个插件只读写 `tag_mapping` 里属于自己 `item_type` 的行，不建表、不迁移。为了在没装标签插件时也不骗人：

- 能力清单可以声明 `capability.requires: ["wb-addon-tags"]`；宿主 `capabilities.get/list` 计算 `missingRequires`，缺依赖时在 `warnings` 里追加「依赖未安装：wb-addon-tags；相关参数（如 tagIds/tags）会报错，其余功能正常」，`capabilities.get` 文本还会单列一行「依赖：wb-addon-tags（未安装）」。
- **站点**：传了标签参数（`tagIds`、`tags`、`addTags` 等）却缺标签域时必须抛可读错误「标签域未安装（未安装 dsh-workbench-tags 插件），无法…；去掉参数即可继续」，**不能**抛底层 SQL 错误、也不能静默丢弃或返回空列表。
- **任务**（2026-11-09 起）：标签是可选能力，缺域时不阻断写入——忽略标签参数、正文照常落库，回执带 `notices: [{code:"tag_domain_missing"}]`；读侧省略 `tags` 字段、按标签筛选返回空结果、`groupBy=tag` 返回空分组、`tasks.tags` 返回 `available:false`；客户端隐藏标签输入与筛选。契约测试同样在 `scripts/test-nodeps.mjs`。
- 不带标签参数时两个域的功能完全不受影响（增删改查、统计、数据页、表索引都正常）。
- `tag_mapping` 的同步声明只在标签域（整表行级同步，不区分 `item_type`）；站点域不再重复声明同一张表。站点备份仍导出 `item_type='site'` 的映射行，因为那是站点自己的数据（标签域没装时备份导入会跳过该表）。

契约测试在 `scripts/test-nodeps.mjs`（`pnpm test:nodeps`）：分别只装载「宿主 + 任务」「宿主 + 站点」，断言上面每一条。

契约测试在 `scripts/test-native.mjs` 的「4.3 自描述契约」段：断言字段字典存在且方向/范围正确、`tasks.list` 不传 `statuses` 时不做状态过滤、`sort=-priority` 真的把数值大的排前面、`bulkUpdate` 的 tags 整体替换与 `addTagIds` 增量的行为与描述一致。改实现或改描述时两边必须同时改，否则测试失败。

## 5. 任务插件 `dsh-workbench-tasks`

| 项 | 内容 |
| --- | --- |
| 包名 | `dsh-workbench-tasks` |
| 域 id | `wb-addon-tasks` |
| 版本 | 5.2.6 |
| 表 | `task`、`task_node`、`task_timeline`、`task_timeline_link`、`task_workspace`、`task_workspace_link` |
| 视图 | `stats`、`tasks`、`timeline`、`workspace`（工作区管理）、`config`、`data`、`commands`（只读命令目录）、`actions`（只读 Action 页） |
| 数据页 | 表清单 + 逐列筛选（`dataQuery`）；侧栏「表索引」汇总本域每张表的行数/列数/主键/索引/最近写入（只读） |
| action 数 | 64（`tasks.*` 49 + `taskNodes.*` 11 + `taskTimelines.*` 7） |

**能力摘要**：记录可执行、可交付的工作项（任务），支持任务树、时间线、重启链、依赖与标签（多对多，标签定义归标签域）。

**记录类型 `task` → `tasks.create`**

- 何时记录：一个工作项已经完成或已有明确下一步；用户明确说“记一下 / 建个任务 / 加到工作台”；会话中发现需要后续处理、但当前不立即完成的动作。
- 不要记录：纯信息查询或一次性问答；没有明确标题或完成标准的模糊想法。
- 归属必填：`tableId` 与 `tablePath` 恰选一个；先用 `tasks.capabilities` 或 `tasks.resolveTable` 查看完整路径和职责，再明确选择。新路径仅在 `createMissing:true` 且每个新增段都有职责描述时创建。
- 常用参数：`title`、`description`、`tags`（标签名，缺失自动建）、`priority`、`targetDate`、`tagIds`、`dedupeKey`。
- 没有「类型」字段：工作/生活/学习/开发 已迁成同名标签，一个任务可挂多个。
- 去重：同 `dedupeKey` 的未删除任务会复用；自动记录建议稳定键，如 `dsh-session:<id>`。
- 关系：`taskNode` 通过 `tableId` 归组；`tag` 通过 `tagIds` / `tags.link` 关联。
- 约束：日期为 `YYYY-MM-DD`；`source=1` 需已有 `timelineId`（兼容 `timelineKey`），`source=2` 需 `restartKey` 且原任务已有有效归属；`status` 0 已开启 / 1 已关闭 / 2 已完成，不要直接创建 3（RESTARTED）。
- 标题不唯一：只做 trim + 非空校验，允许与其它任务重名，用 id 区分（与「标签名唯一」「任务节点名同级唯一」是不同规则）。
- 重启优先级：重启需优先级 >0。API `source=2` 未传 `priority` 时回落 1；显式 0 报错。UI 继承原任务有效优先级，原值为 0 时使用配置默认并限制在 1–10；空值/0 当场提示并禁止提交。通过 `capabilities.get` 查看概念说明，`tasks.capabilities` 发现有效任务表。
- 状态机：0 → 1 已关闭（`priority` 清零、补 `shutdownDate`）/ 2 已完成（`priority` 清零、补 `doneDate`）；1 或 2 可回到 0 继续办理；3 已重启只在重启老任务时由 `tasks.update` 写入，create 禁止。
- 分组键：`restart_key` = 重启链链首任务 id（普通任务为自身 id，`source=2` 继承原任务，`tasks.restart` 读取）；`timelineId` = 有效实体归属（普通任务为 null，`source=1` 只能加入已手动创建的线，重启必须继承）；`timelineKey` 是 deprecated 兼容别名。旧列保留用于双写与审阅，历史 key 不自动实体化。
- 分页：`pageSize` 上限 200（超出按 200 截断，`filter.pageSizeCapped=true`）；`total` 为真实总数、`returned` 为本次返回条数、`truncated` 表示是否还有未返回的行；未分页最多 500 条。

### 斜杠命令 `/wb-task-publisher`（5.2.6）

任务插件自带一个面向人的斜杠命令，插件安装或更新后**需要重启 DSH** 才会出现在命令面板。

- 用法：`/wb-task-publisher <需求描述>`，可附截图或文档附件；`/wb-task-publisher` 不带参数只显示用法，不产生模型轮次。
- 命令本身不建任务、不写业务数据：它把用户原话与发布 SOP 作为一条用户消息送入下一轮模型，由 agent 按流程执行。
- brief 固定的七步：A 调研现状（只有代码需求才看仓库，结论区分「用户说的/我查到的/我推测的」并给证据）；B 润色补充（标题「动词+对象+结果」，缺信息标「待确认」）；C 归属（任务表 + 工作区：先 `taskNodes.overview` 选表，多候选且职责相当才问用户，没合适节点就自行建模并 `taskNodes.create` 建组/表，确有新职能域才建组；再 `taskWorkspaces.list` 取候选，按 title/name/description/dir 判断「不关联 / 关联一个 / 关联多个」，能对应到具体目录就 `taskWorkspaces.create` 建一个再挂，判断不了就不挂，禁止按名称相似或列表第一条自动挂，创建时传 `workspaceIds`）；D 时间线（能挂就挂，预计形成 2 个及以上任务的链条就 `taskTimelines.create` 新开一条，只有一单写「无时间线归属」，不硬挂）；E 标签（发布前取现有标签：`tasks.tagOptions` 分页或 `tasks.tags` 全量，按业务域、功能面、动作、影响面选，建议至少 3 个、通常 4–6 个；优先复用同义标签；直接按名字传 `tags`，不用 `tagIds`、不必先 `tags.create`，未知名字受 `form.autoCreateTags` 控制；标签域未安装时仍传 `tags`，任务照常创建、回执写 notices，不停问不重试不虚报）；F 发布（先 `tasks.list` 查重，`source:0`，`dedupeKey` 用会话前缀拼接 `sessionId`，`workspaceIds` 与 `tags` 一起传入，回执含任务 id、路径、工作区归属、时间线、标签、计划完成日期与「本次自建」段）；G 何时停下来问（只有任务表多候选且职责相当、信息互相冲突、查重命中三种；缺任务表/时间线/工作区不再停问，自行补齐并在回执说明）。
- 需求超过 8000 字符时命令返回错误，提示精简或改用附件；`recordInput:false`，同一段需求不会在会话日志里重复记录。
- 无 commands 服务（ACP、无 UI）时命令不注册，插件照常加载。
- 命令的元信息与 SOP 正文分离：目录在 `lib/publisher/catalog.js`（`TASK_COMMANDS`），注册与「命令」页都从这里派生；新增命令只加数组项。
- 「命令」页每条命令都能展开只读的提示词模板：模板由 `buildBrief({ preview: true })` 用占位符 `{需求描述}` / `<sessionId>` / `<生成时间>` 现场渲染，与真正发送的内容同源，页面不另存正文、不可编辑。
- 回归：`pnpm test:task-publisher`、`pnpm test:commands`。

### `/wb-task-publisher` 增加标签步骤（5.2.6）

发布流程原来只到「归属 → 时间线 → 发布」，标签全靠 agent 自觉，结果 2026-11-09～11-11 的存量任务大面积无标签。现在 SOP 插入独立的 **E 标签** 步（原发布、停问顺延为 F/G），要求先枚举现有标签再按维度选：业务域（tasks/tags/sites/storage/宿主/工作台）、功能面（UI/数据/统计/命令/发布）、动作（新增/优化/修复/重构/调研）、影响面（用户可见/内部/跨插件）；语义准确下尽量多，建议至少 3 个、通常 4–6 个，不设硬上限，但禁止堆无意义标签。

写入方式统一为「按名字传」：`tasks.create` 的 `tags` 接受名称数组，未知名字受 `form.autoCreateTags` 控制（默认自动创建，关闭时报错并列出可用标签），因此不必先 `tags.create`、也不要用 `tagIds`。标签域未安装时不阻断发布：`tags` 照传，任务照常创建，回执 `notices` 说明标签缺失，agent 不得停问、重试或声称已打标。输出格式第 3 条与回执第 4 条都增加标签行（标注沿用/新建，未打标须说明原因）。

改动集中在 `packages/addons/tasks/lib/publisher/brief.js`（SOP 与输出格式）与 `catalog.js`（命令摘要、送入回执与说明文案）；「命令」页只读模板由同一 `buildPublisherBrief` 现场渲染，无需另改。`scripts/test-task-publisher.mjs` 增加步骤顺序、`tags: ["标签名"]`、`form.autoCreateTags`、标签域缺失降级、回执与输出格式含标签、边界规则不重复标签口径等断言。brief 净增约 330 字，未稀释原有 A–D 步骤。

### 储物记录新增「位置」字段（storage 1.5.1）

储物条目原来只有名称、品牌、单位、库存、图片、备注，存放位置只能挤进备注，无法单独展示、搜索或排序。本次新增 `location`（位置）：string、非必填、默认空串、最多 200 字，与品牌同级贯通全线。

- 存储：新库建表带 `location TEXT NOT NULL DEFAULT ''`；老库在 `ensureSchema` 里用 `PRAGMA table_info` 判列后幂等 `ALTER TABLE` 补列，历史记录落空串，不做推断回填。
- 读写：`fieldsOf` 白名单加 location（trim、类型校验、≤200 字），`save` 的 INSERT/UPDATE 列与参数同步；`storage.update` 省略 location 时保留原值。
- 查询：`storage.list` 的关键词 OR 增加 location；`SORT` 增加 `location`，配置 `list.sortColumn` 枚举同步；`storage.dataQuery` 的列标签增加「位置」。
- API：`storage.create`/`storage.update` 的 schema、能力清单 `keyArgs` 与字段说明、`storage.list` 描述都写明位置。
- 界面：编辑表单加「位置」输入（中英双语），卡片元信息显示「位置：…」并配 map-pin 图标，记录页搜索占位改「名称、品牌、位置或备注」，排序下拉加「位置」。
- 备份：导出是 `SELECT *`，旧版备份缺 location 时导入落空串；`sync_change_log` 存整行 JSON，新列随行同步。
- 回归：`scripts/test-storage.mjs` 覆盖默认空串、trim、省略保留、超长/非字符串报错、关键词命中、排序、导出与老库迁移幂等；`scripts/test-storage-cards.mjs` 覆盖卡片展示位置与图标。

### 备份导出端点区分 4xx/500，全量导出跳过不备份的模块（host 0.6.7）

`GET /workbench/api/backup/export` 原来只有一个出口：不传 `modules`（或传 `all`）时遍历全部已启用域，
遇到没有 `exportData` 的域（消息插件就是刻意不备份的）直接整包 500；显式传参出错也一律 500，
调用方分不清「我传错了」和「服务端炸了」。

修正（`packages/shell/src/infra/backup.ts`、`packages/shell/src/infra/network.ts`）：

- 全量导出只打包 `enabled && 有 exportData` 的域，被跳过的域写进 `manifest.skipped`
  （`{id,title,reason:"no-export"}`，可选字段，`formatVersion` 仍为 1，导入侧忽略它）。
- 显式 `modules` 语义更严：不可导出 → 400 `not_exportable`，未知 id → 400 `invalid`，
  无可导出模块 → 400；只有导出执行期异常才 500 `export`，且不返回堆栈，日志记录模块 id。
- 备份页不变（仍按勾选传具体 id），错误文案直接取自 `error` 字段。
  契约与 curl 示例见 [15-数据备份](./specs/15-数据备份.md) 的「导出端点契约」。

### 全屏页的返回按钮不再被窗口拖拽区吞掉（host 0.6.6）

macOS 桌面端把窗口顶部若干行标记为 `-webkit-app-region: drag`。Electron 的拖拽区按图层几何计算：
覆盖在 drag 区之上、又没有声明 `no-drag` 的元素，点击会被当成「拖窗口」，事件到不了按钮 ——
表现就是四个插件的全屏页里「← 返回首页」点不动，用户被困在插件页。

修正（`packages/shell/client/styles.cjs`，一处共享层改动，四个插件同时生效）：

- 全屏页仍然铺满整个窗口（`position: fixed; inset: 0; height: 100vh`），外观与之前一致；
- 覆盖层根节点声明 `-webkit-app-region: no-drag`，把宿主 chrome 的 drag 区从这块区域里减掉，
  点击落到插件页而不是窗框上；
- 工具栏空白段恢复 `drag`（仍可拖窗口），工具栏内的按钮/输入框统一 `no-drag`，与宿主 chrome 行的约定一致；
- 顶部仍用 `padding-top: var(--dsh-frame-top-clearance, 0px)` 让开红绿灯与控制区，其余三边不留白；
- 新增 `scripts/test-shell-immersive.mjs`（`pnpm test:shell-immersive`）锁定以上约束。

### 时间线视图（3.2.0）

顶层顺序为统计、记录、时间线、配置、数据。时间线为独立手动创建的实体，通过唯一 task_id 关联表形成 1:N。页面默认显示空线和单成员，支持创建、改名、编辑描述、删除（保留任务）、显式添加/移出任务、分页搜索和整线合并；合并先 dryRun 再确认。任务未关联时显示“没有关联时间线”；重启必须继承原有有效归属，无关联先手动建线并关联，失败零写。

列表每项返回 timelineKey/title/taskCount/openCount/doneCount/firstPublishDate/lastActivityDate；另含 timelineId/description/timelineUpdatedAt，标题由实体独立维护。API默认只显示多成员，includeSingletons=true显示全部（包括空线）。最近活动日取发布、完成、关闭、创建和更新日期的最大本地日，不含计划完成日。整线合并只迁移有效成员，返回 selectedCount 与 wouldUpdate（预览）或 updated（执行），不返回全量成员 id；旧 ids 模式保持兼容。

实体管理 action：

| Action | 行为 | 参数 |
| --- | --- | --- |
| `taskTimelines.create` | 手动创建空线 | `id?`, `title?`, `description?` |
| `taskTimelines.get` | 读取有效实体 | `timelineId`（兼容 `timelineKey`） |
| `taskTimelines.update` | 改标题/描述，不改任务 | `timelineId`, `title?`, `description?` |
| `taskTimelines.delete` | 软删线并移出成员，保留任务 | `timelineId`, `dryRun?` |
| `taskTimelines.attach` | 任务加入/换至有效线，幂等 | `taskId`, `timelineId` |
| `taskTimelines.detach` | 移出任务，保留空线 | `taskId` |
| `taskTimelines.migrate` | 只读审阅默认；审批清单回填 | `dryRun?`（默认 true），实际执行需 `approvedKeys` 与 `snapshotHash` |

备份 v3 包含实体、关系、墓碑与迁移 manifest，移除了任务排序值；兼容导入 v1/v2，v1 导入不把旧 key 自动建为实体。同步乱序关系仅保存，三方有效后才投影；旧设备不同 key 进入待审阅候选，不能覆盖实体归属。迁移报告含 syncCandidates，不能仅凭同步提示直接批准回填。

### 列表状态与时间范围（3.4.0）

`tasks.list` 与按条件导出的 `tasks.export` 支持 `publishFrom` / `publishTo`，分别可选，空字符串按未传处理。两端均含当天，以 `publish_date` 前十位比较，兼容历史时间部分；严格验证真实的 YYYY-MM-DD 日期。起始晚于终止时自动交换，回执 notices 提示「起始晚于终止，已交换」，筛选摘要显示归一后的发布日范围。与关键词、标签、页签及其他条件取 AND。

新增 `doneFrom` / `doneTo`、`shutdownFrom` / `shutdownTo`，与发布范围共用真实日期校验和归一逻辑；对应反序提示为 `done_range_swapped`、`shutdown_range_swapped`。三组范围取 AND；完成范围要求当前状态 2，关闭范围要求当前状态 1，同时提供两组非空范围时交集为空。

`targetFrom` / `targetTo` 是目标日期区间（含两端，可与任意状态组合），`statuses` 为 0/1/2/3/4 的整数数组（4=已接取），`urgent` 为布尔值；数组内状态与紧急谓词取 OR，再与其他条件 AND；空数组且 urgent=false 表示全部。`urgent` 仍兼容但客户端不再使用。4.0.0 起 `tab` 与 `filterRestarted` 已彻底移除：传了会直接报错，并给出对应的 `statuses` 写法（0→`statuses:[0]`+优先级 8..10、1..4→同名标签、5→`statuses:[1]`、6→`[0]`、7→`[2]`、8→`[]`（全部状态）、9→`[4]`）。单个 `status` 与活动筛选参数继续兼容。

左侧筛选区顶部是快捷筛选（4.1.0）：紧急任务 P8–10、高难度 D4–5、已逾期、今日到期、近 7 天完成、已接取六个按钮，点一下套用对应组合、再点一次回到全部；激活态由当前筛选值精确推导，手动改任何条件都会自动熄灭。下面依次是状态复选框、关键词、标签、优先级区间、难度区间、目标日期范围、四组事件日期（发布/完成/关闭/接取）和未填难度筛选；全部与其他状态互斥，清空选择显式回到全部。每组日期复用原时间范围按钮，点击展开起止日期选择，按钮显示已选范围并支持清除、Esc 关闭回焦，不常驻展开六个输入框。桌面吸顶并在超高时内部滚动，窄屏可折叠。热力图跳转换算为根节点下对应日期的单日范围和状态。动作按钮留在内容区。

节点名称和名称路径的每段上限统一为 40（JavaScript length，即 UTF-16 代码单元；部分 emoji 占两个单位）；最多 32 段、总输入最多 2048 个同口径长度单位。客户端 maxLength、后端错误和 schema 使用同一常量；不涉及数据库迁移。

### 年度任务活动热力图（3.1.5）

### 优先级/难度区间与时间线搜索（3.4.2）

`tasks.list` 与 `tasks.export` 新增 `difficultyMin` / `difficultyMax`（0..5，兼容 0.5 档，非数字或越界抛错、不静默截断），NULL 视作未设置（0）：仅给上限时包含 NULL，下界为 0 时同样把 NULL 算入，下界大于 0 时排除未填难度的任务。`priorityMin` / `priorityMax` 沿用原有 0..10 取整口径，本次为四个端点补充了带字段名的报错（`priorityMin 必须是 0..10 内的数字`）。`filter` 回显实际生效的四个值，列表摘要显示 `P>=6`、`难度2–4` 等。

左侧筛选面板在「标签 / 仅未填难度」之后、三组日期之前有优先级与难度两行：每行是「标签 + 一行单位说明」的标题行加两个数字输入与重置按钮；默认预填完整域（优先级 0–10、难度 0–5，端点等于完整域时不发送筛选参数，避免默认值变成隐性筛选），不再有分组标题与整段说明，`min>max` 自动交换并提示，非法值不写入状态。输入框保留草稿，失焦或回车才提交，避免输入「10」的首位就触发交换。难度区间与「仅未填难度」互斥：勾选后者清空难度区间，设置难度区间则取消勾选。四个值写入会话存储，切换视图再回来或刷新后仍保留；从热力图或排行显式跳转时按导航参数覆盖，不会串用上次的条件。

`urgent` 参数保留在 schema 中供旧链接与外部调用使用，但界面已不再发送它：「紧急任务」改为前端快捷组合，勾选即 `priorityMin=6`、`priorityMax=10`，手动把优先级改回 6–10 时复选框自动勾上，改成其它区间自动取消。口径变化因此明确为「优先级 6–10」，不再包含「优先级低但 2 天内到期」的任务，面板提示里写明了这一点。

`tasks.timelines` 的 `titleKey` 改为同时匹配时间线标题与描述（字面子串、ASCII 大小写不敏感，仍不搜索成员任务标题），与 `includeSingletons` 及其它条件 AND；列表行标题与描述首行摘要都会用 `<mark class="wbt-hit">` 高亮命中词，描述为空不占位。无结果时显示带搜索词的提示，与「暂无时间线」的空态文案区分。

### 最近发布清单（3.4.1）

统计页最近发布、最近完成、最近关闭三张卡各占 4 列，宽屏并列，窄屏堆叠。`lists.recentPublish` 包含全部状态的未删除任务，按 `publish_date DESC, updated_at DESC, id DESC` 排序，缺少发布日期的旧任务置末尾（`date: ""`、`daysAgo: null`，界面显示 `—`）；不受统计时间范围影响。行字段与另外两张最近清单一致。

新增可选参数 `recentPublishLimit`（默认 10，向下取整后夹到 1–50）；配置 `stats.recentPublishLimit` 位于统计分组，客户端透传，默认显示区块包含 `recentPublish`。

### 最近任务的难度与任务表跳转（3.1.3）

`tasks.statsReport` 的 `lists.recentDone` / `lists.recentShutdown` 均返回 `difficulty`（空值归为 0）、`tableId`、`groupId`、`tableTitle`、`tableDeleted`。已删除或不存在的表返回空导航 ID 和 `tableDeleted: true`。

统计页两张最近任务表共用列定义：难度展示星级和数值（兼容半星），0 显示 `—`；仅任务表名称是可键盘操作的链接式按钮，点击进入该表的全部记录列表并清空关键词和标签筛选。已删除表保持普通文本。返回统计页保留区间和滚动位置。

### 难度填写与巡检（3.1.2）

难度与优先级独立：优先级表示紧急程度，难度表示实现复杂度。创建、更新时建议填写 1–5，完成时应补齐；为兼容已有调用，不增加硬必填校验。0 和 null 表示未设置，不能当成最简单。已有半星值仍兼容。

| 难度 | 判定锚点 |
| --- | --- |
| 0 / null | 未设置 |
| 1 | 改文案、样式等单点小改 |
| 2 | 单模块内的局部功能 |
| 3 | 跨 2–3 个模块或带数据读取变更 |
| 4 | 涉及存储、迁移、同步、构建链路 |
| 5 | 跨进程架构重构或需多阶段验证 |

结合改动文件数、是否涉及数据迁移及测试面判断。创建带描述或标签的任务却未填难度时，回执提供 `notices: [{ code: "difficulty_missing", field: "difficulty", message: "建议填写 1–5 难度；0 会被统计为未设置" }]` 软提示；缺省不输出空 difficulty 字段。

巡检未填难度任务，再按实际复杂度分组补齐（不要把全部任务统一猜成同一档）：

```js
Workbench({ action: "tasks.list", args: { statuses: [], difficultyMissing: true, pageNumber: 1, pageSize: 100 } })
Workbench({ action: "tasks.bulkUpdate", args: { ids: ["已核对的任务id"], patch: { difficulty: 2 }, dryRun: true } })
// 核对预览后，使用同样 ids 和 patch，去掉 dryRun 执行。
```

筛选与表、状态、标签等条件取 AND；按 total/returned/truncated 翻页。统计页保留“未设置”桶，并提供未填数量及跳转；列表与卡片只在难度大于 0 时显示星级。新建开放任务即可填写，编辑展示星级和数值。

四个业务插件各有一个只读「Action」标签页，数据由**插件自己**提供：插件在注册 action 时本地记录定义，并注册自己的只读 action `<域>.actionSchema`（`tasks.actionSchema` / `tags.actionSchema` / `sites.actionSchema` / `storage.actionSchema`）；页面通过 `api.call("<域>.actionSchema")` 取数，插件未加载时页面自然降级，不需要宿主了解各插件的内部结构。

宿主仍保留统一接口 `GET /workbench/api/schema`（与 `actions.list(detail=true)` 同源，可带 `?domain=wb-addon-tasks`），服务于宿主自身的跨域场景；它不再是这些插件页面的数据源。

设计说明见 `docs/specs/41-插件自证Action清单.md`。

该页的标签名是「Action」（英文界面仍为 `Actions`），按 action 渲染名称、所属域、必填参数、参数类型（含 `number | string` 这类联合类型）、枚举、默认值、范围/长度等约束与说明，支持搜索、按必填/类型过滤、复制示例、展开原始 JSON Schema；搜索命中的 action 名称、说明与参数文本会高亮，口径与过滤完全一致（示例与原始 JSON Schema 不高亮）。不提供执行入口，读取 schema 不产生任何审计或写入。

## 8.2 消息（message 0.1.0）

消息中心给 agent、子插件与界面提供**一个**发送入口：`message.send`。插件之间不互相 import、不直读对方数据表——子插件在自己的 `apply(ctx)` 里存下 `ctx.workbench`，之后 `host.invoke("message.send", {...}, "ui")` 即可；消息域未安装时按 `host.hasDomain("wb-addon-message")` 降级，不阻断自己的主流程。同理，消息插件不依赖任何业务插件。

数据只落本机（`sync: {tables: []}`，不参与云端同步，也不进业务备份导出）。已读消息默认保留 30 天（`retention.readDays`），未读消息永久保留；总量上限 5000 条，超出时从最旧的已读开始清理，单次最多 200 条。去重靠 `dedupeKey`：同一键在未删除期间只保留一条，重复发送返回 `deduped: true` 与已有消息。

新消息通过宿主 SSE 的 `domain-event` 广播 `message.created`（随后 `message.read`），客户端提示音**只**监听本域事件：默认开启、可配置音量，`audience=agent` 的消息不发声，页面隐藏时默认不响，22:00–08:00 默认不启用免打扰且只放行 warning/error。提示音由 WebAudio 合成，首次点击页面后解锁；界面另有「试听」按钮。

## 8.3 凭据保险箱（vault 0.1.0）

独立域 `wb-addon-vault`，只保存密文与 KDF 参数；`vault_meta` / `vault_secret` 不参与云同步，备份只返回空凭据列表。口令经 scrypt（N=32768, r=8, p=1）派生 KEK，AES-256-GCM 包裹 DEK；单条凭据再用 DEK 加密。DEK 只在宿主进程内存，空闲 15 分钟或手动 lock 后清除。

三种解锁模式：A 全锁（默认，每次启动要解锁）、B 自动解锁但查看凭据需再输口令、C 自动解锁且查看免口令。B/C 用 `$WB_HOME/vault-device.key`（32B，0600）包裹 DEK；切回 A 会删除该文件。

| `vault.setup` | passphrase, mode | passphrase | 首次初始化；仅 ui |
| `vault.unlock` | passphrase | passphrase | 解锁；连续 5 次失败锁 5 分钟；仅 ui |
| `vault.lock` | 无 | 无 | 清除内存 DEK；ui/plugin |
| `vault.setUnlockMode` | mode, passphrase | mode | 切换 A/B/C；切换失败保持原模式；仅 ui |
| `vault.changePassphrase` | oldPassphrase, newPassphrase | 两个 | 只重包 DEK，不重加密凭据；仅 ui |
| `vault.secretList` | q, kind | 无 | 列表只含名称/类型/备注；agent 可读 |
| `vault.secretCreate` | name, kind, secret, meta | name/kind/secret | 新增，明文不落审计；仅 ui |
| `vault.secretUpdate` | id, name, kind, secret, meta | id | 改名/改类型会重加密；secret 留空不轮换；仅 ui |

## 8.4 连接器（connector 0.1.0）

独立域 `wb-addon-connector`，把 RSS/Atom 与 Webhook 内容接进工作台。四张表：`connector_source`（来源定义，参与云同步）、`connector_source_state`（secret_id/cursor/next_run_at/失败计数，本机）、`connector_item`（内容，本机）、`connector_run`（运行记录，本机）。备份只导出来源定义，不含凭据、cursor、条目。

driver 内置 `rss` 与 `webhook`；抓取不引入 XML 依赖，按 `<item|entry>` 边界解析。调度器在插件内每 15 秒检查一次，单次最多 3 个到期来源；失败按 60/120/240…秒指数退避，上限 6 小时。投递统一走 `host.call("message.send", …, "plugin")`，不直写消息表。

| `connector.sourceList` | q | 无 | 来源定义与最近运行状态；不返回 cursor/secret |
| `connector.sourceGet` | id | id | 单个来源定义与状态 |
| `connector.sourceCreate` | name, driver, config, scheduleSec, sink, sinkConfig, enabled, secretId | name/driver | 新建；同事务写 source+state；仅 ui |
| `connector.sourceUpdate` | id, name, driver, config, scheduleSec, sink, sinkConfig, enabled, secretId | id | config 整体替换；仅 ui |
| `connector.sourceDelete` | id | id | 软删除并停止调度；仅 ui |

Webhook 入口为 `POST /workbench/hooks/connector/inbound?source=<id>`。鉴权支持：

- `authMode=token`：token 放在 `header`（默认 `x-webhook-token`），常量时间比较；
- `authMode=hmac`：`x-webhook-timestamp` 毫秒时间戳 + `x-webhook-signature: sha256=<hex>`，签名内容为 `timestamp + "." + rawBody`，窗口默认 300 秒；同一签名只接受一次（进程内重放缓存）。

`sourceBind` 只写 `secret_id`，明文由 `vault.lease` 在运行时租用，列表与数据页都不回显。

## 9. 记录边界与已知缺口

- **能力清单是声明，不是强制校验**：宿主会校验 `kind` 非空/不重复、`primaryAction` 已注册，但不会阻止 agent 绕过清单直接调 action。
- **没有跨插件事务**：一次“任务 + 标签 + 站点”需要多次 action；失败时由调用方自行补偿和去重。
- **站点没有 `dedupeKey`**：自动记录前必须用 `sites.list` 查重；标签允许重名，创建前建议先复用同名标签。
- **任务有 `dedupeKey`**：自动记录建议使用稳定键，避免重复建任务。
- **`capabilities.list` 是紧凑视图**：只返回 kind / title / description / primaryAction；完整的 `when`、`notFor`、`dedupe`、`relations`、`examples` 需要 `capabilities.get`。
- **未声明能力的插件**：`source:"fallback"`，仍可用 `actions.list` 查看 action；不会凭空编造记录类型。

## 10. 会话记录模式（/record）

记录模式是宿主提供的会话级行为开关，不新增 tool，也不改变工具集。开启后，当前会话的 agent 会在完成主任务后，按各业务插件声明的能力清单，把本轮可复用的交付物记成任务、站点或标签。

### 10.1 开关与状态

- 斜杠命令：`/record on`、`/record off`、`/record status`；不带参数显示帮助。
- 对话输入区左侧的记录胶囊：点击开启/关闭，状态与斜杠命令通过 `record-mode` SSE 双向同步。
- 状态按 `sessionId` 存在本机 `workbench.db` 的 `session_mode` 表；不参与同步和备份，也不自动作用于子 agent。
- 仅影响当前会话；关闭后，用户明确说“记一下”时 agent 仍可直接调用 `Workbench`。

### 10.2 注入给 agent 的规则

开启后，宿主通过 `systemPrompt.section` 注入 `workbench:record-mode`（order 为 `PLAN_POLICY` + 10），要求：

1. 先查 `capabilities.list`，需要字段细节时用 `capabilities.get`，再按需 `actions.help`；
2. 只记录同时满足 `when` 且不满足 `notFor` 的内容，没有命中就不写；
3. 用 `records[].primaryAction` 写入，不猜 action 名；
4. 写入前查重：任务用 `tasks.list`（`titleKey`），站点用 `sites.list`，标签用 `tags.list` / `tags.search`；
5. 只新增，不修改、不删除已有数据；
6. 多条记录合并成一行回执，失败只提示一次，不阻塞主任务；
7. plan mode 下不写入。

### 10.3 记录边界

- **任务**：完成的可交付项或明确的下一步；不记纯问答、一次性查询、模糊想法。
- **站点**：以后还会访问的外部站点；排除 `localhost`、`127.0.0.1`、内网地址、临时页和搜索结果页。
- **标签**：可复用的主题分类；不记一次性描述、状态词、日期。
- **一律不记**：聊天内容、日志、临时笔记、token/密钥/密码，以及用户明确拒绝记录的内容。

### 10.4 已知限制

- 这是提示层行为模式，不是 100% 自动入库；agent 仍需判断 `when` / `notFor` 并调用 action。
- 没有跨插件原子写入；一次“任务 + 标签 + 站点”需要多次 action，失败时由调用方补偿。
- 站点没有 `dedupeKey`，必须先用 `sites.list` 查重；标签允许重名，创建前建议先复用同名标签。
- 关闭后不会删除已记录的数据；改删需要用户到工作台 UI 操作。

原理、状态表、prompt 注入时序、设计取舍与故障排查见 [会话记录模式.md](./会话记录模式.md)。

### 难度分布五维切换（5.2.7）

难度分布卡原来只有「当前存量」一种口径，看不出某段时间里完成或关闭的任务难度结构。现在卡内加入 **全部 / 完成 / 发布 / 接取 / 关闭** 五维页签（复用页首时间范围，切换只重取一次 `tasks.statsReport`，不重载整页、不丢其他卡状态）：

### 发布引导边界规则收敛（5.1.3）

brief 的「边界规则」原来有两条与 SOP 重复且方向相反的指令：「不要自动建任务表或任务节点，必须先拿到用户授权」「不做无人值守的全自动发布」。它们和 SOP E/F 冲突——F 要求归属唯一、查重无命中时直接发布，边界却要求先停下要授权，模型读到相反指令会把可发布的需求拦成提问。现在建节点/建表的授权口径只由 SOP C（没有合适节点时给建议路径，获得授权后再创建）定义，能否直接发布只由 SOP F 定义；边界规则只保留「不改 `tasks.create` / `tasks.update` 的 schema 与业务语义、不伪造数据或证据」与「一次性问答、临时查询不建任务，物品登记走 `storage.create`」两条。`scripts/test-task-publisher.mjs` 增加断言：边界段恰好两条、被删文案不再出现、SOP C/F 的口径仍在。

### 筛选面板区间控件收敛（5.1.2）

优先级与难度不再有分组标题和整段说明：每行标题行是「标签 + 单位说明」，下一行只有两个输入框与重置按钮。默认预填完整域（优先级 0–10、难度 0–5，中英文一致），端点等于完整域时不发送 `priorityMin/Max`、`difficultyMin/Max`，因此默认值不会变成隐性筛选；重置把该行恢复为完整域。校验域同步为 0 起（优先级整数、难度 0.5 档），错误提示改为「0–10」「0–5」。窄栏下标题行与输入行都按容器宽度换行，不横向溢出。

### 发布命令不得写出裸会话引用（5.1.1）

`/wb-task-publisher` 生成的 brief 正文曾把 `dsh-session:` 前缀和裸 sessionId 直接连写。DSH 会把用户消息里的 `dsh-session:<base64url>` 当会话引用 URI 解析，裸 id 不是合法 payload，于是下一轮在模型调用前就抛 `invalid session reference URI`。修复方式：brief 只写 `sessionId: <id>`，dedupeKey 改为文字描述「用 `dsh-session:` 前缀拼接上面的 sessionId」，不出现可直接匹配的裸串；`scripts/test-task-publisher.mjs` 增加 `/dsh-session:[A-Za-z0-9_-]+/` 不得命中的回归断言。
