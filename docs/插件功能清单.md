# 插件功能清单（Tool 与 Action）

> 适用版本：宿主 `dsh-workbench` 0.5.2；任务插件 2.6.1；标签插件 1.4.0；站点插件 1.4.0。
>
> 本文只列 **DSH agent 可调用的 tool 与 action**；客户端按钮、视图内部函数不在范围内。字段级 schema 以运行时 `actions.help` 为准。

## 1. 调用链

```text
DSH Agent
  └─ Workbench（唯一 tool）
       ├─ capabilities.list / capabilities.get   宿主元 action：插件记录什么
       ├─ actions.list / actions.help            宿主元 action：action 的真实字段
       └─ <plugin>.<action>                      业务插件注册的 action
            ├─ tasks.* / taskNodes.*
            ├─ tags.*
            └─ sites.* / siteTags.* / siteNodes.*
```

关键点：

- 业务插件不各自注册 DSH tool，只向宿主注册 action；DSH 只看到 `Workbench` 一个工具。
- `Workbench` 的 `action` 是命名空间字符串，`args` 是该 action 的入参。
- action 名稳定；字段可能演进，调用前用 `actions.help` 确认，不要按旧顶层 schema 猜。

## 2. Tool 清单

### 2.1 `Workbench`

| 项 | 内容 |
| --- | --- |
| 名称 | `Workbench` |
| 注册方 | 宿主 `dsh-workbench` |
| 用途 | 个人工作台统一入口：任务、标签、站点、能力发现 |
| 超时 | 60s |
| 入参 | `action`（必填）、`args`（对象，选填） |
| 返回 | `{ text }`，agent 直接读文本 |

调用示例：

```js
Workbench({
  action: "tasks.create",
  args: { title: "整理发布清单", priority: 7, targetDate: "2026-11-10" }
})
```

注意：

- 参数必须放 `args`。旧版顶层字段仍兼容，但会按 action 的真实 schema 校验；`due_at` / `tags` / `parentId` 等假字段会明确提示“已忽略”。
- 不带命名空间的旧 action 会映射到 `tasks.*`；新调用请写全命名空间。
- 插件安装/卸载不在本工具里做，走 DSH 插件管理。

### 2.2 为什么没有“每个插件一个 tool”

如果 tasks/tags/sites 各注册一个 tool，DSH 会同时看到三个大 schema，参数重叠且难以维护。现在用一个 `Workbench` + 每个插件自己的 action：

- `capabilities.*` 回答“这个插件记录什么、首选哪个 action”；
- `actions.*` 回答“这个 action 的真实字段是什么”；
- 业务 action 只负责执行。

## 3. 能力发现顺序

1. `Workbench({ action: "capabilities.list" })` — 所有插件的能力摘要；可传 `kind` 过滤（`task` / `site` / `tag`）。
2. `Workbench({ action: "capabilities.get", args: { domain: "tasks" } })` — 单插件完整清单：记录时机、不要记录、去重、关系、示例、action 列表。
3. `Workbench({ action: "actions.list", args: { domain: "tasks" } })` — action 参数与必填项。
4. `Workbench({ action: "actions.help", args: { action: "tasks.create" } })` — 完整 JSON Schema 与示例。
5. 调 `primaryAction`。

`domain` 可写完整 id（`wb-addon-tasks`）或短名（`tasks`）。未声明能力的插件仍会在 `capabilities.list` 中出现，`source` 为 `fallback`，此时直接用 `actions.list`。

## 4. 宿主元 action（4 个）

| Action | 说明 | 入参 | 返回重点 |
| --- | --- | --- | --- |
| `capabilities.list` | 列出各业务插件“记录什么、首选哪个 action” | `kind?` | `domains[]`：summary、records、source、actionCount、warnings |
| `capabilities.get` | 查看单个插件完整能力清单与 action 列表 | `domain` 或 `id` | `capability`（records/when/notFor/dedupe/relations/examples）+ `actions[]` + warnings |
| `actions.list` | 列出 action、参数与必填项 | `domain?`、`detail?` | `domains[]`、`actions[]`；`detail:true` 带 input schema |
| `actions.help` | 单个 action 的完整 schema、参数说明、示例 | `action`（或 `name`） | `input`、`params`、`examples` |

> 注意：站点插件还有一个业务 action `sites.capabilities`，返回 `{ tags: boolean }`，表示“标签子插件是否可用”；它不是宿主元 action `capabilities.*`。

## 5. 任务插件 `dsh-workbench-tasks`

| 项 | 内容 |
| --- | --- |
| 包名 | `dsh-workbench-tasks` |
| 域 id | `wb-addon-tasks` |
| 版本 | 2.6.1 |
| 表 | `task`、`task_dep`、`task_node` |
| 视图 | `tasks`、`stats` |
| action 数 | 33（`tasks.*` 25 + `taskNodes.*` 8） |

**能力摘要**：记录可执行、可交付的工作项（任务），支持任务树、时间线、重启链、依赖与标签（多对多，标签定义归标签域）。

**记录类型 `task` → `tasks.create`**

- 何时记录：一个工作项已经完成或已有明确下一步；用户明确说“记一下 / 建个任务 / 加到工作台”；会话中发现需要后续处理、但当前不立即完成的动作。
- 不要记录：纯信息查询或一次性问答；没有明确标题或完成标准的模糊想法。
- 常用参数：`title`、`description`、`tags`（标签名，缺失自动建）、`priority`、`targetDate`、`tagIds`、`dedupeKey`。
- 没有「类型」字段：工作/生活/学习/开发 已迁成同名标签，一个任务可挂多个。
- 去重：同 `dedupeKey` 的未删除任务会复用；自动记录建议稳定键，如 `dsh-session:<id>`。
- 关系：`taskNode` 通过 `tableId` 归组；`tag` 通过 `tagIds` / `tags.link` 关联。
- 约束：日期为 `YYYY-MM-DD`；`source=1/2` 时分别需要 `timelineKey` / `restartKey`；`status` 0 进行中 / 1 已关闭 / 2 已完成，不要直接创建 3（RESTARTED）。

## 6. 标签插件 `dsh-workbench-tags`

| 项 | 内容 |
| --- | --- |
| 包名 | `dsh-workbench-tags` |
| 域 id | `wb-addon-tags` |
| 版本 | 1.4.0 |
| 表 | `tag`、`tag_mapping` |
| 视图 | `tags`、`stats` |
| action 数 | 10 |

**能力摘要**：维护跨业务对象的标签；只做归类，不负责记录任务或站点。

**记录类型 `tag` → `tags.create`**

- 何时记录：已有任务或站点需要稳定、可复用的主题分类；用户明确要求创建或复用标签；多个记录共享同一主题且以后还会用。
- 不要记录：一次性描述、状态词或日期；不要为了给单个对象加说明而新建标签，优先复用。
- 常用参数：`name`。
- 去重：没有内置去重；先用 `tags.list` / `tags.search` 查重名，再决定是否创建。
- 关系：`task` 通过 `tags.link(itemType=task)`；`site` 通过 `sites.create(tagIds)` / `sites.update(tagIds)`，由站点插件写入自己的标签映射。
- 约束：标签名最大 64 字符，重名会报错；`tags.link` 的 `itemType` 默认 `task`。

| `tags.search` | 按名称搜索标签（tags.list 的别名，兼容旧 /tag/search） | — | `text`, `pageNumber`, `pageSize` |

| `tags.link` | 批量给业务对象挂标签：tagIds × itemIds 笛卡尔积写入 tag_mapping（itemType 默认 task，site 由站点插件自行写入） | `tagIds`, `itemIds` | `tagIds`, `itemIds`, `itemType` |
| `tags.unlink` | 批量解除标签关联（软删）：可给 tagIds 精确解除，不给则清空这些对象的全部标签 | `itemIds` | `tagIds`, `itemIds`, `itemType` |

## 7. 站点插件 `dsh-workbench-sites`

| 项 | 内容 |
| --- | --- |
| 包名 | `dsh-workbench-sites` |
| 域 id | `wb-addon-sites` |
| 版本 | 1.4.0 |
| 表 | `site`、`site_node`、`site_node_mapping`、`tag_mapping` |
| 视图 | `sites`、`stats` |
| action 数 | 19（`sites.*` 10 + `siteNodes.*` 9） |

**能力摘要**：记录值得再次访问的站点（URL + 目录 + 标签），不记录本地开发地址和内网临时页面。

**记录类型 `site` → `sites.create`**

- 何时记录：用户明确说收藏 / 记录这个站点；会话中产出了以后还会访问的外部站点或文档入口；站点与当前任务相关且不是一次性搜索结果。
- 不要记录：`localhost`、`127.0.0.1`、内网 IP、临时调试地址；一次性搜索结果页、登录页、未确认可访问的链接；没有目录归属的站点。
- 常用参数：`siteName`、`description`、`siteLinks`、`dirIds`、`tagIds`、`bindable`。
- 去重：没有 `dedupeKey`；先用 `sites.list` 按标题 / URL 查重，再决定创建。
- 关系：`tag` 通过 `tagIds` / `sites.update`；`siteNode` 通过 `dirIds`，站点必须归入至少一个目录。
- 约束：`sites.create` 必填 `siteName` 与 `dirIds`；没有目录时先用 `siteNodes.create`；`siteLinks` 元素结构为 `{ link, description, isDefault }`。

```js
// 1) 先拿目录 id

Workbench({

  args: {
    siteName: "DSH 文档",
    description: "DeepSeek Harness 使用文档",
    siteLinks: [{ link: "https://example.com/docs", description: "文档首页", isDefault: true }],
    dirIds: ["1"]

```

## 9. 记录边界与已知缺口

- **能力清单是声明，不是强制校验**：宿主会校验 `kind` 非空/不重复、`primaryAction` 已注册，但不会阻止 agent 绕过清单直接调 action。
- **没有跨插件事务**：一次“任务 + 标签 + 站点”需要多次 action；失败时由调用方自行补偿和去重。
- **站点没有 `dedupeKey`**：自动记录前必须用 `sites.list` 查重；标签重名会直接报错。
- **任务有 `dedupeKey`**：自动记录建议使用稳定键，避免重复建任务。
- **`capabilities.list` 是紧凑视图**：只返回 kind / title / description / primaryAction；完整的 `when`、`notFor`、`dedupe`、`relations`、`examples` 需要 `capabilities.get`。
- **未声明能力的插件**：`source:"fallback"`，仍可用 `actions.list` 查看 action；不会凭空编造记录类型。

## 10. 会话记录模式（/record）

记录模式是宿主提供的会话级行为开关，不新增 tool，也不改变工具集。开启后，当前会话的 agent 会在完成主任务后，按各业务插件声明的能力清单，把本轮可复用的交付物记成任务、站点或标签。

### 10.1 开关与状态

- 斜杠命令：`/record on`、`/record off`、`/record status`；不带参数显示帮助。
- 对话输入区左侧的记录胶囊：点击开启/关闭，状态与斜杠命令通过 `record-mode` SSE 双向同步。
- 状态按 `sessionId` 存在本机 `workbench.db` 的 `session_mode` 表；不参与同步和备份，也不自动作用于子 agent。
- 仅影响当前会话；关闭后，用户明确说“记一下”时 agent 仍可直接调用 `Workbench`。

### 10.2 注入给 agent 的规则

开启后，宿主通过 `systemPrompt.section` 注入 `workbench:record-mode`（order 为 `PLAN_POLICY` + 10），要求：

1. 先查 `capabilities.list`，需要字段细节时用 `capabilities.get`，再按需 `actions.help`；
2. 只记录同时满足 `when` 且不满足 `notFor` 的内容，没有命中就不写；
3. 用 `records[].primaryAction` 写入，不猜 action 名；
4. 写入前查重：任务用 `tasks.list`（`titleKey`），站点用 `sites.list`，标签用 `tags.list` / `tags.search`；
5. 只新增，不修改、不删除已有数据；
6. 多条记录合并成一行回执，失败只提示一次，不阻塞主任务；
7. plan mode 下不写入。

### 10.3 记录边界

- **任务**：完成的可交付项或明确的下一步；不记纯问答、一次性查询、模糊想法。
- **站点**：以后还会访问的外部站点；排除 `localhost`、`127.0.0.1`、内网地址、临时页和搜索结果页。
- **标签**：可复用的主题分类；不记一次性描述、状态词、日期。
- **一律不记**：聊天内容、日志、临时笔记、token/密钥/密码，以及用户明确拒绝记录的内容。

### 10.4 已知限制

- 这是提示层行为模式，不是 100% 自动入库；agent 仍需判断 `when` / `notFor` 并调用 action。
- 没有跨插件原子写入；一次“任务 + 标签 + 站点”需要多次 action，失败时由调用方补偿。
- 站点没有 `dedupeKey`，必须先用 `sites.list` 查重；标签重名会直接报错。
- 关闭后不会删除已记录的数据；改删需要用户到工作台 UI 操作。

原理、状态表、prompt 注入时序、设计取舍与故障排查见 [会话记录模式.md](./会话记录模式.md)。
