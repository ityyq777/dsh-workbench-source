# 14. 自动化逻辑盘点：哪些该搬进内置规则、哪些留下

本篇回答一个问题：**仓库里那些自己开定时器、自己写死阈值的「自动化逻辑」，哪些已经可以由
`DomainDef.automations` 声明、由宿主引擎统一调度，哪些不适合声明式、需要保留在代码里。**

结论先行：真正能外置的是**「周期调用一个已注册 action」**这一类；其余三类必须留下——
依赖运行时现场状态（连接、inFlight、凭据）、按写入次数而不是时间触发、以及**没有 action 入口
的内部循环**（宿主云同步、事件补扫）。后者的外置前提是先补 action 面，属于另一条设计决策。

## 2. 引擎能力缺口

对照 `01a20c92-8c6f-723f-98f9-93a75ce15f44` 定下的 `DomainDef.automations` 声明结构：

| 缺口 | 需要的声明字段 | 归属 | 现状 |
| ---- | -------------- | ---- | ---- |
| 秒级周期 | `trigger.everySeconds` | 改引擎 | **本次已补**：`rule.ts` 的 `normalizeTrigger/nextAt` 支持，与 `everyMinutes` 二选一 |
| 一次性启动延迟 | `trigger.startDelaySeconds` | 不外置 | connector/mail 的延迟只是「启动后先跑一轮」，规则用 `nextAt` 达到同样效果，不新增字段 |
| 事件触发 | `trigger.kind="event"` | 已支持 | 需在 `events.subscriptions` 声明（注册期校验） |
| 条件门 | `condition`（`eq/neq/contains/gt/lt`） | 部分支持 | 目前只对运行上下文求值；「配置项未启用则跳过」这类需要读配置的表达式仍不支持，**不外置** |
| 动作返回值透出 | 运行记录的 `result` | 已支持 | `automation_run` 存 `ok/error`，返回值可在运行详情看 |
| 失败分类 | 运行记录 `error` + 审计 `audit` 钩子 | 已支持 | 内置规则调用写 `[automation]` 日志，跨域调用记 skipped |
| 无 action 入口的循环 | — | 不外置 | 见 §1 的 #1/#2/#4/#5/#6 |

## 3. 迁移顺序与现状

原本计划的顺序是「宿主 → connector → mail → message」。盘点后调整为：

1. **已就绪**：`DomainDef.automations` 声明面（见 [03 SDK 与插件契约](03-SDK与插件契约.md)）与内存注册表
   （`packages/shell/src/infra/automation/registry.ts`），
   插件可以随时声明「周期调用本域 action」的规则，样例见
   [`../../packages/addons/mail/lib/index.js`](../../packages/addons/mail/lib/index.js) 的 `daily-unread-digest`。
2. **本次可外置的只有 #7/#8**，两者都缺一个 `origins: ["plugin"]` 的 action 入口：
   - `mail.sync` 当前 `["ui","agent"]`，加 `plugin` 会扩大「插件能触发同步」的面；
   - message 的超期清理还没有 action。
   这两处都要先补 action 面再声明规则，属于**同一类决策**，留给用户拍板（见 §4 A）。
3. **明确不外置**：#1、#2、#3、#4、#5、#6。理由逐条写在 §1 的「结论」列。

## 4. 待确认

- **A. 是否扩大 action 面来外置 #7/#8**：给 `mail.sync` 加 `plugin` origin、给 message 加
  `message.pruneRead`（`origins:["plugin"]`，不对 ui/agent 开放），然后各声明一条内置规则。
  不接受则两者保持现状，清单里记「不外置」。
- **B. 审计清理（#4）是否改成时间触发**：改了会改变清理时机（现在是每 200 次写入顺手清），
  本轮保持按次数触发。
- **C. mail IDLE（#6）保留在插件内、只把兜底循环外置**：本轮按「整条保留」处理，因为兜底循环
  与 IDLE 共用同一个按到期时间排队的探测器，拆开会让状态机分叉。
- **D. connector 15s tick 改成规则 interval**：规则调度的最小精度是 30s（引擎 tick 周期），
  改成规则会把抓取时效从 15s 拉到 30s，本轮不接受，保留原定时器。
