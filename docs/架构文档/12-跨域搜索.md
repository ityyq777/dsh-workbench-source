# 12 跨域搜索

工作台把一次关键词查询分给已注册的业务域。子插件决定哪些记录能被搜到、匹配哪些字段、怎样显示命中项；宿主负责选择提供者、并行查询和统一排序。当前实例的域清单可通过宿主 action `search.providers` 查询。[返回架构指南](../ARCHITECTURE.md)

## 子插件怎样接入

在插件 `setup` 中用自己的业务域 id 注册 `SearchProvider`。下面以邮件为例，`engine.search` 读取邮件域的本地数据。已有插件会先检查宿主是否提供注册函数，以兼容旧宿主。

```js
if (typeof api.registerSearchProvider === "function") {
  api.registerSearchProvider({
    domainId: "wb-addon-mail",
    search: (q, opts) => engine.search(q, opts),
  });
}
```

`search(q, { limit })` 可以同步返回 `SearchHit[]`，也可以返回 Promise。每条结果至少含 `id` 和 `title`，可用 `snippet` 返回展示摘要，`view` 指向本域视图，`url` 提供外部链接，`at` 提供毫秒时间戳。同一域再次注册会替换旧提供者。注册函数返回注销回调，旧回调只会移除自己注册的实例。[SDK 契约](../../packages/sdk/src/index.ts#L230) · [宿主注册表](../../packages/shell/src/index.ts#L179) · [邮件注册入口](../../packages/addons/mail/lib/index.js#L52)

## 一次查询如何返回

1. 调用 `search.query({ q, domains?, limit? })`。宿主去除关键词两端空白，最多保留 100 个字符。空关键词直接返回空结果。省略 `domains` 或传空数组时查询全部已注册域，指定时使用完整业务域 id。
2. 宿主并行调用选中的提供者。`limit` 是每域查询上限，默认 20，范围 1–50。某域抛错或超出 500 毫秒等待时间，宿主仍返回其他域的结果，并用 `partial: true` 和 `failed` 列明失败域。
3. 宿主给每条命中补上注册时的 `domainId`，过滤缺少 `id` 或 `title` 的记录，再计算相关性。标题忽略大小写，完全匹配、前缀匹配、包含匹配分别取 100、80、60 分；摘要包含关键词加 20 分，有 `url` 加 1 分。同分按 `at` 从新到旧，再按标题排序，最终合并结果最多 100 条。[查询与排序实现](../../packages/shell/src/infra/search.ts#L14)

## 验证接入与排查空结果

先调用 `search.providers`，确认目标域出现在 `domains` 中。插件自己的列表 action 可用，只能证明该 action 的调用链可用；跨域搜索还需要注册提供者。

再选一条本域已存在的记录，用上表中的匹配字段测试。例如，选择一个已保存的站点，把以下示例中的域名片段换成其真实链接的一部分。

```js
Workbench({ action: "search.query", args: {
  q: "example.org", domains: ["wb-addon-sites"], limit: 5
} })
```

检查 `items` 中的记录 id、标题和 `domainId`。若目标域出现在 `failed`，应先排查该域查询出错或超时。若该域已注册、`partial` 为 `false` 且 `items` 为空，再核对关键词命中的列与记录可见条件。响应的 `domains` 列出全部已注册域，即使本次只指定了一个域。
