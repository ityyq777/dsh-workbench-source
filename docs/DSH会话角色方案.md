# DSH 会话角色方案

> 本方案已实现，现行契约以[架构文档 13 会话角色](架构文档/13-会话角色.md)为准；
> 本文保留当时的方案论证与验收场景，两者冲突时以实现与那一章为准。

工作台宿主 0.17.0 在 DSH 对话输入区提供角色选择器。默认选项为「不使用工作台角色」，DSH 按原预设运行，新增角色提示为空。用户可以在同一会话连续发布需求，随后切换到任务执行者处理已经发布的任务。

## 选择与生效时机

- 角色选择按会话保存在本机。刷新或重新打开会话后可恢复，其他会话及子会话各自独立。
- 选择角色后，宿主在组装模型请求时自动注入该角色的职责和规则。Agent 无须调用工具查询自己的角色，仅注入的文本占用输入 token。
- 每一轮使用开始时确定的角色。当前轮次执行过程中选择或取消角色，下一轮生效。切换角色保留已有消息、附件和任务引用。

## 管理角色

打开工作台「角色管理」，查看角色名称、来源、用途、工作规则和允许的工作台动作。插件角色由提供方维护，可以复制到本机后按自己的需要调整。新建、复制出的角色均为独立的用户角色，可编辑或删除。

例如，需要只读的任务核对助手时，可复制「任务执行者」，将名称改为「验收核对员」，把工作规则写为“读取任务并逐项对照验收证据，列出尚未满足的条件”，在动作列表中仅保留所需的查询动作。保存后，在目标会话输入框选择新角色。

角色定义保存在本机。保存修改会产生新版本，原先绑定旧版本的会话需要重新选择。角色被删除后，可在原会话改选其他角色，或选择「不使用工作台角色」。

## 插件契约与权限

子插件在业务域声明可选的 `roles[]`。每项包含插件内唯一的 `id`、显示名 `name`、一句职责 `description`、版本 `version`、工作规则 `instructions` 和工作台动作列表 `actions`。宿主生成带业务域前缀的角色 ID，例如 `wb-addon-tasks/publisher`。插件卸载时其角色从可选目录撤销。

输入区通过 `conversation.input.left` 接入。宿主从运行时确定会话及轮次，在动作发现与执行时检查当前角色的声明范围和已有 agent 授权。原有 DSH 工具继续由 DSH 管理。[工作台架构指南](ARCHITECTURE.md)

## 任务插件

| 角色 | 对话与业务产出 |
| --- | --- |
| 任务发布者 | 讨论阶段只读。明确要求发布时，结合原话和附件调研现状，整理验收标准并查重。归属唯一且信息齐全时直接发布。任务表职责相当、信息冲突或疑似重复时提问。回执给出任务编号和归属。独立需求分别使用可重试的去重键。 |
| 任务执行者 | 先读取指定任务的状态、工作区及验收标准。询问进度时只读，要求执行时推进目标任务并回写进展或阻塞。标记完成时提供可核实的验收证据。 |

用户也可以通过 `/wb-task-publisher <需求>` 单次使用发布者。命令保留用户原文和附件，发布规则和选择器共用同一份定义。该次请求结束后恢复会话原有角色。[发布规则](../packages/addons/tasks/lib/publisher/brief.js) · [角色声明](../packages/addons/tasks/lib/publisher/roles.js)

## 验收场景

1. 新会话直接对话，角色提示为空。选择任务发布者后，首条消息按所选职责处理。
2. 带截图连续发布两条不同需求，取得不同编号。重试第一项沿用其任务编号。
3. 发布者输出任务编号后切到执行者，说「按刚才的验收标准推进」。若有多个目标，先确认任务编号。
4. 使用发布命令时，单次请求按发布者处理。下一轮按该会话原先选择的角色处理。
5. 禁用某项工作台动作后，从当前角色可调用的动作中移除，直接执行也受宿主权限检查。
