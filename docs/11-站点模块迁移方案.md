# 11 · 站点模块迁移方案

> 状态：已完成（2026-11-07）。实现为 `wb-addon-sites@1.0.3`，业务全部本地，
> 云端只负责安装包分发与后续数据备份。标签模块见 [10](10-标签模块迁移方案.md)。

## 1. 结论

- 归档仓库里 **没有 site 后端**（没有 SiteController / Site 实体 / Mapper），
  只有 React 前端与 `siteService.tsx` 声明的一套接口。迁移以「前端实际调用 + 字段语义」
  为准，后端缺失的部分补为本地 action。
- 归档前端只有「站点 + 目录 + 链接 + 标签」四块；行内的「账号」按钮是死按钮，
  既没有页面也没有接口。本期不实现 `site_account / site_account_external`，
  不伪造账号交互。
- 目录树从 MPTT 改为**邻接表 + 路径枚举**：`parent_id + path + sort + depth`；
  根 id=0 是虚拟节点，不落库。子树查询用 `path LIKE '/x/%'`。
- 站点删除、目录删除、目录移动全部改为软删除/增量维护，不物理删行；
  `site_node_mapping` 与 `tag_mapping(item_type='site')` 由本站点插件维护。
- UI 保留旧版的左右分栏、表格列、展开子表、三步表单与筛选语义；
  修掉旧版本里会丢数据或写错表的问题（见 §4.2）。

### 2.3 树与前端约定

- `SiteAntdTreeUtilsClass` 构造 `super(0,-1)`：根 id=0、父 -1；
  `children?id=0` 返回根下的目录数组（虚拟根不落库）。
- 节点同时输出 `parent` 与 `parentId`（旧前端读 `parent`）。
- 每个节点必须有 `children` 数组，否则 `children.map` 会崩。
- 拖拽 `moveNode(dragNode, node, info.node.expanded ? 0 : 2)`：
  `0`=作为目标子节点，`2`=作为目标同级之后。
- 选中目录更新 `{id, path}`；面包屑根显示 Home，跳转时拉 `path_children`
  更新树路径、选中与展开。

## 3. 目标数据模型

平台列沿用 `created_at / updated_at / deleted_at / rev`；时间毫秒整数，id 为 UUIDv7。

```sql
CREATE TABLE site (
  id TEXT PRIMARY KEY,
  site_name TEXT NOT NULL DEFAULT '未命名',
  description TEXT NOT NULL DEFAULT '',
  bindable INTEGER NOT NULL DEFAULT 1,
  site_link TEXT,                       -- JSON: [{description,link,isDefault}]
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted_at INTEGER,
  rev INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE site_node (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  parent_id TEXT NOT NULL DEFAULT '0',  -- 0 = 虚拟根
  path TEXT NOT NULL,                   -- /a/b/c/
  sort INTEGER NOT NULL DEFAULT 0,
  depth INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted_at INTEGER,
  rev INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE site_node_mapping (
  id TEXT PRIMARY KEY,
  site_id TEXT NOT NULL,
  node_id TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted_at INTEGER,
  rev INTEGER NOT NULL DEFAULT 1
);
```

索引：

- `idx_site_updated_at`、`idx_site_created_at`、`idx_site_name`；
- `idx_site_node_parent`、`idx_site_node_path`、`idx_site_node_sort(parent_id,sort)`；
- `idx_site_node_mapping_site`、`idx_site_node_mapping_node`；
- `uk_site_node_mapping(site_id,node_id) WHERE deleted_at IS NULL`。

标签复用 tag 插件的 `tag / tag_mapping`，本站点只读写
`tag_mapping.item_type='site'`；不复制标签表，也不跨 addon 调 action。

## 4. MPTT → 路径枚举

### 4.1 规则

- 根：`parent_id='0'`，`path='/'`，`depth=0`；根不落库。
- 子节点：`parent_id=父 id`，`path=父.path + 自身 id + '/'`，`depth=父.depth+1`。
- 兄弟顺序：`sort` 升序，新建追加到末尾；移动后重排新旧父级。
- 子树：`path LIKE '/x/%'`；后代数量按个人数据量可接受。
- 删除：只软删节点与映射，站点保留；删除后可重建同名目录。
- 移动：禁止移到自己或自己的子树；`moveType=0` 作为目标子节点，
  `2` 作为目标同级之后；移动后重写整棵子树的 `path/depth`。

### 4.2 为什么不用 MPTT

MPTT 的 `lft/rgt` 在一个节点移动时要改动几十上百行，离线多端合并时会产生大量
行级冲突；路径枚举只改被移动子树，且子树查询天然按前缀。代价是重命名/移动要重写
子树 path，但目录规模小，收益更大。

## 5. Action 契约

所有 action 只读写本地 SQLite；结果放在 `{ok:true,result}` 信封里。

### 5.1 目录树（9 个）

| action | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `siteNodes.tree` | — | `SiteDirTreeNode[]` | 完整树，不含虚拟根 |
| `siteNodes.children` | `id` | `SiteDirTreeNode[]` | 直接子目录；id=0 返回根下 |
| `siteNodes.multipleChildren` | `ids[]` | `{id,children}[]` | 批量懒加载 |
| `siteNodes.pathChildren` | `id` | `{id,children}[]` | 根到目标的沿途层级 |
| `siteNodes.path` | `id` | `{id,name,parent}[]` | 面包屑 |
| `siteNodes.create` | `parentId,name` | `{node}` | 默认「未命名」、≤40 字 |
| `siteNodes.rename` | `id,name` | `{node,unchanged?}` | 同名 no-op |
| `siteNodes.move` | `sourceId,targetId,moveType` | `{node}` | 0/2 两种语义 |
| `siteNodes.delete` | `id` | `{deletedNodes,removedMappings}` | 软删子树 + 清映射 |

### 5.2 站点、标签与能力探测（9 个）

| action | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `sites.capabilities` | — | `{tags}` | 标签能力：`wb-addon-tags` 已安装且启用、且表存在 |
| `sites.list` | `nodeId,text,tagIds,pageNumber,pageSize,sortColumn,sortOrder` | `{current,size,total,pages,pageable,records}` | 默认 16，最大 200 |
| `sites.get` | `id` | `{site}` | 含目录路径与标签 |
| `sites.create` | `siteName,description,siteLinks,dirIds,tagIds,bindable` | `{site}` | 名称必填、至少一个目录 |
| `sites.update` | `id` + 可选字段 | `{site}` | 传 dirIds/tagIds 时替换映射 |
| `sites.delete` | `id` | `{deleted,removedNodeMappings,removedTagMappings}` | 软删站点 + 清两类映射 |
| `sites.stats` | — | `{total,tagged,nodes}` | 概览 |
| `siteTags.search` | `text,pageNumber,pageSize` | `{records}` | 默认 10，最大 100 |
| `siteTags.byIds` | `ids[]`（≤500） | `{records}` | 列表拼标签 |

列表过滤：`nodeId` 走目录子树内的 `site_node_mapping`；`tagIds` 用
`tag_mapping` 做 OR；`text` 同时搜 `site_name` 与 `description`（不区分大小写）。
排序字段兼容旧接口的 `update_time/create_time/site_name` 与平台列名。

`sites.capabilities` 每次调用时现算，不在 `setup` 时缓存；因此运行中安装/卸载
标签插件后，站点侧能力会立即变化。标签不可用时，`sites.list/get/create/update`
返回的 `tags/tagIds` 一律为空，传入的 `tagIds` 被忽略但不会删除已有
`tag_mapping`（避免卸载标签插件再编辑站点时丢历史关联）。

写操作都会写 `sync_change_log`（`origin=sync` 时跳过），并 emit
`sites-changed` 或 `site-nodes-changed`；壳通过 SSE 广播为 `addon-event`。

## 6. UI

- 入口：工作台首页「站点」card → 沉浸式全屏页；
- 顶部：标题、总数、新建；左侧目录树，右侧面包屑 + 搜索 +（有标签插件时）标签筛选 + 表格；
- 目录树：虚拟「全部站点」、＋新建、✎重命名、×删除、拖拽、懒加载；
  新建子目录后父节点自动展开并加载 children；
- 表格：勾选/全选、站点名 + 描述 + 默认链接、标签 chips（仅标签插件可用时）、
  创建/更新时间排序、链接/目录展开子表、编辑、删除、批量删除；
- 标签插件未安装/未启用时：不渲染标签列、标签筛选、行内标签 chips；
  新建/编辑弹窗从三步降为两步（基础、目录），不再请求 `siteTags.*`；
- 新建/编辑三步 Modal：基础（名称/描述/多链接 + 默认单选）→ 目录多选 →
  标签搜索多选；保存前校验名称与至少一个目录；
- 目录 Modal：新建根/子目录、重命名、删除确认；删除当前子树后回到根；
- 分页：16/30/50，上一页/下一页；
- 实时：SSE `sites-changed` 刷新列表；`site-nodes-changed` 刷新树；
  标签被其它插件创建/删除（`tags-changed`）时刷新标签筛选缓存；
- 窄屏：目录树收窄，工具栏换行，表格横向滚动；
- 空态/加载/错误/重试/toast 与任务、标签插件保持一致。

## 7. 跨插件边界

- 标签本体归 `wb-addon-tags`；站点插件只读 `tag`、读写 `tag_mapping`。
- 标签被删除时 tag 插件会级联软删 `tag_mapping`，站点列表自然不再显示该标签。
- 站点删除/目录删除会同步软删自己的映射；不会反向删除标签本体。
- 站点插件把“标签”视为可选能力：优先用 `api.hasAddon('wb-addon-tags')`
  判断是否已安装且启用，同时要求 `tag/tag_mapping` 表存在；旧壳没有
  `hasAddon` 时退回表探测。
- 标签能力不可用时，站点本体、目录、链接照常使用，只是隐藏所有标签 UI；
  站点列表/详情不返回标签，写操作忽略 `tagIds`。
- 客户端还会用 `host.addons` 再判一次（`a.enabled !== false`），因此即使
  服务端是旧壳，页面也能在标签插件卸载后隐藏标签相关 UI。

## 8. 云端与备份边界

- 安装包走云端 catalog：`wb-addon-sites@1.0.3` tarball + sha256；
- `site / site_node / site_node_mapping` 都是可备份的本地表；
- `site` 与 `site_node_mapping` 属行级同步（A 类），字段含
  `updated_at/deleted_at/rev`；
- `site_node` 是树形表（B 类）：`sort` 必须整组重排，不能逐行 merge；
  备份/恢复时应整树快照，恢复后本地重建；
- 当前 core 的 `SYNCED_TABLES` 仍是 `tasks/habits`，站点三表尚未接入 push/pull；
  接入时需同时加白名单与树表快照逻辑（见 07）。
