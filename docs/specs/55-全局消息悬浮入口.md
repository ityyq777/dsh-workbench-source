# 全局消息悬浮入口设计（message 0.1.7）

> 编号说明：任务描述里写的是 `52`，但 `52` 已被「统计图表交互设计」占用（`53` 工资记录、`54` 弹幕亦已存在），
> 这里顺延为 `55`，内容与任务一一对应。0.1.7 起入口从「固定两角」升级为「自由拖拽的悬浮球」。

## 1. 要解决的问题

消息插件目前只有「声音」没有「看得见」：人不在消息页时完全不知道有新消息——未读数只能进
插件「收件箱」才看得到，首页卡片描述是静态的，不会随未读变化。

目标：任意页面（工作台首页、任务/站点等插件页、聊天页）常驻一个消息悬浮球；可拖到视口内
任意位置并记住；无未读时干净无红点；有未读时右上角数字角标（99+ 封顶）；收到新消息时按钮
弹跳一次、提示音只响一次；点击直达消息「收件箱」；未读清零角标消失；停在左右边缘且一段时间
不交互时像手机悬浮球一样半隐藏贴边，鼠标靠近再展开。

## 2. 层级与落点

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 挂载点 | 优先 `[data-shell-overlay]`，缺省退 `document.body` | 与弹幕层同一套策略：有宿主浮层容器时跟着它走，没有也能工作 |
| 容器 | `position:fixed; left:0; top:0; width:0; height:0; pointer-events:none`，按钮自身 `pointer-events:auto` | 常驻层不能挡住页面点击；零尺寸容器即使被宿主改成 `auto` 也没有可命中的面积 |
| 定位 | 按钮 `position:absolute`，`left/top` 由 JS 按归一化坐标算成像素 | 自由拖拽、贴边半隐、窗口缩放都只改这两个值 |
| z-index | `860` | 高于弹幕（780），低于弹窗（900）：提示要浮在内容之上，但不能盖住正在操作的对话框 |
| 桌面端 | 容器与按钮都声明 `-webkit-app-region:no-drag` | 顶栏之外也要保证按钮可点；不声明 `drag`（仓库 UI 红线） |

> **点击穿透修复（0.1.6 起，0.1.7 保留）**：容器不 `inset:0` 铺满全屏。宿主浮层容器对直接
> 子元素声明了 `.overlayLayer>*{pointer-events:auto}`，与 `.wbm-float-root{pointer-events:none}`
> 同权重，样式注入顺序一变，全屏容器就会接管整页点击（表现正是「只有气泡按钮可点」）。
> 0.1.7 把容器缩成左上角 `(0,0)` 的零尺寸定位点，按钮靠绝对定位溢出显示；root 与按钮再各写
> 一条内联 `pointer-events`（`none` / `auto`）兜底。

## 3. 位置模型

- 位置统一用**归一化中心坐标** `(rx, ry)`（0–1）保存，读取时按当前视口与按钮实际尺寸换算成
  `left/top` 像素；窗口缩放、换显示器都不会漂。
- 持久化在配置项 `float.customPos`（字符串 `"rx,ry"`，4 位小数，默认空串）：
  - 空串 / 缺少逗号 / 非数字 / 越界 → 回退 `float.position` 指定的角位（`bottom-right` 默认，
    `bottom-left` 镜像），不报错；
  - 拖拽**松手时**才经 `message.configSet` 写一次，拖拽过程中只改 DOM；位移小于 1‰ 不写，
    避免无意义写库；
  - 配置存宿主 meta 表、不参与同步与备份，位置因此按设备/profile 生效。
- 默认角位：距视口边缘 20px（窄屏 12px），并沿用输入框避让 `--wbm-float-lift`（48–140px）。
  `float.customPos` 生效期间不再套用避让，否则拖到右下会被自动顶起；回默认角后恢复。
- 拖拽与缩放后按钮必须完整留在视口内（最小可见 24px 的规则由「完整可见」覆盖，更严格）。
- 「恢复默认位置」：配置页悬浮入口分组下的一行按钮，点击把 `float.customPos` 置空并立即回
  `float.position` 角位；未自定义时禁用，避免无效点击。

## 4. 交互

- 拖拽（Pointer Events，兼容鼠标/触控/触控笔）：
  - 位移 < 5px 视为点击；≥ 5px 进入拖拽，并抑制随后的 `click`（`justDragged` 窗口 120ms）。
  - `setPointerCapture` + 鼠标按下期间挂 window 级 `mouseup` 兜底（捕获可能先丢）；
    `pointerup` / `pointercancel` 共用同一收尾，鼠标拖出窗口松手不会卡在拖拽态。
  - 拖拽中关闭 `left/top` 过渡并跟手移动；松手落定、夹取、换算回归一化坐标并持久化。
  - 半隐藏态按下先整体展开再决定是点击还是拖拽。
- 点击：展开态调用宿主 `navigateAddon("wb-addon-message", "inbox")` 直达收件箱。该调用在聊天页等
  非工作台页面同样成立：宿主会先切到工作台面板、等页面挂载后再补跳（0.8.3 起）。
  - **半隐藏态第一次点击只展开、不跳转**，展开后再点才进收件箱。
  - 已经在消息插件页时不再重复跳转（宿主返回 true 但路由相同，无副作用）。
  - **不清角标**：红点只由服务端未读数决定（`message.read` / `message.unreadCount`），
    本地不猜、不提前清。
- 键盘：按钮是真实 `<button>`，Enter/Space 原生可用；聚焦即展开，`focus-visible` 用
  `--wb-accent` 描环。
- 缺宿主 `navigateAddon`（旧宿主/独立安装）：按钮照常显示计数，点击把一句可读提示写到
  `console.info` 并保持不报错，不静默吞掉点击。

## 5. 边缘收起

- 边缘判定：按钮距视口左或右边缘 ≤ 48px，视为「位于边缘」；中间位置即使空闲也不移动。
- 空闲计时：对该按钮无交互（指针进入/移动/按下、点击、聚焦）开始计时，默认 3000ms 后贴边；
  `float.idleSeconds`（0–60，默认 3，0 = 关闭）可配置。
- 收起形态：**半隐藏**——就近一侧把按钮 50% 移出视口，只留半个圆；悬停、聚焦、开始拖拽
  立即完全展开。
- 半隐藏态来新消息：立即临时完全展开（角标与弹跳可见），停留 2000ms 无交互后重新计时收起；
  停留期间再来消息只顺延停留时间，不重复展开、不重启弹跳；悬停/聚焦/拖拽期间不收。
- 展开态是叠加状态：悬停展开、来消息展开、半隐藏点击展开共用同一个展开结果，收起前分别
  判断来源（指针仍在按钮上 / 临时展开未到期 / 正在拖拽），避免 hover 离开就立刻缩回。
- `float.edgeSnap = false` 时永不贴边；按钮始终完整显示。
- `prefers-reduced-motion: reduce`：不做位移动画，只做即时状态切换。

## 6. 动画

- 新消息：按钮 `translateY(-7px) → 0` 的 600ms bounce（`cubic-bezier(.34,1.56,.64,1)`）。
- 连续消息**合并为一次**：动画进行中（600ms 内）再有消息只更新数字，不排队、不叠加。
- 位置与收起的过渡为 `left/top/box-shadow` 180ms；首次定位完成后才开启（`data-ready`），
  避免挂载瞬间从 `(0,0)` 滑过来；拖拽中关闭过渡。
- `@media (prefers-reduced-motion: reduce)`：不做位移，只让描边闪一次主题色再回落。

## 7. 样式与主题

- 颜色按「应用外壳 token → 工作台插件 token → 中性兜底」三级取，不写死色值：
  - 底色 `--dsw-alias-button-floating-fill`（深色 `#2c2c2e`、浅色 `#fff`），
    兜底 `--wb-card`，最后 `#2c2c2e`；
  - 图标与文字 `--dsw-alias-label-primary`，兜底 `--wb-muted`，最后 `currentColor`；
  - 描边 `--dsw-alias-border-l2`，兜底 `--wb-border`；
  - 角标底色 `--dsw-alias-state-error-primary`，兜底 `--wb-danger`；角标文字
    `--dsw-alias-label-on-color`。
  这样在 DSH 聊天页（自定义深色壁纸、拿不到 `--wb-*`）与工作台插件页里都跟随应用主题，
  不会出现「白块压在深色壁纸上」的错位。
- 按钮是 46px 圆形（窄屏 40px），`border-radius` 同时写在样式表与内联，因为外壳对全局
  `button` 有圆角规则，只靠单类选择器会被压成圆角方块。
- 半隐藏态角标会有一半在视口外，此时直接隐藏角标；来新消息先临时展开再显示。
- 桌面端不声明 `-webkit-app-region: drag`；角标文字用 token 而不是裸 `#fff`，
  在浅深两色下与红色底对比 ≥4.5:1。
- 浅色/深色/自定义深色壁纸三套都要目视核对（见第 10 节截图）。

## 8. 可访问性

- `role="button"` 语义由 `<button>` 自带；`aria-label` 形如「消息，N 条未读」/「Messages, N unread」，
  无未读时为「消息，无未读」。
- 角标数字对读屏不重复播报：角标 `aria-hidden="true"`，语义只通过按钮 `aria-label` 表达。
- 键盘聚焦即展开，与鼠标悬停行为一致；拖动不是唯一操作路径，默认角位与「恢复默认位置」都能
  用键盘/表单完成。

## 9. 降级

| 场景 | 行为 |
| --- | --- |
| 无 `[data-shell-overlay]` | 挂到 `body`，视觉一致 |
| 无 `navigateAddon` | 按钮照常显示与计数，点击给可读提示、不抛错 |
| 旧宿主忽略 `viewId` | 落到 `views[0]`（统计页），不报错；新宿主才直达收件箱 |
| 初始化 `message.unreadCount` 失败 | 不显示角标（未知 ≠ 0），按钮仍可点；下次事件或页面可见时重拉 |
| `float.customPos` 非法 | 静默回退默认角，不抛错、不阻止其它配置生效 |

## 10. 数据流

- **不新建 SSE 连接**：提示音模块 `notify/notifier.cjs` 已经订阅 `GET /workbench/api/events`，
  浮层用它的 `subscribe()` 共用同一条事件流，避免双连接与重复声音。
- 计数规则：
  - 初始：`message.unreadCount` 返回 `{ unread }`。
  - `message.created`：`+1`，并按 `message.id` 去重（同一 id 重复推送不再加）。
  - `message.read`：直接用事件里的 `unread` 覆写（服务端权威值）。
  - 页面从隐藏转可见（`visibilitychange`）：重拉一次 `message.unreadCount`，纠正漏事件。
- 配置（`float` 分组 5 项）：
  - `float.enabled`（bool，默认 true）；
  - `float.position`（`bottom-right` / `bottom-left`，默认 right）；
  - `float.customPos`（string，默认空串，拖拽自动写入，清空回默认角）；
  - `float.idleSeconds`（int 0–60，默认 3，0 = 不自动收起）；
  - `float.edgeSnap`（bool，默认 true）。
  改配置后按钮立即隐藏/移动/换收起策略并持久化，不需要刷新页面（事件驱动，不轮询）。

## 12. 非目标

- 不做系统级通知（Notification API / 桌面托盘）；
- 不做浮层内消息列表/弹窗面板（点击就是进收件箱）；
- 不改提示音默认策略与音色；
- 不做甩抛惯性、弹簧跟随、碰撞等物理玩法（拖动只求拖到哪停到哪）；
- 不做跨设备同步位置，也不按页面分别记位置；
- 不引入拖拽/动画第三方库，也不把 dsh-pet 作为依赖；
- 不引入新的音频资源或新依赖。
