# 全局消息悬浮入口设计（message 0.1.6）

> 编号说明：任务描述里写的是 `52`，但 `52` 已被「统计图表交互设计」占用（`53` 工资记录、`54` 弹幕亦已存在），
> 这里顺延为 `55`，内容与任务一一对应。

## 1. 要解决的问题

消息插件目前只有「声音」没有「看得见」：人不在消息页时完全不知道有新消息——未读数只能进
插件「收件箱」才看得到，首页卡片描述是静态的，不会随未读变化。

目标：任意页面（工作台首页、任务/站点等插件页、聊天页）右下角常驻一个消息按钮；无未读时干净
无红点；有未读时右上角数字角标（99+ 封顶）；收到新消息时按钮弹跳一次、提示音只响一次；
点击直达消息「收件箱」；未读清零角标消失。

## 2. 层级与落点

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 挂载点 | 优先 `[data-shell-overlay]`，缺省退 `document.body` | 与弹幕层同一套策略：有宿主浮层容器时跟着它走，没有也能工作 |
| 容器 | `position:fixed; left:0; right:0; bottom:0; height:0; pointer-events:none`，按钮自身 `pointer-events:auto` | 常驻层不能挡住页面点击；不铺满全屏，见下方 0.1.6 说明 |
| z-index | `860` | 高于弹幕（780），低于弹窗（900）：提示要浮在内容之上，但不能盖住正在操作的对话框 |
| 桌面端 | 容器与按钮都声明 `-webkit-app-region:no-drag` | 顶栏之外也要保证按钮可点；不声明 `drag`（仓库 UI 红线） |

> **0.1.6 点击穿透修复**：容器缩成底部零高度定位带，不再 `inset:0` 铺满全屏。宿主浮层容器对
> 直接子元素声明了 `.overlayLayer>*{pointer-events:auto}`，与 `.wbm-float-root{pointer-events:none}`
> 同权重，样式注入顺序一变，全屏容器就会接管整页点击（表现正是「只有气泡按钮可点」）。
> 零高度容器即使被宿主管成 `auto` 也没有可命中的面积；root 与按钮再各写一条内联
> `pointer-events`（`none` / `auto`）兜底，按钮仍靠 `overflow:visible` 显示在容器外。

## 3. 定位

- 默认右下角：`right:20px; bottom:20px`；`float.position = bottom-left` 时镜像到 `left:20px`。
- 窄屏（`max-width:640px`）：按钮 48px → 40px，边距 20px → 12px，下移到 `bottom:12px`，
  避免贴住系统手势区与 DSH 输入框右侧的图标列。
- 与 DSH 输入区的避让：按钮只占右下角 20px 边距内的 48×48 区域；DSH 输入框右侧图标在输入框
  内部同一水平带，按钮是 `position:fixed` 相对视口，不参与文档流，实测在 1280×800 及以上不重叠；
  窄屏靠缩小与下移让位。

## 4. 交互

- 点击：调用宿主 `navigateAddon("wb-addon-message", "inbox")` 直达收件箱。
  - 已经在消息插件页时不再重复跳转（宿主返回 true 但路由相同，无副作用）。
  - **不清角标**：红点只由服务端未读数决定（`message.read` / `message.unreadCount`），
    本地不猜、不提前清。
- 键盘：按钮是真实 `<button>`，Enter/Space 原生可用；`focus-visible` 用 `--wb-accent` 描环。
- 缺宿主 `navigateAddon`（旧宿主/独立安装）：按钮照常显示计数，点击把一句可读提示写到
  `console.info` 并保持不报错，不静默吞掉点击。

## 5. 动画

- 新消息：按钮 `translateY(-3px) → 0` 的 600ms bounce（`cubic-bezier(.34,1.56,.64,1)`）。
- 连续消息**合并为一次**：动画进行中（600ms 内）再有消息只更新数字，不排队、不叠加。
- `@media (prefers-reduced-motion: reduce)`：不做位移，只让角标背景短暂换成 `--wb-accent`
  再回落（颜色变化，不移动）。
- 可选 ring pulse（角标外扩一圈）同样受 reduced-motion 约束。

## 6. 样式与主题

- 颜色按「应用外壳 token → 工作台插件 token → 中性兜底」三级取，不写死色值：
  - 底色 `--dsw-alias-button-floating-fill`（深色 `#2c2c2e`、浅色 `#fff`），
    兜底 `--wb-card`，最后 `#2c2c2e`；
  - 图标与文字 `--dsw-alias-label-primary`，兜底 `--wb-muted`，最后 `currentColor`；
  - 描边 `--dsw-alias-border-l2`，兜底 `--wb-border`；
  - 角标底色 `--dsw-alias-state-error-primary`，兜底 `--wb-danger`；角标文字
    `--dsw-alias-label-on-color`。
  这样在 DSH 聊天页（自定义深色壁纸、拿不到 `--wb-*`）与工作台插件页里都跟随应用主题，
  不会出现「白块压在深色壁纸上」的错位；0.1.5 修的就是这个配色问题（0.1.4 的
  `var(--wb-card,#fff)` 兜底在聊天页解析不到 token，用了白底）。
- 0.1.6 起容器只占底部一条零高度定位带（`left/right:0;bottom:0;height:0`），
  不再用 `inset:0` 全屏铺开；按钮的 `right/bottom` 仍相对视口底部，视觉位置不变。
  原因见第 2 节：宿主浮层容器对直接子元素的 `pointer-events:auto` 会与容器规则同权重竞争。
- 按钮是 46px 圆形（窄屏 40px），`border-radius` 同时写在样式表与内联，因为外壳对全局
  `button` 有圆角规则，只靠单类选择器会被压成圆角方块。
- 桌面端不声明 `-webkit-app-region: drag`；角标文字用 token 而不是裸 `#fff`，
  在浅深两色下与红色底对比 ≥4.5:1。
- 浅色/深色/自定义深色壁纸三套都要目视核对（见第 10 节截图）。

## 7. 可访问性

- `role="button"` 语义由 `<button>` 自带；`aria-label` 形如「消息，N 条未读」/「Messages, N unread」，
  无未读时为「消息，无未读」。
- 角标数字对读屏不重复播报：角标 `aria-hidden="true"`，语义只通过按钮 `aria-label` 表达。

## 8. 降级

| 场景 | 行为 |
| --- | --- |
| 无 `[data-shell-overlay]` | 挂到 `body`，视觉一致 |
| 无 `navigateAddon` | 按钮照常显示与计数，点击给可读提示、不抛错 |
| 旧宿主忽略 `viewId` | 落到 `views[0]`（统计页），不报错；新宿主才直达收件箱 |
| 初始化 `message.unreadCount` 失败 | 不显示角标（未知 ≠ 0），按钮仍可点；下次事件或页面可见时重拉 |

## 9. 数据流

- **不新建 SSE 连接**：提示音模块 `notify/notifier.cjs` 已经订阅 `GET /workbench/api/events`，
  这里给它加一个 `onMessage(fn)` 订阅口（收到 `message.created` / `message.read` 时回调，
  携带事件名与数据），浮层订阅同一条事件流，避免双连接与重复声音。
- 计数规则：
  - 初始：`message.unreadCount` 返回 `{ unread }`。
  - `message.created`：`+1`，并按 `message.id` 去重（同一 id 重复推送不再加）。
  - `message.read`：直接用事件里的 `unread` 覆写（服务端权威值）。
  - 页面从隐藏转可见（`visibilitychange`）：重拉一次 `message.unreadCount`，纠正漏事件。
- 配置：`float.enabled`（默认 true）、`float.position`（`bottom-right` / `bottom-left`，默认 right）。
  改配置后按钮立即隐藏/移动并持久化，不需要刷新页面（事件驱动，不轮询）。

## 11. 非目标

- 不做系统级通知（Notification API / 桌面托盘）；
- 不做浮层内消息列表/弹窗面板（点击就是进收件箱）；
- 不改提示音默认策略与音色；
- 不做自由拖拽换位（只给左右两侧配置）；
- 不引入新的音频资源或新依赖。
