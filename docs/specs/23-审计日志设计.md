# 23 · 审计日志设计（2026-11-08）

> 对应工作台任务：`01a1bb7a-9efd-7975-9106-343d5b74aab0`（先设计后开发）。
> 实施位置：宿主 `packages/shell/src/infra/audit.ts`（表 + 采集 + 查询）、`packages/shell/src/index.ts`
> （唯一分发点挂钩与 `audit.*` 元 action）、宿主客户端「审计日志」页、`scripts/test-audit.mjs`。

## 1. 为什么需要

现有的 `sync_change_log` 是**同步协议**的变更流水：按行记 `table_name/row_id/op/payload`，
为推送与冲突解决服务。它能回答「这一行什么时候被改过」，但回答不了审计关心的四件事：

1. **谁**：哪个入口干的（agent 调工具 / 桌面 UI 点按钮 / 同步引擎 / 云端拉取）；
2. **通过什么**：哪个 `action`、带了什么参数；
3. **结果如何**：成功还是失败、失败原因、耗时；
4. **影响谁**：目标记录 id。

`tasks.history` / `tasks.changelog` 只覆盖任务插件、且读的是同步流水，标签/站点/宿主自身的
操作（备份导入、配置修改、账号登录）都没有面向人的痕迹。排障时最常见的三个问题——
「这条标签是谁删的」「agent 为什么把 targetDate 改成空」「昨天导入备份覆盖了什么」——
现在都答不上来。

审计日志是**本地行为账本**，不参与同步、不进备份包（避免行为日志被推到云端），但可由
`audit.list` / 页面导出给使用者自查。

## 2. 设计目标与非目标

目标：

- 覆盖所有业务 action 调用（写入默认全记，读操作可选记录）；
- 参数脱敏 + 截断后落库，**永不落明文密码 / token / 保险箱内容**；
- 失败也要留痕（含错误信息与耗时），且审计写入失败绝不影响业务调用；
- 可按 action、入口、成败、时间、关键字、目标 id 查询与分页；
- 保留期可配，默认 90 天，过期清理；
- agent 可用 `audit.list` / `audit.get` / `audit.stats` / `audit.prune` 自举查询，schema 与其他
  action 一样可被 `actions.help` 发现。

非目标（v1 明确不做）：

- 不做防篡改哈希链（本机单用户，威胁模型不成立）；
- 不做跨设备同步与云端聚合（云端审计是另一个产品问题）；
- 不记录 `capabilities.*` / `actions.*` 这类自举元 action（噪声，无审计价值）；
- 不做实时告警与报表导出（后续版本）。

## 3. 采集点：宿主唯一分发函数

宿主 `invoke(action, args, origin)` 是所有调用的必经之路：

- agent：`Workbench` 工具 → `invoke(..., "agent")`；
- 桌面 UI：`POST /workbench/api/domains/:id/actions/:action` → `invoke(..., "ui")`；
- 同步：引擎内部不经过 `invoke`，不产生 action 审计（同步本身另有 report 与 conflict 记录）。

因此采集放在 `invoke` 外层：进入时记开始时间，`invokeInner` 返回后按 `domainId` 落一条；
抛错时落一条 `ok=0` 并把错误文本记入 `error`，然后原样抛出。`audit.*` 与自举元 action 直接跳过。

读操作判定：action 名最后一段命中
`list/get/search/stats/statsReport/help/report/history/changelog/timeline/preview/tree/schema/nav/breakdown/export/data/config` 视为只读。
默认**不记录只读调用**（避免每次列表都写一行），可在 `meta` 表把 `audit.recordReads` 设为 `1`
打开。

## 4. 表结构（宿主库 `workbench.db`）

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  at         INTEGER NOT NULL,          -- 毫秒时间戳（宿主持久时钟）
  actor      TEXT    NOT NULL,          -- agent | ui | sync | other
  action     TEXT    NOT NULL,          -- tasks.update
  domain     TEXT    NOT NULL,          -- wb-addon-tasks
  ok         INTEGER NOT NULL,          -- 1 成功 / 0 失败
  error      TEXT,                      -- 失败原因（截断 2000 字）
  target     TEXT,                      -- 目标记录，"id=xxx" / "taskId=xxx"
  args       TEXT,                      -- 脱敏后的参数 JSON（截断 12KB）
  result     TEXT,                      -- 脱敏后的结果摘要 JSON（截断 2KB）
  duration_ms INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_audit_at     ON audit_log(at);
CREATE INDEX IF NOT EXISTS idx_audit_action ON audit_log(action);
CREATE INDEX IF NOT EXISTS idx_audit_ok     ON audit_log(ok);
```

这是**平台表**：不登记进任何业务域的 `tables`，因此不参与同步与备份；卸载业务插件不会删它。

## 5. 脱敏与截断

递归遍历参数与结果（深度 ≤ 6，对象字段 ≤ 60，数组 ≤ 50）：

- 键名命中 `pass/pwd/token/secret/credential/authorization/cookie/api key/access key/private key/vault`
  （大小写不敏感）→ 值替换为 `***`；
- 字符串 > 2000 字截断并标注原长度；
- 整体 JSON > 12KB 时改为 `{"truncated":true,"preview":"…"}`，绝不写半截 JSON；
- `BigInt`/函数/循环引用统一转字符串或占位，序列化失败写 `"[unserializable]"`。

## 6. action 契约

| action | 说明 |
| --- | --- |
| `audit.list` | 分页查询：`action`（精确）、`actionPrefix`、`actor`、`domain`、`ok`、`q`（action/target/error 模糊）、`target`、`since` / `until`（毫秒或 `YYYY-MM-DD`）、`page`、`pageSize`（默认 50，上限 200） |
| `audit.get` | 按 `id` 取一条完整记录（含脱敏参数与结果） |
| `audit.stats` | 按 `rangeDays`（默认 30）汇总：总数、失败数、按 action / 入口 / 日期分布 |
| `audit.prune` | 清理早于保留期的记录，`retentionDays` 缺省读 `meta.audit.retentionDays`（默认 90），返回删除条数 |

返回一律含 `total` 与 `returned`，与任务分页的新语义保持一致。审计查询本身**不记审计**。

## 7. 保留与清理

- 默认保留 90 天；`meta.audit.retentionDays` 可覆盖；
- 宿主启动时静默清理一次（失败只 `log`，不影响启动）；
- 每 200 次写入触发一次惰性清理，避免长会话无限增长；
- `audit.prune` 可手动指定天数（1..3650）。

## 8. UI

宿主首页「管理」区新增「审计日志」卡片，页面提供：action 关键字、入口选择、仅失败开关、
时间范围（最近 1/7/30 天）、刷新、上一页/下一页；行内展示时间、入口、action、目标、结果、
耗时，点开展示脱敏参数与错误。数据来自 `GET /workbench/api/audit`。

## 9. 隐私边界

- 审计只在本机 SQLite，不上传、不进备份包、不随同步；
- 参数已脱敏，但仍可能包含标题、备注等用户内容，查询页默认折叠明细；
- 删除方式：`audit.prune` 或直接清库；不提供「删除单条」（审计的价值在于完整性）。

## 10. 测试

`scripts/test-audit.mjs` 覆盖：写入与读取、读操作默认不记、`recordReads` 开关、失败记录、
脱敏（password/token/vault 键）、超长字符串与超长 JSON 截断、target 提取、分页与 total、
关键字/成败/时间过滤、stats 分布、prune 保留期边界、审计自身不递归记录。
