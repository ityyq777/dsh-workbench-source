## 2. 数据模型

### 2.1 定名与语义修正

| v2 名称 | 本仓名称 | 说明 |
| --- | --- | --- |
| `key` | `account_key` | `key` 是 SQLite 关键字，改名；语义不变：站点内的用户可读唯一标识（外联 chips 与级联下拉都展示它） |
| `account` | `account` | 登录名，可为空 |
| `external_account_id` | `external_account_id` | v2 注释写作「外部系统账号 ID」是错的：实际指**本库另一站点的一条 `site_account.id`**，不是第三方账号 |
| `is_deleted` | `deleted_at` | 沿用本仓软删口径 |
| `create_time/update_time` | `created_at/updated_at` | 沿用本仓命名 |

### 2.2 空值与可空性

v2 除 `site_id` 外全列可空、未填写存 NULL（`site_service.dart:542-545` `_blankToNull`）。
本仓既有表全部使用 `NOT NULL DEFAULT ''`，数据页与 `filters` 也按空串处理。
**决定：沿用本仓口径 `NOT NULL DEFAULT ''`**，`''` 即「未填写」；迁移时 NULL → `''`。
这是对 v2 的有意语义收敛，写进本文以免日后被当成 bug。

### 2.3 DDL

```sql
CREATE TABLE IF NOT EXISTS site_account (
  id              TEXT PRIMARY KEY,
  site_id         TEXT NOT NULL,
  account_key     TEXT NOT NULL DEFAULT '',   -- 站点内唯一（未删除行）
  account         TEXT NOT NULL DEFAULT '',   -- 登录名
  password        TEXT NOT NULL DEFAULT '',   -- 敏感：本机专用，见 §3
  phone_number    TEXT NOT NULL DEFAULT '',   -- 敏感
  identity_card   TEXT NOT NULL DEFAULT '',   -- 敏感
  remark          TEXT NOT NULL DEFAULT '',
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL,
  deleted_at      INTEGER,
  rev             INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX IF NOT EXISTS idx_site_account_site ON site_account(site_id);
CREATE UNIQUE INDEX IF NOT EXISTS uk_site_account_key
  ON site_account(site_id, account_key) WHERE deleted_at IS NULL;

CREATE TABLE IF NOT EXISTS site_account_external (
  id                   TEXT PRIMARY KEY,
  native_account_id    TEXT NOT NULL,   -- → site_account.id（引用方）
  external_account_id  TEXT NOT NULL,   -- → site_account.id（被引用的另一站点账号）
  created_at           INTEGER NOT NULL,
  updated_at           INTEGER NOT NULL,
  deleted_at           INTEGER,
  rev                  INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX IF NOT EXISTS idx_sae_native ON site_account_external(native_account_id);
CREATE INDEX IF NOT EXISTS idx_sae_external ON site_account_external(external_account_id);
CREATE UNIQUE INDEX IF NOT EXISTS uk_sae_pair
  ON site_account_external(native_account_id, external_account_id) WHERE deleted_at IS NULL;
```

说明：
- 唯一索引带 `WHERE deleted_at IS NULL`，与 `uk_site_node_mapping` 同款，允许软删后重建同 key。
- `account_key` 为空串时不参与唯一：因为索引对 `''` 也会生效，**改为应用层校验**（见 §5），
  索引只在 key 非空时才有意义，故实际写成普通索引更稳妥 —— 实现时取「应用层校验 + 普通索引」，
  避免多条空 key 账号被唯一索引拦截。
- 不加外键（与全仓一致），`site_id` / `native_account_id` 由应用层维护。

## 3. 安全与同步决策（已拍板：方案 B —— 加密后再同步）

### 3.1 决策记录

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| A. 本地专用，不同步 | 未采用 | 换机即丢账号，与「工作台本来就是跨设备用的」矛盾 |
| **B. 写库前加密，字符密文再同步**（选定） | 采用 | 云端 `change_log.payload` / `row_states.payload` 是通用 jsonb，只要同步就是「上传密文、不是明文」；密钥不与密文同行，云端无法解密 |
| C. 只同步非敏感列 | 未采用 | 需要列级同步能力（当前引擎行级），且「手机号能同步、密码不能」无法解释 |

配套决策（用户确认）：**agent 永远拿不到明文**。`sites.accounts.get` 只在 `origin === "ui"` 且保险箱已解锁时返回明文；
`origin === "agent"` 一律返回 `{masked: true, reason: "仅界面可查看"}`。明文的显形与复制只发生在界面进程内。

### 3.2 加密方案：口令保险箱（站点账号保险箱）

仓库目前没有任何本地加密设施（`packages/**` grep `encrypt|safeStorage|cipher` 0 命中），
且插件运行在宿主主进程、要兼顾桌面与 Web 端，所以不依赖 OS Keychain，采用**口令派生密钥**：

1. **首次启用**：用户设置「账号保险箱口令」（≥8 位）。生成 16 字节随机盐，
   用 `scrypt(passphrase, salt, { N: 2^15, r: 8, p: 1, maxmem: 64MB })` 派生出 32 字节密钥；
   盐与校验值写入 `meta` 表：
   - `sites.vault.salt` = base64 盐
   - `sites.vault.verifier` = base64(HMAC-SHA256(key, "sites-vault-v1"))，用于校验口令是否正确
   - **密钥本身绝不落库、不入日志、不进同步**
2. **字段加密**：`password` / `phone_number` / `identity_card` 三列在**写本地库之前**加密，
   存 `v1:<base64 iv>:<base64 tag>:<base64 ciphertext>`（AES-256-GCM，每次随机 12 字节 IV）。
   空串表示「未填写」，不加密。
3. **解锁**：口令 → 派生密钥 → 校验 verifier → 密钥只存在宿主内存；空闲 `vault.idleMinutes`（默认 15）后自动锁定，
   也可手动「锁定」。锁定状态下三列在界面上显示 `••••••`，不提供显形/复制。
4. **同步**：`site_account` / `site_account_external` 加入 `siteSync.tables`（row 模式）。
   同步的是密文字符串，云端无密钥；另一台设备输入**同一口令**即可解密并查看。
5. **口令丢失 = 这三列永久不可读**（账号名、备注等非敏感列仍可读）。设置口令时界面必须明确二次确认这一后果。

> 为什么不把密钥随密文一起同步：那等于把明文放进同一个保险箱再上云，等于没加密。
> 为什么不派生自登录口令：插件拿不到登录口令，且登录口令轮换会让历史密文全部失效。

### 3.3 展示与复制规则（修掉 v2 的明文缺陷）

v2 声明「密码圆点掩码」，实际 `site_account_views.dart:264-299` 因 `realValue` 覆盖掩码而**明文渲染**。本期明确：

1. 密码默认 `••••••`（固定 6 点，**不泄露长度**）；手机号/身份证掩码中段（`138****8000`）。
2. 「显形」：仅在保险箱解锁时可用，显示 `ui.revealMs`（默认 10 秒）后自动回掩码；离开视图立即回掩码。
3. 「复制」：只在界面进程内取明文，复制后按 `ui.copyClearMs`（默认 10 秒）清空剪贴板。
4. 三列原值不写任何日志、不进 `logChange.payload`、不进错误信息、不通过 action 返回给 agent。
5. 数据页对三列固定输出 `••••••`，且**不提供显形开关**（数据页面向结构排查）。

## 4. Action 契约

命名沿用既有域前缀 `sites.*`（一期已用 `sites.list` / `siteNodes.*` / `siteTags.*`）。

| action | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `sites.accounts.list` | `siteId`（必填） | `{siteId, total, accounts:[{id, siteId, accountKey, account, hasPassword, phoneNumber, identityCard, remark, externals:[{id, siteId, siteName, accountKey}], createdAt, updatedAt}]}` | **列表不返回密码原文**，只给 `hasPassword`；`phoneNumber/identityCard` 原样返回（本机专用域，agent 读取属本机操作；文档需注明） |
| `sites.accounts.get` | `id` | `origin="ui"` 且保险箱解锁 → `{account:{...含明文}}`；否则 → `{masked:true, reason:"仅界面可查看"}` | **agent 永远拿不到明文**；schema 描述写明「敏感，仅界面可查看」 |
| `sites.accounts.create` | `siteId`, `accountKey`（必填）, `account?`, `password?`, `phoneNumber?`, `identityCard?`, `remark?`, `externalAccountIds?` | `{id}` | 校验 key 非空、同站点未删行唯一；`externalAccountIds` 里的每个 id 必须存在、属于 `bindable=1` 的**其他**站点、且 `account_key` 非空 |
| `sites.accounts.update` | `id` + 同上可选字段 | `{ok:true}` | 不允许改 `siteId`；`externalAccountIds` 给定时整体替换外联 |
| `sites.accounts.delete` | `id` | `{ok:true}` | 软删 + 双向清外联（同一事务） |
| `sites.accounts.link` | `nativeAccountId`, `externalAccountId` | `{ok:true}` | 幂等；自引用与同站引用报错 |
| `sites.accounts.unlink` | `nativeAccountId`, `externalAccountId` | `{ok:true}` | 软删该关系行 |
| `sites.accounts.cascade` | `excludeSiteId?` | `{groups:[{siteId, siteName, accounts:[{id, accountKey}]}]}` | 只含 `bindable=1` 且 `account_key != ''` 的账号 |
| `sites.vault.status` | — | `{enabled, unlocked, idleMinutes, remainingMs}` | 保险箱状态；不含任何密钥材料 |
| `sites.vault.setup` | `passphrase`（≥8 位，必填） | `{ok:true}` | 首次设置口令；已设置时拒绝并要求先 `rekey` |
| `sites.vault.unlock` | `passphrase` | `{ok:true}` / 口令错误报错 | 口令错误不泄露任何提示信息；连续失败 5 次后指数退避 |
| `sites.vault.lock` | — | `{ok:true}` | 清空内存密钥 |
| `sites.vault.rekey` | `oldPassphrase`, `newPassphrase` | `{ok:true}` | 解密全部敏感列 → 用新密钥重加密（单事务）；命令只认口令，不认密钥 |
| `sites.delete`（改造） | 现有参数 | 有账号时**报错**「该站点仍存在账号，请先删除其账号」 | 与 v2 一致 |
| `sites.update`（改造） | 现有参数 + `bindable` | `bindable` 由 1→0 且被外联引用时报错「该站点的账号正被外联账号引用，请先解除外联关系」 | 与 v2 一致 |
| `sites.create` / `sites.update` | 增加可选 `accountCount` 返回字段 | 列表行展示「账号 N」 | 可选，二期 UI 需要 |

约定：
- 所有返回遵循本仓口径：`renderText` 给人类可读摘要，`data` 给结构化对象。
- `capability.fields` 增加账号域字段的方向/枚举说明（`hasPassword` 是派生字段，不是存储列）。
- 敏感字段在 `actions.help` 里显式标注「敏感，仅本机，不回传云端」。

## 5. 业务规则

| # | 规则 | 触发点 |
| --- | --- | --- |
| 1 | `accountKey` 必填，长度 ≤ 60；同站点未删行内唯一（大小写敏感，trim 后比较） | create/update |
| 2 | `account/password/phoneNumber/identityCard/remark` 可为空，不做格式校验（与 v2 一致） | 同上 |
| 3 | 账号不能换站点 | update 忽略/拒绝 `siteId` |
| 4 | 删站：存在未删账号 → 拒绝并提示数量 | `sites.delete` |
| 5 | `bindable` 1→0：本站账号被任何外联引用 → 拒绝 | `sites.update` |
| 6 | 删账号：双向清外联 + 软删账号，同一事务 | `sites.accounts.delete` |
| 7 | 外联：`native != external`，两端必须属于**不同**站点，两端 `account_key` 非空，被引用站点 `bindable=1` | link/create/update |
| 8 | 外联重复 link 幂等；unlink 不存在的关系返回 `{ok:true}` | link/unlink |
| 9 | 账号列表按 `created_at` 升序（v2 口径） | list |
| 10 | 删除目录节点不影响账号（账号只挂站点） | siteNodes.delete（保持现状） |

## 6. UI 设计

### 6.1 记录页行操作

在「链接 / 目录 / 编辑 / 删除」之间插入「账号 N」按钮（`badge` 图标 + 数量），点击打开账号弹窗。
`N` 来自列表接口返回的 `accountCount`（需在 `sites.list` 的行数据里补）。

### 6.2 账号弹窗（`AccountModal`）

- 头部：`站点账号 · <站点名>` + 计数徽标 + 右侧「新增账号」按钮（v2 的只读弹窗只能删，这里补新增）。
- 列表：每条一张卡
  - 首字母头像 + `account_key`（粗体）+ 右侧「编辑 / 删除」
  - `account`（可复制）、`password`（掩码 + 显形 + 复制）、`phoneNumber` / `identityCard`（掩码 + 显形）、`remark`
  - 外联 chips：`<站点名> · <account_key>`，chip 上可解绑
- 空态：「该站点暂无账号」，提示可新增。
- 「账号仅保存在本机」用 `.wbs-mhint` 提示条常驻在弹窗顶部。

### 6.3 编辑卡（`AccountEdit`）

字段：`account_key`（必填）、`account`、`password`（`type=password` + 显形按钮）、`phoneNumber`（datalist 来自本站点历史值）、`identityCard`（同上）、`remark`（多行）、外联选择器（两段下拉：站点 → 账号，排除本站点与自身，按 id 去重）。

### 6.4 站点表单

站点新建/编辑弹窗内新增「账号」折叠区，可快速看到数量并跳转账号弹窗；不在站点表单里直接编辑账号，避免把敏感字段塞进通用保存流程。

| `form.maxAccounts` | int（1–50） | `20` | 单站点账号上限 |

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 明文密码被 agent 或日志带出 | `list` 不返回密码；`get` 的 schema 标注敏感；数据页掩码；不写日志 |
| 用户换机后账号丢失（决策 A 的代价） | UI 常驻「仅保存在本机」提示；备份含账号；后续 P4 加密同步 |
| 唯一索引与空 key 冲突 | 唯一性放应用层，DB 只建普通索引 |
| 删站守卫影响既有自动化（测试脚本里删站） | 守卫只在「存在未删账号」时触发，一期数据无账号，天然兼容 |
| 站点列表返回 `accountCount` 影响既有断言 | 新增字段，不改既有字段 |

## 12. 决策记录（已确认）

1. 同步策略：**B —— 写库前加密、同步密文**；密钥由「账号保险箱口令」经 scrypt 派生，不落库、不同步。
2. 账号弹窗允许**新增**（v2 只能看和删，新增在向导里）；本设计选择允许。
3. 明文可见范围：**仅界面进程**（`origin === "ui"` 且保险箱解锁）；agent 通过 action 永远只能拿到 `masked:true`。
