# 数据页设计（三个业务插件的「数据」视图）

> 状态：已实施（2026-11-08）。
> 关联：[03-UI设计](./03-UI设计.md)、[04-子插件体系](./04-子插件体系.md)、
> [05-本地存储设计](./05-本地存储设计.md)、[20-配置表与配置页设计](./20-配置表与配置页设计.md)。

## 0. 结论

给任务、标签、站点三个插件各加第四个视图「数据」，形态照搬数据库可视化工具：

- 左侧是**该插件自己负责的表**（不含平台表、不含其它插件的表）；
- 右侧是选中表的**分页表格**，展示真实列与真实行；
- 支持排序、关键字过滤、切换「包含已删除」「显示系统列」、切换每页条数；
- **只读**：不提供 INSERT/UPDATE/DELETE，不提供 SQL 控制台；
- 服务端只暴露两个 action：`dataTables`（表清单 + 列元信息 + 行数）与
  `dataQuery`（分页查询），表名/列名一律白名单校验，查询参数全部绑定。

### 0.1 当前表索引视图（2026-11-09）

任务、标签、站点、物品四个插件共用数据视图：左侧只列真实表，保留中文名、英文表名两行和次要行数；「行数据 / 表索引」仅在右侧顶部切换。

- 进入索引标签时通过本域 `dataTables({ stats: true })` 获取统计快照；左侧切表保持索引标签，只从快照选择当前表，不重复请求全部表。刷新重新获取快照。
- 表头显示当前表名、所属表总行数、列数与「共 N 个索引」。索引表一索引一行，列为索引名、有序列名（联合索引逗号分隔）、类型、来源、行数。
- 类型按 SQLite `origin=pk` 显示主键，否则按 `unique` 显示唯一或普通；`sqlite_autoindex_` 前缀显示自动来源，其余为显式创建。自动唯一索引仍是额外索引，不误判为主键。
- 只有主键（含复合主键）或没有索引时显示「该表除主键外没有额外索引」，不显示空表格；元数据缺失单独显示统计不可用。索引数采用 SQLite 返回的物理索引数量，不虚构 INTEGER PRIMARY KEY 的索引名。
- 每行「行数」沿用所属表 `stats.rows`（包含软删除行），说明文案与悬停提示明确这不是索引条目数；部分索引也不伪造独立行数。
- 长索引名、联合索引列允许换行，固定表格布局不被长内容撑破。保留切表清空旧行数据、退出标签忽略晚到响应和重复刷新只接受最新请求的保护。
- 专测：`node scripts/test-data-ui.mjs --source` 使用内存源码 bundle 覆盖四插件，无需修改生成物；常规构建后仍可运行原命令验证发布 bundle。

## 1. 背景与目标

### 1.1 问题

配置页解决了「行为偏好」，统计页解决了「汇总」，但排查问题、核对同步结果、
确认某条数据到底存成什么样时，仍然要开 sqlite CLI。业务用户没有这个能力，
agent 也不该为了看一行数据去写脚本。

### 1.2 目标

1. 在 UI 里看到每个插件负责的表的**原始数据**（列名、值、NULL、空串、软删标记）。
2. 千行级表也能流畅翻页；单页最多 200 行。
3. 行为可预期：默认隐藏系统列、默认过滤软删、默认按创建时间倒序。
4. 与统计/配置页同一套视觉语言，只使用 `--dsw-alias-*` 与 `--wb-*` token。
5. 为后续「导出 CSV」「行详情」留出扩展位，但本期不实现。

### 1.3 非目标

- 不做写操作（编辑单元格、删除行）；写入口仍然走各自业务页与 action。
- 不做任意 SQL；不接受调用方传入的 `WHERE` 片段。
- 不做跨插件 JOIN；标签关联表在标签模块里看，任务侧只看 `task*`。
- 不做实时订阅；切换表、翻页、点刷新时拉取，`tasks-changed` 等事件不自动重查
  （避免用户正在看的数据被刷新打断，只在表头显示「刷新」按钮）。
- 不展示 `meta`（配置键值，内部实现）与 `sync_*` 平台表。

## 2. 表归属

每个插件只暴露自己 `ensureSchema` 里建的表：

| 插件 | 表 | 中文名 | 行数级 |
| --- | --- | --- | --- |
| tasks | `task` | 任务 | 千 |
| tasks | `task_node` | 任务单元 | 百 |
| tags | `tag` | 标签 | 百 |
| tags | `tag_mapping` | 标签关联 | 千 |
| sites | `site` | 站点 | 百 |
| sites | `site_node` | 站点目录 | 百 |
| sites | `site_node_mapping` | 站点目录关联 | 千 |

说明：

- `sites` 的 `DomainDef.tables` 里还声明了 `tag_mapping`，那是为了备份/同步能覆盖
  共享表；这张表由标签域创建，**不在站点数据页展示**，避免两个页面看到同一份数据
  却归属不同。
- `meta` 是配置存储（[20](./20-配置表与配置页设计.md)），属于实现细节，不展示。
- 表清单写死在各自 `lib/data.js` 的 `TABLES` 常量里，不从 `sqlite_master` 动态枚举：
  避免把用户自建表、临时表、未来新增的内部表无意暴露出去。

## 3. 列元信息

服务端用 `PRAGMA table_info(<表>)` 读真实列，再补两层展示信息：

### 3.1 类型归一

SQLite 的声明类型只有 `TEXT/INTEGER/REAL` 三种，前端需要更细的语义：

| 判定 | 规则 | 展示 |
| --- | --- | --- |
| `id` | 列名以 `_id` 结尾或等于 `id`、`parent_id` | 等宽、完整显示，过长截断 |
| 时间戳 | 列名以 `_at` 结尾且类型为 INTEGER | 毫秒 → 本地 `YYYY-MM-DD HH:mm:ss`，悬停看原值 |
| 日期 | 列名以 `_date` 结尾且类型为 TEXT | 直接显示 `YYYY-MM-DD` |
| 路径 | 列名 `path` | 等宽，`/` 分段可折行 |
| 布尔 | 列名 `bindable`、`deleted` | `1/0` → `是/否`，悬停看原值 |
| 数字 | 类型 INTEGER/REAL | 右对齐 |
| 文本 | 其余 TEXT | 左对齐，单行截断 320px |
| JSON | `parseJsonLike()` 成功且是对象/数组 | 显示压缩 JSON，点击抽屉看格式化 |

### 3.2 系统列

`rev`、`created_at`、`updated_at`、`deleted_at` 归为系统列，默认隐藏；
表头右侧的「显示系统列」开关打开后参与查询与渲染。`id` **不算**系统列，始终显示。

### 3.3 列标签

已知列给中英文名（`COLUMN_LABELS`），未知列回退列名本身：

```js
const COLUMN_LABELS = {
  id: { zh: "ID", en: "ID" },
  title: { zh: "标题", en: "Title" },
  site_name: { zh: "站点名", en: "Name" },
  parent_id: { zh: "父 ID", en: "Parent" },
  deleted_at: { zh: "删除时间", en: "Deleted at" },
  // ...
};
```

## 4. action 契约

两个 action 都由各插件 `lib/data.js` 注册，命名 `<domain>.dataTables` /
`<domain>.dataQuery`（`tasks.dataTables`、`tags.dataQuery`…）。

### 4.1 `dataTables`

请求：无参数（`{}`）。

响应：

```json
{
  "domain": "tasks",
  "tables": [
    {
      "name": "task",
      "label": { "zh": "任务", "en": "Tasks" },
      "count": 40,
      "deletedCount": 2,
      "columns": [
        { "name": "id", "type": "TEXT", "kind": "id", "label": { "zh": "ID", "en": "ID" }, "system": false },
        { "name": "status", "type": "TEXT", "kind": "text", "label": { "zh": "状态", "en": "Status" }, "system": false },
        { "name": "deleted_at", "type": "INTEGER", "kind": "timestamp", "label": { "zh": "删除时间", "en": "Deleted at" }, "system": true }
      ]
    }
  ]
}
```

- `count` = `deleted_at IS NULL` 的行数；`deletedCount` = 全部行数 − count。
- 列顺序按 `PRAGMA table_info` 的 `cid`。
- 表或列在库里不存在（例如旧版本未迁移）：该表 `columns: []`、`count: 0`，
  `warnings` 里给一条说明，不让整页失败。

### 4.2 `dataQuery`

请求：

```json
{
  "table": "task",
  "page": 1,
  "pageSize": 50,
  "sort": "created_at",
  "order": "desc",
  "search": "发布",
  "includeDeleted": false
}
```

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `table` | string enum | 必填 | 必须是本插件 `TABLES` 之一 |
| `page` | number | 1 | 夹到 `[1, 总页数]` |
| `pageSize` | number | 50 | 夹到 `{10,25,50,100,200}`，就近取档 |
| `sort` | string | `created_at`（无则 `rowid`） | 必须是该表真实列 |
| `order` | string | `desc` | `asc` / `desc` |
| `search` | string | 空 | 对全部 TEXT 列做 `LIKE %kw%`，最长 100 字 |
| `includeDeleted` | bool | false | 为 false 时加 `deleted_at IS NULL` |

响应：

```json
{
  "domain": "tasks",
  "table": "task",
  "columns": [{ "name": "id", "kind": "id", "system": false }],
  "rows": [{ "id": "01a1…", "title": "发布 v2.8.0", "created_at": 1762600000000 }],
  "page": 1,
  "pageSize": 50,
  "pages": 1,
  "total": 40,
  "sort": "created_at",
  "order": "desc",
  "includeDeleted": false,
  "search": "发布",
  "queryMs": 3
}
```

- `rows` 里的键按 `columns` 顺序；值保持数据库原值（时间戳是毫秒数字，NULL 是 `null`）。
- `total` 是过滤后的总数；`pages = max(1, ceil(total / pageSize))`。
- `queryMs` 用 `performance.now()` 量，前端显示在右下角，便于发现慢查询。

### 4.3 校验与错误

| 情况 | 行为 |
| --- | --- |
| `table` 不在白名单 | 抛 `未知数据表：xxx`（HTTP 500） |
| `sort` 不是该表列 | 抛 `未知排序列：xxx` |
| `pageSize` 超范围 | 就近夹取，不报错 |
| `page` 超出总页数 | 夹到最后一页；`total=0` 时 `page=1` |
| `search` 超长 | 截断到 100 字 |
| 表在库里不存在 | 返回空集 + `warnings`，不抛错 |

关键实现约束：

- 表名与列名拼进 SQL 前必须先过白名单（不能只靠参数绑定，标识符不能绑定）；
- `search` 用 `?` 绑定，并 `ESCAPE '\'` 转义 `%` `_` `\`；
- 不加 `ORDER BY` 之外的任何用户输入拼接；
- 只读：SQL 只允许 `SELECT`，`db.prepare` 后不做写入。

### 4.4 为什么不做 `dataSql`

用户能想到的下一步一定是「直接跑 SQL」。本期拒绝：

- agent 与 UI 共享 action 通道，开放 SQL 等于把整库（含 `meta`、同步游标、
  其它插件的表）交给任意调用方；
- 只读也难以保证——SQLite 的 `PRAGMA`、`ATTACH`、`load_extension` 都是攻击面；
- 真需要时走 `sqlite3` CLI 或宿主的数据库工具，不在插件 UI 里做。

## 5. 客户端页面

新增 `packages/addons/<name>/client/data.cjs`，导出 `{ DataView, DOMAIN }`，
在 `client.src.cjs` 注册第四个视图：

```js
{ id: "data", title: { zh: "数据", en: "Data" }, component: dataView.DataView }
```

### 5.1 布局

```
┌ 数据 ────────────────────────────────────────────────────────────┐
│ ┌ 表 ─────────┐ ┌ task  任务  40 行 · 2 行已删除   [刷新] ───────┐ │
│ │ 任务     40  │ │ [搜索标题/内容…]  [每页 50 ▾] [含已删除] [系统列] │ │
│ │ 任务依赖  0  │ ├──────────────────────────────────────────────┤ │
│ │ 任务单元 11  │ │ # │ id        │ 标题      │ 状态 │ 创建时间      │ │
│ │              │ │ 1 │ 01a1…c9   │ 发布…     │ 进行中│ 11-08 19:02  │ │
│ │              │ │ 2 │ 01a1…d1   │ 整理…     │ 已完成│ 11-08 18:40  │ │
│ │              │ ├──────────────────────────────────────────────┤ │
│ │              │ │ ‹ 上一页   第 1 / 1 页   下一页 ›   共 40 行 · 3ms│ │
│ └──────────────┘ └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

- 外层 `.X-data` 用 `display:grid; grid-template-columns: 216px minmax(0,1fr)`，
  gap 16，铺满内容区（不设 max-width，和 03 的全宽约定一致）。
- 侧栏是 `.X-data-side`，粘性定位（`position:sticky; top:12px`），表项两行：
  中文名 + 行数；选中项左侧 2px brand 竖条 + 淡背景。
- 主区 `.X-data-main` 是卡片：表头区 + 工具条 + 表格滚动区 + 分页条。
- 表格滚动区 `max-height: calc(100vh - 260px)`，横向 `overflow:auto`，
  表头 `position:sticky; top:0`，行号列也 `sticky; left:0`。

### 5.2 工具条

| 控件 | 行为 |
| --- | --- |
| 搜索框 | 输入 300ms 防抖后从第 1 页重查；placeholder 说明「匹配所有文本列」 |
| 每页条数 | `select`：10 / 25 / 50 / 100 / 200，改动即重查并回第 1 页 |
| 含已删除 | 开关，切换后重查；开启时行尾出现「已删除」徽标 |
| 显示系统列 | 开关，纯前端过滤列，不重查 |
| 刷新 | 保留当前页码、排序、过滤重查；按钮上有 loading 态 |
| 行数摘要 | `共 N 行 · 其中 M 行已删除`，数据来自 `dataTables` 的 count |

### 5.3 表格

- 列头：列名 + 类型小字（`TEXT` / `INT` / `REAL`），可点击排序，
  三态循环 `desc → asc → 默认`；`aria-sort` 同步。
- 单元格：
  - `null` → 斜体灰 `NULL`；
  - 空串 → 灰 `""`；
  - 时间戳 → 本地时间，`title` 里放原始毫秒；
  - 布尔 → `是/否`，`title` 放 `1/0`；
  - 长文本 → 320px 截断 + 省略号，`title` 放全文；点击打开右侧抽屉；
  - JSON → 压缩成一行，点击抽屉里 `JSON.stringify(value, null, 2)`。
- 行号列：显示 `(page-1)*pageSize + i + 1`，方便对照分页。
- 已删除行：整行 60% 透明 + 「已删除」徽标。
- 斑马纹与 hover 用 `color-mix(in srgb, currentColor 3%, transparent)`，不写死颜色。
- 单元格点击复制：点击时把原值写入剪贴板，右下角出现 1.2s 的「已复制」提示
  （长按/点击文本不再是唯一入口，避免与抽屉冲突：单击复制，双击开抽屉）。

### 5.4 抽屉

- `.X-data-drawer` 从右侧滑入，宽 `min(520px, 92vw)`；
- 标题 = 列名 + 行号；正文 = 格式化后的值（JSON 用 `<pre>`，文本保留换行）；
- 底部「复制」按钮 + 「关闭」；
- `Esc` 关闭，打开时焦点进入抽屉，关闭后焦点回到触发单元格。

### 5.5 状态

- 首次加载：侧栏骨架 + 表格 8 行骨架；
- 切换表：保留侧栏，主区骨架；
- 空表：表格区域居中「这张表还没有数据」+ 表名；
- 错误：主区错误条 + 「重试」；侧栏仍可用；
- 请求竞态：自增 `reqId`，只应用最后一次响应；
- 语言：`props.lang` 决定 `zh/en`，所有文案走 `COPY`。

### 5.6 主题与响应式

- 只用 `--dsw-alias-*`（文本、边框、背景）与宿主 `--wb-line` / `--wb-surface`；
- 宽度 < 900px 时侧栏改为顶部横向 chips，表格占满；
- `prefers-reduced-motion` 时关闭抽屉动画。

## 7. 性能

- 每次查询两条 SQL：`COUNT(*)` + `SELECT … LIMIT ? OFFSET ?`；表都在千行级，
  单页 200 行、20 列以内的响应 < 10ms（`queryMs` 可在页面右下角核对）。
- 不加索引：数据页是诊断工具，不参与主流程；已有 `task` 的
  `idx_task_open(status,target_date)` 等索引在排序 `created_at` 时用不上，
  但千行级全表扫可接受。行数上到十万级再考虑 `deleted_at` 部分索引。
- 侧栏行数只在进入页面和点刷新时算；翻页不重算 `dataTables`。

## 8. 安全

- 只读，无写路径；
- 表名/列名白名单；`search` 绑定参数并转义通配符；
- 不返回 `meta`，避免配置值里的潜在敏感内容（例如未来可能存 token）被展示；
- 不提供导出/下载，避免把整库一次性带走（需要时另做「导出当前页 CSV」并单独评审）；
- 数据本身是用户自己的本地库，不做额外脱敏；若未来引入多用户，需在宿主层加权限。

## 9. 测试计划

新增 `scripts/test-data.mjs`（临时 sqlite，依次加载 tags → tasks → sites）：

1. `dataTables` 返回的表集合与顺序符合 `TABLES`，不含 `meta`；
2. 列名与 `PRAGMA table_info` 完全一致，`system` 标记覆盖 `rev/created_at/updated_at/deleted_at`；
3. 造 3 条任务、软删 1 条：`count` 与 `deletedCount` 正确；
4. `dataQuery` 默认过滤软删；`includeDeleted:true` 时包含；
5. 分页：`pageSize=10` 时 `pages/total` 正确，`page` 超界夹到最后一页；
6. 排序：`sort=title&order=asc` 与手工查询结果一致；`sort=created_at&order=desc` 首行是最新；
7. 搜索：命中 `title`/`description` 中的关键字；`%` 被当字面量（转义生效）；
8. 非法输入：未知表、未知排序列抛错；`pageSize=999` 夹到 200；
9. 只读：查询前后 `task` 行数与 `sync_change_log` 不变。

CI 顺序：`pnpm build:clients` → `audit-actions` → `test:native` / `test:tags` /

## 11. 风险与后续

| 风险 | 处理 |
| --- | --- |
| 大文本列撑爆响应 | 单页 200 行上限；后续可加「列裁剪」或服务端截断 |
| `LIKE` 对中文大小写不敏感无影响，但对 `%`/`_` 误匹配 | 已转义；文档注明搜索是「包含」而非全文 |
| 用户把数据页当编辑器 | 单元格无编辑态；只读文案在表头副标题里说明 |
| 表格横向过宽 | 列宽按内容自适应 + 横向滚动；行号列与表头固定 |
| 未来新增内部表 | 显式 `TABLES` 白名单，不自动枚举 |

后续可做（不在本期）：

1. 当前页导出 CSV；
2. 行详情抽屉（同表关联行的快捷跳转）；
3. 列显示/隐藏自定义；
4. 键盘导航（↑↓ 选行、Enter 开抽屉）。
