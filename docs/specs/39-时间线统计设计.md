# 时间线统计设计（首期：三个必需指标 + 排行与分布）

关联任务：01a1c105-d888-7617-9662-c9246c11027e。日期：2026-11-10。状态：设计已随实现提交（tasks 3.4.4 起 `tasks.timelineStats` 只读 action；页面区块按本文档第 7 节接入）。

## 1. 目标与边界

任务统计页此前只有任务、标签、任务表维度，缺时间线维度，无法回答「哪条线任务最多」「多少任务没有时间线」「多少线是空的」。首期给出三项必需指标（Top100、无归属任务数、空线数）与配套分布、逾期、趋势，全部由服务端一次聚合返回，页面不逐条请求明细。

时间线是**可选归属**：普通任务可以没有时间线，这不是错误数据；「没有时间线」与「没有任务表归属」是两种不同情况，统计文案必须区分。

## 2. 口径（与 `tasks.timelines` 列表一致）

- 有效任务：`task.deleted_at IS NULL AND task.status != '3'`。已重启任务（status=3）是历史载体，不计入有效成员；因此本统计的有效任务数可能小于任务总览（含已重启）的数量，页面必须提示差异。
- 有效时间线：`task_timeline.deleted_at IS NULL`。
- 有效归属：`task_timeline_link.deleted_at IS NULL`，且任务与时间线均有效。以真实成员关系判定，**不看 `task.timeline_key` 等兼容列**：未关联的普通任务即使兼容列有值也不算已归属。
- 状态构成：进行中 `status='0'`、已完成 `status='2'`、已关闭 `status='1'`。已重启 `3` 不出现。
- 活动日 `lastActivityDate`：该线有效成员的发布日、完成日、关闭日与创建/修改本地日的最大值；计划目标日 `targetDate` 不算活动（与时间线列表同定义）。
- 逾期：`status='0'` 且 `targetDate` 早于今天（本地日期，按前 10 位比较）。
- 空线：存活且有效任务数为 0，包含「尚未添加任务」「成员被移出」「成员被删除」「成员被重启」四种成因。
- 范围：`from`/`to` 只影响趋势（范围内事件），不影响存量指标；「范围内没有任务」不等于空线。

## 3. 指标与公式

存量（不随日期范围变化）：

| 指标 | 定义 |
| --- | --- |
| `timelines` | 有效时间线总数 |
| `timelinesWithTasks` | 至少 1 个有效任务的时间线数 |
| `emptyTimelines` | `timelines - timelinesWithTasks` |
| `emptyRatio` | 空线 / 时间线总数，百分数一位小数；总数为 0 时为 null |
| `tasks` | 有效任务总数（排除已重启） |
| `assignedTasks` | 有有效归属的有效任务数 |
| `unassignedTasks` | `tasks - assignedTasks` |
| `coverage` | 已归属 / 有效任务，百分数一位小数；有效任务为 0 时为 null |

不变式（回执 `invariants` 自检并返回）：`assignedTasks + unassignedTasks = tasks`；`timelinesWithTasks + emptyTimelines = timelines`。

排行 `top`：对全部有效时间线聚合后按 `taskCount` 降序、`id` 升序取前 `topLimit`（默认 100，限 1..100），不受列表分页影响；`truncated` 表示还有未返回的线。每条含标题、任务总数、进行中/已完成/已关闭、完成率（空线为 null）、逾期数与活动日。

规模分布 `distribution`：按任务数分 `0`、`1`、`2–5`、`6–10`、`11–50`、`51+` 六档，覆盖全部有效时间线，合计等于 `timelines`。

逾期 `overdue`：有逾期任务的时间线（按逾期数降序、id 升序，最多 `topLimit` 条），另给 `lineCount` 与逾期任务合计 `taskCount`。

趋势 `trend`（仅传日期范围时）：范围内新增时间线（创建本地日）、新增任务（发布日）、完成任务（当前已完成且完成日落在范围内）。只描述范围内事件，不宣称还原历史时点归属。

## 4. 排序与稳定性

- 排行：`taskCount DESC, id ASC`；同数量按 id 稳定排序，测试用并列样本断言顺序。
- 逾期榜：`overdueCount DESC, id ASC`。
- 分布：固定档位顺序，不按数量重排。

## 5. 删除、重启与移出

- 时间线软删除：不计入 `timelines`，其成员任务回到「未归属」（若没有其他有效关联），因此 `unassignedTasks` 会上升。
- 任务软删除：不计入有效任务，也不再计入其线；线可能因此变为空线。
- 任务重启（status 3）：原任务退出有效成员，重启后的新任务仅在显式关联后计入；原任务所在线若因此失去全部成员则计入空线。
- 成员移出：关联软删除；任务回到未归属，线可变为空线。
- 任务表归属与本统计无关：任务可以没有任务表（理论上不写入成功），统计只回答时间线维度。

## 6. 接口契约（`tasks.timelineStats`，只读）

输入：`topLimit?`（1..100，默认 100）、`from?`/`to?`（YYYY-MM-DD，必须同时提供；反序自动交换并在 `trend.swapped` 标记）。

输出：`generatedAt`、`scope`（口径说明字符串）、`totals`、`invariants`、`top{limit,returned,truncated,records[]}`、`distribution[]`、`overdue{lines[],lineCount,taskCount}`、可选 `trend{from,to,swapped,newTimelines,newTasks,doneTasks}`。

实现：[timeline-stats.js](../../packages/addons/tasks/lib/stats/timeline-stats.js)。空库返回全 0 与 null 比率，不报错，不隐式建线。

## 7. 页面布局（首期）

统计页在「时间线」区块内自上而下：

1. 四张 KPI：时间线总数（含空线占比）、有效任务数（含覆盖率）、空线数、Top1 任务数；附一行口径说明「已重启不计入；无时间线不是错误」。
2. 排行：Top100 单行列表（标题 + 总数 + 状态构成徽标），可展开成员明细（复用 `tasks.timelines` 成员列表，不再另取全量排行）。
3. 分布：六档横向条形（复用现有 charts 画布）。
4. 逾期：有逾期任务的时间线 Top 若干，点击跳转记录列表（逾期筛选）。
5. 趋势（可选）：传页面时间范围时画新增时间线/新增任务/完成三组数字。

刷新：时间线创建、改名、删除，成员加入/移出/换线，任务创建、状态变化、重启与删除后重新拉取（订阅 `task-timelines-changed`，并复用现有 `tasks-changed`）。

## 9. 验收

- 空库：全部 0，比率为 null，排行空。
- 空线、单成员、并列数量、成员移出/删除/重启后空线计数正确。
- 超过 100 条时间线：`top.returned=100`、`truncated=true`，`totals` 与 `distribution` 不受截断影响。
- 已归属 + 未归属 = 有效任务；有任务线 + 空线 = 时间线总数（回执自检为 true，测试独立断言）。
- 明细数量与统计一致（同一口径 SQL）；任务统计页原有 KPI 不回归。
- 测试：`node scripts/test-timeline-stats.mjs`（`pnpm test:timeline`）。
