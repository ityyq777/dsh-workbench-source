# 25 · 标签域解耦：审计与改造方案

> 状态：设计（审计已完成，改造按第四节执行）。
> 起因：任务「标签子插件解耦：审计 tasks / sites 对标签的强耦合（未安装时不得报错或误报能力）」。
> 结论先行：**所有权本来就是清楚的（`tag` / `tag_mapping` 只由标签插件建表），
> 真正的问题是「没有安装标签插件时，标签相关参数的行为不统一」——有的抛底层 SQL 错误、
> 有的静默丢弃、有的把空列表当成「没有数据」，而能力清单还在宣称支持标签。**

## 1. 现状：所有权是清楚的

| 表 | 建表方 | 证据 |
| --- | --- | --- |
| `tag`、`tag_mapping` | 标签插件 | `packages/addons/tags/lib/db.js:16,24` |
| `task`、`task_dep`、`task_node` | 任务插件 | `packages/addons/tasks/lib/db.js:11,46,61` |
| `site`、`site_node`、`site_node_mapping`、两张账号表 | 站点插件 | `packages/addons/sites/lib/db.js:16,33,51` |

任务与站点都不建标签表，只读写 `tag_mapping` 里 `item_type='task'` / `'site'` 的行，
这是设计时就约定好的（`packages/addons/tasks/lib/tagging.js:1-10`、`packages/addons/sites/lib/db.js:6`）。
所以这次不是「拆表」，而是把**降级语义**和**能力声明**补严。

## 2. 审计发现（按严重度）

实测方式：用只加载宿主 + 单个业务插件的探针（`WB_HOME` 指向临时目录）调用 action，
复现「未安装标签插件」的场景。

### P0 · 直接报错或静默骗人

1. **`tasks.list` 传 `tagIds` 时没有守卫，抛的是底层 SQL 错误。**
   `packages/addons/tasks/lib/tasks.js:911-915` 直接拼
   `EXISTS (SELECT 1 FROM tag_mapping …)`；标签表不存在时 SQLite 抛
   `ERR_SQLITE_ERROR / SQL logic error`，agent 完全无法判断是「参数不对」还是「插件没装」。
   对照：同一个函数里按**标签名**过滤的分支是有守卫的（`tasks.js:872-884`，
   抛「标签域未安装，无法按标签过滤」）。
2. **`sites.list` 传 `tagIds` 时静默返回空列表。**
   `packages/addons/sites/lib/sites.js:190-194`：标签域缺失就直接返回空页，
   用户看到的是「没有站点」，而站点其实都在——这比报错更糟。
3. **`sites.create` / `sites.update` 传 `tagIds` 时静默丢弃。**
   `packages/addons/sites/lib/sites.js:248-249` 的 `validateTagIds` 在标签域缺失时
   `return []`，写入「成功」但标签没了；任务侧对同样情况是抛错的
   （`tasks.js:568`、`tasks.js:672`：`标签域未安装，无法写标签`）。两侧语义相反。

### P1 · 能力误报

4. **能力清单静态宣称标签能力。** 任务域的描述里写着「可按标签筛选」，
   站点域的能力说明同样提到标签；标签插件没装时这就是误报，
   agent 会照描述传 `tagIds`，然后撞上第 1~3 条。

### P2 · 归属重叠（不致命，但要收敛）

5. **`tag_mapping` 被两个域同时声明为同步表**：`packages/addons/tags/lib/sync.js:3-12`
   与 `packages/addons/sites/lib/sync.js:119-124`。两域各自 push/pull 同一张表，
   唯一键与墓碑策略靠两处手写保持一致，属于隐性重复。
6. **`tag_mapping` 被站点域的备份重复导出**：`packages/addons/sites/lib/backup.js:111,155,170`
   （有 `hasTagMapping` 守卫，不会报错，但会与标签域的备份重叠）。
7. `tasks.syncChanges` 的默认表清单含 `tag_mapping`（`tasks.js:1256`，描述见 `tasks.js:1630`）。
   这一处只是读 `change_log` 的文本表名，不会碰标签表，属于「名字暗示所有权」，不修改。

### P3 · 有意保留的越权

8. 任务侧的旧类型迁移会**代写 `tag` 行**（`tagging.js` 的 `tags_from_types_v1`），
   否则老任务会集体变成未打标签。它已经由 `tagsAvailable()` 守卫，
   本方案明确保留，并在注释里写清「唯一允许的跨域写入，且只在迁移期跑一次」。

## 3. 目标语义（改造后的契约）

| 场景 | 现状 | 改造后 |
| --- | --- | --- |
| 标签域已安装 | 正常 | 不变 |
| 未安装 + 不传标签参数 | 正常 | 正常（任务/站点照常读写） |
| 未安装 + 传 `tagIds` / `tags` / `addTags` 等 | 报 SQL 错 / 静默丢 / 返回空 | **站点**：抛可读错误「标签域未安装…」；**任务**：跳过标签、正文照常落库，回执带 `notices: [{code:"tag_domain_missing"}]`（2026-11-09 修订） |
| 未安装 + 读能力清单 | 宣称支持标签 | **站点**：能力带 `requires` 并渲染「依赖未安装」；**任务**：不声明 requires（标签是可选能力），描述里注明降级行为 |

> **2026-11-09 修订**：任务侧从「缺标签就报错」改为「可选能力降级」——写入忽略标签参数并回执
> `notices`，读侧省略 `tags` 字段、按标签筛选返回空结果、`groupBy=tag` 返回空分组。
> 理由：标签是任务的附加归类，缺插件不该让「记一条任务」整条失败；站点不同，标签是站点
> 记录的一等字段，缺域时静默丢标签比报错更糟。实现见 `packages/addons/tasks/lib/tasks.js`
> 的 `tagMissingNotices` / `TAG_DOMAIN_NOTICE`，客户端用 `hostHasAddon("wb-addon-tags")` 隐藏标签控件。

## 4. 改造方案

### 4.1 一期：语义统一 + 能力自描述（本次执行）

1. 新增能力依赖声明：`capability.requires: string[]`（域 id）。
   宿主 `packages/shell/src/index.ts` 的 `capabilityOf` 归一化该字段，
   计算 `missingRequires`，并在 `warnings` 追加
   「依赖未安装：wb-addon-tags；相关参数（tagIds/tags）会报错，其余功能正常」；
   `capabilities.get` 与 `capabilities.list` 的渲染都带上依赖行。
2. 任务域：`tasks.list` 的 `tagIds` 分支补守卫——2026-11-09 起改为降级为空结果 + notice（不再抛错）。
3. 站点域：`sites.list` 的 `tagIds` 分支从「静默返回空」改为抛错；
   `validateTagIds` 在标签域缺失且确实传了 `tagIds` 时抛错，不再静默丢弃。
4. 站点域的 `capability` 增加 `requires: ["wb-addon-tags"]`，描述里的「可按标签筛选」补上
   「（需安装标签插件）」；任务域不声明 requires（可选能力，见 2026-11-09 修订）。

### 4.2 二期：归属收敛（本次执行，改动小）

5. `tag_mapping` 的同步声明只保留在标签域：从 `packages/addons/sites/lib/sync.js` 移除。
   标签域的声明是整表行级同步（不区分 `item_type`），站点的映射行照样同步。
6. 站点域备份**保留**导出 `item_type='site'` 的 `tag_mapping` 行（那是站点自己的数据，格式已有文档约定，改动会破坏老备份的校验）；只收敛同步声明，避免两处维护同一套唯一键策略。

### 4.3 三期：契约测试（本次执行）

7. 新增 `scripts/test-nodeps.mjs`：分别以「仅任务域」「仅站点域」装载宿主与插件，
   断言上表每一行语义：无标签参数时 CRUD 正常、传标签参数时报可读错误、
   能力清单带「依赖未安装」、数据页与统计不受影响。

### 4.4 不做的事

- 不把 `tag` / `tag_mapping` 挪到宿主（会破坏现有备份与同步契约）。
- 不给任务/站点复制一份标签表（真正的双写地狱）。
- 不删除旧的 `tasks.syncChanges` 默认表名（兼容期内无收益）。

## 5. 验收标准

- 只装任务插件：`tasks.create` / `tasks.list` / `tasks.stats`（不含标签参数）全部正常；
  带 `tags` / `tagIds` 时写入照常、回执带 `tag_domain_missing`；`tasks.list({ tagIds })`
  返回空结果 + notice（不抛 SQL 错误，也不静默返回空而无提示）。
- 只装站点插件：`sites.create`（不传标签）正常；传 `tagIds` 报同样可读错误；
  `sites.list({ tagIds })` 报错而不是返回空。
- 三个插件都装：现有测试（test-native / test-tags / test-sites / test-data）保持全绿。
- `capabilities.list` 在标签域缺失时对站点域给出「依赖未安装」提示；任务域不告警（可选能力）。
- `scripts/test-nodeps.mjs` 覆盖上述两条语义（任务降级 / 站点报错）。
