# 53 工资记录插件设计（salary 0.1.0）

> 状态：设计稿（已按「日期维度、支持日结/月结」修订），确认后开发。
> 目标包：`dsh-workbench-salary`，域 `wb-addon-salary`，前端前缀 `wbsal`。

## 1. 背景与目标

用户提供 4 张工资条截图（实发 7878.77 / 8111.56 / 8189.17 / 10672.36，最后一张标注
「2026年10月工资条」）。工资条除姓名外共有 18 个金额维度：7 个收入项、3 个税前扣款项、
6 个社保与个税项、2 个汇总项。

工资可能是**日结**也可能是**月结**，所以记录的时间维度用**发薪日期 `payDate`
（YYYY-MM-DD）**，不是「月份」；`cycle`（`daily` 日结 / `monthly` 月结）只作标注与筛选，
不改变金额口径。统计时把日期归入所属自然月做趋势，按年做汇总。

本插件解决三件事：

1. 按日期录入/修改/删除一笔工资，金额逐项留档，不依赖截图；
2. 按月/按年查看实发趋势、年度汇总、社保公积金与个税累计；
3. agent 可通过 `salary.*` action 查询某段时间/某年工资，或在用户口述后直接录入。

**非目标**：不做 OCR/自动抓工资条、不多公司并行核算、不做报销与支出流水（用 storage）、
不做加密与云同步（沿用宿主备份与登录同步边界）。

## 2. 数据模型

### 2.1 表 `salary_record`

| 列 | 类型 | 含义 | 截图字段 |
| --- | --- | --- | --- |
| `id` | TEXT PK | `sal_` + 时间戳 + 随机 | — |
| `pay_date` | TEXT NOT NULL | 发薪/结算日期 `YYYY-MM-DD` | 2026年10月（工资条月份） |
| `cycle` | TEXT NOT NULL DEFAULT `'monthly'` | `monthly` 月结 / `daily` 日结 | — |
| `base_pay` | REAL | 基本工资 | 基本工资 |
| `performance_pay` | REAL | 绩效工资 | 绩效工资 |
| `position_pay` | REAL | 岗位工资 | 岗位工资 |
| `allowance` | REAL | 补贴 | 补贴 |
| `performance_bonus` | REAL | 绩效奖惩（允许负数） | 绩效奖惩 |
| `other_pay` | REAL | 其他收入 | 其他 |
| `holiday_overtime` | REAL | 法定假期加班工资 | 法定假期加班工资 |
| `sick_deduction` | REAL | 病假扣款 | 病假扣款 |
| `personal_deduction` | REAL | 事假扣款 | 事假扣款 |
| `other_deduction` | REAL | 其他扣款（入职/离职/转正/产假） | 其他扣款 |
| `gross_pay` | REAL | 应发税前工资 | 应发税前工资 |
| `pension` | REAL | 养老 | 养老 |
| `medical` | REAL | 医疗 | 医疗 |
| `unemployment` | REAL | 失业 | 失业 |
| `housing_fund` | REAL | 公积金 | 公积金 |
| `income_tax` | REAL | 个税 | 个税 |
| `post_tax_deduction` | REAL | 税后扣除 | 税后扣除 |
| `net_pay` | REAL | 实发工资 | 顶部大数字 |
| `note` | TEXT NOT NULL DEFAULT '' | 备注（可选） | — |
| `created_at` / `updated_at` | INTEGER | UTC 毫秒 | — |
| `deleted_at` | INTEGER NULL | 软删除时间 | — |
| `rev` | INTEGER | 版本号，更新 +1 | — |

索引：

```sql
CREATE INDEX IF NOT EXISTS idx_salary_pay_date ON salary_record(pay_date);
CREATE INDEX IF NOT EXISTS idx_salary_deleted  ON salary_record(deleted_at);
```

**同一日期允许有多条记录**：日结可能一天多笔（多班次/补发），不做唯一约束；UI 在选中
已有日期时提示「该日已有 n 笔，保存将新增一条」，由用户决定新增还是编辑已有记录。

### 2.2 派生口径（写入时计算并落库）

```text
收入合计   = base_pay + performance_pay + position_pay + allowance
           + performance_bonus + other_pay + holiday_overtime
税前扣款   = sick_deduction + personal_deduction + other_deduction
应发       = max(收入合计 - 税前扣款, 0)
社保公积金 = pension + medical + unemployment + housing_fund
税后扣款   = pension + medical + unemployment + housing_fund + income_tax + post_tax_deduction
实发       = max(应发 - 税后扣款, 0)
```

用截图反证：

- 2026-10：收入 8800+2200+800+480=12280；扣款 739.2+184.8+46.2+462+175.44=1607.64；
  实发 12280-1607.64=10672.36 ✓
- 第二张：应发 9640；扣款 739.2+184.8+46.2+462+96.24=1528.44；实发 8111.56 ✓
- 第三张：应发 9720；扣款 1530.83；实发 8189.17 ✓
- 第一张：基本 7040+绩效 2200+补贴 160=9400；扣款 1521.23；实发 7878.77 ✓

写入规则：

1. 所有金额按 `round2`（`Math.round(n*100)/100`）存储，非法数字抛错；
2. 收入与扣款项缺省 0，允许为 0，不允许负收入/负扣款（`performance_bonus` 是奖惩净额，
   允许负数表示扣罚，单独放行）；
3. `gross_pay` / `net_pay` 默认由公式推导；调用方同时传了这两个汇总值时以传入值为准
   （用于「只记得实发」或截图缺字段的补录，不参与其他字段计算）；
4. `payDate` 必须是合法 `YYYY-MM-DD`（年份 2000–2100，日期用 UTC 解析回读校验）；
5. `cycle` 只接受 `monthly` / `daily`，缺省 `monthly`；
6. 更新时只覆盖传入的字段，未传字段保留原值；若本次改了任一金额，则重算 `gross_pay`
   与 `net_pay`（除非本次显式传了汇总值）。

### 2.3 与截图的字段映射

界面文案与截图逐字一致（基本工资、绩效工资、岗位工资、补贴、绩效奖惩、其他、法定假期
加班工资、病假扣款、事假扣款、其他扣款、应发税前工资、养老、医疗、失业、公积金、个税、
税后扣除、实发工资），避免用户对不上工资条。姓名不落库。

## 3. Action 契约（10 个）

| action | 读写 | origin | 入参 | 返回 |
| --- | --- | --- | --- | --- |
| `salary.status` | 只读 | agent/UI | — | `{ version, records, latestDate, latestNetPay, currentYearNetPay }` |
| `salary.stats` | 只读 | agent/UI | `year?`（默认今年） | `{ year, records, months, netTotal, grossTotal, incomeTaxTotal, socialTotal, deductionTotal, avgNetPay, monthly[12], latest, latestMonth, previousMonth, mom }` |
| `salary.recordList` | 只读 | agent/UI | `year?`、`from?`、`to?`（`YYYY-MM-DD`）、`cycle?`、`limit?`（1–500） | `{ items, total, year, from, to }`，按 payDate 倒序 |
| `salary.recordGet` | 只读 | agent/UI | `id` | `{ item }` |
| `salary.recordCreate` | 写 | agent/UI | `payDate` 必填 + `cycle?` + 18 个金额 + `note?` | `{ item }` |
| `salary.recordUpdate` | 写 | agent/UI | `id` 必填 + 同上任意字段 | `{ item }` |
| `salary.recordDelete` | 写 | agent/UI | `id` | `{ deleted: true, id }`（软删除） |
| `salary.dataTables` | 只读 | UI | — | 白名单表与列 |
| `salary.dataQuery` | 只读 | **仅 UI** | `table`、`limit?` | `{ table, rows }` |
| `salary.actionSchema` | 只读 | agent/UI | — | 本域 action 清单（自证数据源） |

约定：

- 写操作**允许 agent 直接调用**（用户口述「10 月 15 日工资 10672.36」时可落库），描述里
  写明会写库；删除是软删除。
- 金额参数在 schema 中全部声明为 `number`，描述带截图字段名；`payDate` 用 `string` +
  `pattern` 提示，后端严格校验。
- `stats.monthly` 固定 12 个月桶，按 `payDate` 所属月份**求和**（日结多笔会合并）：
  `{ month, records, netPay, grossPay, incomeTax, socialTotal }`，无记录月份 `records=0`。
- `latest` 为当年最后一笔记录，`latestMonth` 为当年最后一个有记录的月份汇总，
  `previousMonth` 为再往前一个有记录的月份；`mom = { amount, percent }`。
- 年度口径按 `payDate` 前 4 位筛选；`socialTotal = 养老+医疗+失业+公积金`；
  `deductionTotal = 税前扣款+社保公积金+个税+税后扣除`。

能力清单（`capabilities.list`）：

```js
records: [{ kind: "record", title: "工资记录",
  description: "一笔工资（日结/月结）：日期、应发、实发、各项收入与扣款。",
  when: ["记录某天/某月的工资", "查询或比较一段时间收入"],
  notFor: ["报销与支出流水（用 storage）", "任务与日程"],
  primaryAction: "salary.recordCreate", keyArgs: ["payDate", "netPay"] }]
fields: [payDate, cycle, netPay, grossPay, basePay, performancePay, ...]
```

## 4. 页面与交互

视图顺序：`records`（工资记录）、`stats`（统计）、`config`（设置）、`data`（数据）、
`actions`（Action）。首屏进「工资记录」。

### 4.1 工资记录页 `records`

```text
┌ 工资记录                                  [＋ 记一笔] ┐
│ 最近实发 10,672.36  最近月合计 10,672.36  今年累计 …  │
│ 2026-10-31 · 月结 · 环比 +2,483.19 (+30.3%)           │
├ 年份 [全部 ▾]  类型 [全部 ▾]        共 4 笔           │
│ 2026年10月 · 合计 10,672.36                           │
│  10-31  月结  实发 10,672.36  应发 12,280.00  …      │
│ 2026年09月 · 合计 8,189.17                            │
│  09-30  月结  实发  8,189.17  应发  9,720.00  …      │
└───────────────────────────────────────────────────────┘
```

- KPI 行：最近一笔实发（大字，附日期/类型）、最近有记录月份的合计、今年累计实发、
  今年个税；无数据时显示 0/—。
- 列表按**自然月分组**（组头显示「2026年10月 · 合计 10,672.36」），组内按日期倒序；
  每行：日期（MM-DD）、星期、`月结/日结` 胶囊、实发、应发、社保公积金、个税；
  点击行内展开详情（三组字段全量、备注、更新时间），带「编辑 / 删除」；
  删除需行内二次确认（不弹系统 dialog）。
- 新建/编辑表单为页面内卡片（不遮罩），分组：
  1. 日期（`type=date`，必填）+ 类型（月结/日结，默认月结）+ 备注（可选）；
  2. 收入项 7 个；
  3. 税前扣款 3 个；
  4. 社保与个税 6 个；
  5. 实时汇总条：应发税前、社保公积金、个税、实发（随输入即时计算，只读）。
- 选中日期已有记录时，表单顶部提示「该日已有 n 笔记录」，并提供「编辑最近一笔」按钮；
  保存仍可新增。
- 金额输入 `type=number step=0.01 min=0`，失焦格式化两位小数；空值视为 0。
- 保存成功刷新列表并收起表单；失败显示后端错误（日期非法、金额非法）。

### 4.2 统计页 `stats`

- 顶部年份切换 `‹ 2026 ›`，右侧「共 n 笔 / 覆盖 m 个月 / 月均实发」。
- KPI：年度实发合计、月均实发、年度应发、年度个税、年度社保公积金。
- 12 个月柱状图：纯 CSS flex 柱（不用第三方图表库），柱高按当年最大值归一；
  无记录月份显示空槽；柱顶 2 位小数，hover `title` 显示「月份 · 实发 / 应发 / 个税」；
  最高月高亮主题色，其余半透明。
- 环比卡：最近有记录月份 vs 上一个有记录月份，显示金额差与百分比；不足两个月时显示
  「无对比」。
- 最近月份构成：收入项与扣款项两组横向比例条（相对应发），标注金额与占比。
- 月度明细表：月份 / 笔数 / 应发 / 实发 / 社保公积金 / 个税 / 环比。
- 全部缺失时给空态引导「先去工资记录页记一笔」。

### 4.3 设置页 `config`

- 统计卡：记录数、覆盖月份数、最近日期、数据库表名。
- 口径说明：计算公式、日期维度、日结/月结、软删除、只存本机/备份包含、agent 可写范围。
- 当前数据 JSON（折叠）。

### 4.4 数据页 / Action 页

- `data`：复用 `packages/addons/lib/data-view.cjs`，接 `salary.dataTables` /
  `salary.dataQuery`（经 `legacy-data.cjs` 适配），表 `salary_record`。
- `actions`：复用 `packages/addons/lib/action-schema-view.cjs`，域 `wb-addon-salary`，
  数据来自 `salary.actionSchema`。

### 4.5 界面约束

- 业务容器全宽，不设 `max-width` + `margin:0 auto`；内容页普通整页滚动，不加 `wb-fill`。
- 颜色只使用 `--wb-*` 主题 token；浅色/深色都要验证卡片、输入框、柱状图、hover/disabled。
- 响应式：≥960px KPI 四列、表单三列；760px 以下单列，KPI 两列；360px 无横向溢出。
- 空态、加载态、错误态各有独立文案；错误不伪造空数据。
- 每页 1 个 `h2` 标题，金额使用 `tabular-nums`。

## 9. 决策记录与待确认

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 时间维度 | `payDate` 日期（YYYY-MM-DD） | 用户明确：工资有日结和月结，不能只按月份 |
| 日结/月结 | `cycle` 标记，不参与金额口径 | 只是分类，统计按日期归属月份聚合 |
| 同日多条 | 允许；UI 提示已有记录 | 日结可能一天多笔，不强制唯一 |
| 金额精度 | REAL + round2 | 与现有插件一致；两位小数足够 |
| 是否存姓名 | 不存 | 用户明确「除去姓名」 |
| 备注字段 | 保留可选 `note` | 补录时说明来源，不影响统计 |
| agent 写入 | 允许 create/update/delete | 支持口述录入；软删除可恢复 |
| 汇总字段 | 允许传入覆盖 | 只记得实发或截图缺字段时也能补录 |
| 初始数据 | 已确认：4 张按图片顺序录 2026-07/08/09/10 | 前 3 张未标注月份，按用户确认的月份取当月 1 日，`note` 注明来源 |
