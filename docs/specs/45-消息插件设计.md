# 消息插件设计（dsh-workbench-message）

状态：设计稿（待评审）· 版本：0.1.0 · 目标宿主：`dsh-workbench-host >= 0.6.5`
相关任务：`01a1ce32-62a3-7a06-98e9-034081a90063`（本设计）、`01a1ce32-7851-7c5f-bc99-60355ee786af`（实现）

## 0. 一句话

工作台新增一个**与任务/标签/站点/储物同构**的消息插件：给子插件和 agent 一个统一的
`message.send` 入口，消息落在本机 SQLite、通过域事件实时推送，浏览器端按配置响提示音；
插件之间只靠 **action 名 + 事件名 + 版本化 payload** 通信，互不 import、互不直读表。

### 0.1 已确认的取舍（2026-11-12 与用户确认）

| 取舍 | 结论 | 影响 |
| --- | --- | --- |
| 跨设备 / 云端同步 | **仅本机**：不声明 sync，不参与 change_log 同步，也不提供备份导出/导入 | `registerDomain` 用 `sync: { tables: [] }`，不实现 `exportData/importData`；`DomainPublicInfo.backup` 自然为 `false` |
| 提示音 | **默认开**，配置页可开关、调音量、设免打扰时段 | 浏览器 WebAudio 合成，无音频资源、无新依赖 |
| 保留策略 | **已读 30 天清理、未读永久**，总量上限 **5000** 条 | 清理任务在写入后与实例启动时触发，超限从最旧已读删起 |
| 通道 | **工作台内自建消息中心**，不接 `dsh_im_*`、不转发系统通知 | 与 IM/外部通道保持边界，见 §10 |

```js
          { id: "actions", title: { zh: "Action", en: "Actions" } },
        ],

      }),
```

> **同步陷阱（实现时务必照做）**：宿主 `registerDomain` 里
> `sync.tables ?? def.tables.map(row)`，不写 `sync` 会**默认按行同步**。消息按用户要求
> 只留本机，所以必须显式 `sync: { tables: [] }`，并且实现里不调用 `api.markSyncDirty`。

## 2. 统一入口契约

### 2.1 action 一览

| action | 作用 | 必填 | 副作用 |
| --- | --- | --- | --- |
| `message.send` | 发一条消息，返回 `messageId` | 无（全可选，但 `title` 与 `body` 至少一个非空） | 写库、发 `message.created` 事件、触发提示音 |
| `message.list` | 分页列出消息 | 无 | 只读 |
| `message.unreadCount` | 未读数（可按来源/级别分组） | 无 | 只读 |
| `message.markRead` | 标记已读（单条 / 批量 / 全部） | 三者其一：`ids`、`all`、`before` | 写库、发 `message.read` 事件 |
| `message.configGet` | 读配置（提示音、免打扰、保留天数等） | 无 | 只读 |
| `message.configSet` | 写配置（白名单校验） | `key` + `value` | 写 meta 表 |
| `message.configReset` | 恢复默认 | 无 | 写 meta 表 |
| `message.dataTables` | 「数据」页表清单（自证） | 无 | 只读 |
| `message.dataQuery` | 只读表数据（分页/过滤） | `table` | 只读 |
| `message.actionSchema` | 「Action」页运行时清单（自证，不走宿主 schema 接口） | 无 | 只读 |

返回：`{ ok: true, messageId, deduped: false, unread: 3 }`；

### 2.4 三种调用形态（可直接复制）

**A. 服务端（子插件的 `lib/` 里）**

> 注意：`DomainSetupApi` 只有 `hasDomain`，没有 `invoke`。跨域调用要用 `apply(ctx)` 里的
> `ctx.workbench`，在模块作用域存一份引用即可（四包已经在 `setup(api)` 里存 `domainApi`，
> 照抄同一形态）。

```js

let host = null;
export function apply(ctx) {
  host = ctx.workbench;
  ctx.effect(() => host.registerDomain({ /* ... */ }), "xxx-domain");
}

// 任意业务代码里：弱耦合，只认 domain 与 action 名，不 import 消息插件
if (host?.hasDomain("wb-addon-message")) {
  try {
    const r = await host.invoke("message.send", {
      title: "标签已合并",

      level: "success",
      source: "tags",
      dedupeKey: "tags-merge-" + Date.now(),

    // r.result.messageId
  } catch (error) {

  }

```

**B. 客户端（其它插件的视图里，拿到的 `props.api`）**

## 3. 解耦规则（评审重点）

1. **不 import**：消息插件不 import 任何业务插件；业务插件不 import 消息插件。
   全仓审计：`grep -rn "addons/message" packages/addons/{tasks,tags,sites,storage}` 必须为空，
   反向亦为空。
2. **不直读表**：`message` 表归消息插件，其它插件不得 `SELECT ... FROM message`；
   需要未读数一律走 `message.unreadCount`。
3. **只认名字**：跨插件通信只有三样东西——action 名（`message.send`）、事件名
   （`message.created`）、版本化 payload（`{ version: 1, message }`）。都写在本文档里，
   改字段就是改契约，要升 `version`。
4. **可缺席**：调用方先探测（服务端 `api.hasDomain("wb-addon-message")`；客户端
   `api.call` 失败即视为未安装），**失败不阻断主流程**，最多 `log`/`warn` 一条。
   这与 sites 对 tags 的可选依赖是同一种写法。
5. **单向依赖**：消息插件不需要认识任务/站点等任何业务域；`source` 只是自由文本。

## 4. 事件契约

| 项 | 值 |
| --- | --- |
| 通道 | 宿主 SSE `GET /workbench/api/events` 的 `domain-event` |
| domainId | `wb-addon-message` |
| event | `message.created` / `message.read` / `message.cleared` |
| `message.created` payload | `{ version: 1, message: { id, title, body, level, source, audience, dedupeKey, createdAt, readAt: null } }` |
| `message.read` payload | `{ version: 1, ids: [...], unread: 3 }`（`all=true` 时 ids 为 `[]` 且带 `all: true`） |
| 断线 | SSE 断线不补发；客户端重连后调 `message.list { since }` 与 `message.unreadCount` 对账 |
| 顺序 | 以 `createdAt` 单调递增为序；同一毫秒内用 `id` 兜底 |

**去重与抑制**：`dedupeKey` 的唯一性由部分唯一索引保证
（`WHERE dedupe_key IS NOT NULL AND deleted_at IS NULL`）。命中时不写库、不发事件、不响铃，
只返回已存在 id。前端另外对同一 `dedupeKey` 做 5 秒内二次抑制，防止重连重放。

## 5. 提示音（浏览器端）

**技术路径**：WebAudio 合成，不引外部音频文件、不加依赖。

```
一次提示音 = OscillatorNode(sine) + GainNode 包络
info/success：880Hz 两短音（各 70ms，间隔 90ms，gain 0.18 → 0）
warning：660Hz 三短音；error：520Hz 三短音 + 更低频尾音
```

**自动播放策略**：

- 浏览器要求用户手势后才能出声。模块加载时注册一次
  `document.addEventListener("pointerdown", unlock, { once: true, capture: true })`，
  在回调里 `new AudioContext()` 并 `resume()`；未解锁前事件只累加未读，不播放。
- 锁定状态用 `localStorage["wb.message.sound"] = "locked|ready"` 记录，设置页显示
  「点击页面任意处启用提示音」的提示。
- 页面不可见（`document.visibilityState === "hidden"`）时默认**不响**，恢复可见时补一次
  未读角标刷新；该行为可在配置页开关（`sound.whileHidden`，默认关）。

**配置项（`message.configSet` 白名单）**：

| key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `sound.enabled` | boolean | `true` | 总开关 |
| `sound.volume` | number 0–1 | `0.4` | 音量 |
| `sound.whileHidden` | boolean | `false` | 页面隐藏时是否响 |
| `quiet.enabled` | boolean | `false` | 免打扰总开关 |
| `quiet.from` / `quiet.to` | `"HH:mm"` | `"22:00"` / `"08:00"` | 免打扰时段，支持跨零点 |
| `quiet.levels` | `("info"|"success"|"warning"|"error")[]` | `["warning","error"]` | 免打扰期间仍允许出声的级别 |
| `retention.readDays` | number | `30` | 已读保留天数（0 = 不自动清理） |
| `list.pageSize` | 12/20/50 | `20` | 消息页每页条数 |

**合并策略**：800ms 窗口内的多条事件合并成一次提示音（按最高级别选音色），角标数字
照常逐条累加。级别为 `agent` 的 `audience` 不发声（它们面向 agent 会话，不面向用户）。

**未读角标**：

- 一期：消息视图内顶部 chip「未读 N」+ 列表未读加粗；首页卡片描述显示
  「N 条未读」（卡片描述是静态字符串，一期先不放进卡片，避免每有消息就刷新 domain 元数据）。
- 二期（**待确认**，需要宿主小扩展）：宿主 `window.__WB_HOST__` 增加
  `subscribe(fn)`/`call(action,args)` 两个方法，并把未读数作为视图 tab 的角标。
  本期不依赖它，见 §12。

## 6. 数据与生命周期

### 6.1 表结构

```sql
CREATE TABLE IF NOT EXISTS message (
  id          TEXT PRIMARY KEY,
  title       TEXT NOT NULL DEFAULT '',
  body        TEXT NOT NULL DEFAULT '',
  level       TEXT NOT NULL DEFAULT 'info',   -- info|success|warning|error
  source      TEXT NOT NULL DEFAULT '',       -- tasks/tags/sites/storage/agent/...
  audience    TEXT NOT NULL DEFAULT 'user',   -- user|agent|all
  dedupe_key  TEXT,
  meta        TEXT NOT NULL DEFAULT '{}',     -- JSON 文本
  created_at  INTEGER NOT NULL,
  read_at     INTEGER,
  deleted_at  INTEGER,
  rev         INTEGER NOT NULL DEFAULT 1
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_message_dedupe
  ON message(dedupe_key) WHERE dedupe_key IS NOT NULL AND deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS idx_message_created ON message(deleted_at, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_message_unread  ON message(deleted_at, read_at);
```

- id 用宿主注入的时钟 + 随机后缀（与四包一致，不依赖自增）；
- `read_at IS NULL` 即未读；
- 删除用软删除（`deleted_at`），与四包保持一致，便于「清空」可回滚（清理任务物理删）。

### 6.2 保留与清理

- 触发时机：每次 `message.send` 之后（同步、轻量）+ 实例启动时一次；
- 规则：`已读 && created_at < now - readDays 天` 物理删除；未读永不自动删；
- 上限：存活消息 > 5000 时，从最旧的**已读**记录删起，删够为止；若已读不够，停止并
  在 `message.list` 的 `warnings` 里提示「消息已达上限，请清理未读」；
- 单次清理最多删 200 条，避免长事务。

### 6.3 为什么不进同步 / 不做备份导出（用户已确认）

- 消息是本机瞬时通知，跨设备后「未读」语义没有共识，同步会产生「手机响了电脑也响」的噪音；
- 备份里放消息只会让备份包变大，恢复后旧通知也没有意义；
- 因此：`sync: { tables: [] }`、不实现 `exportData/importData`、不调 `markSyncDirty`。
- 代价：换机/重装后历史消息丢失——这是接受的取舍，写进消息页的空态文案。

| `config` | 配置 | 提示音开关/音量试听、页面隐藏时是否响、免打扰开关与时段、保留天数、每页条数；即改即存，失败回滚 |
| `data` | 数据 | 只读浏览 `message` 表：`message.dataTables` + `message.dataQuery`（游标/分页、按列排序、导出 CSV 复用四包的数据页组件） |
| `actions` | Action | 自证清单：`message.actionSchema` 返回本域运行时注册的 action，与四包同一写法，**不读宿主 `/workbench/api/schema`** |

### 7.2 首页卡片

由宿主按 domain 的 `title`/`description` 自动生成：宿主 `cardIcon(title)` 取标题首字
（「消息」→「消」），不读插件图标；卡片标题取 `title`、描述取 `description`、徽章取
`version`。点卡片进入该模块第一个视图（`inbox`）。未读数放视图内，不放进卡片描述
（避免 domain 元数据频繁变更引起 SSE `domains-changed` 抖动）。

```
client/
```

## 10. 与 DSH 既有通知 / IM 的边界

| 能力 | 归属 | 是否复用 |
| --- | --- | --- |
| `dsh_im_*` 工具、群消息、外部 IM | DSH 宿主（IM 通道） | **不复用**：那是「跟人/群聊天」，本插件是「工作台内通知」 |
| 系统级通知（OS 通知中心） | 平台 | 不做：macOS/Windows 权限与形态差异大，且会与提示音重复 |
| 任务/站点等的业务事件 | 各业务插件 | 业务插件发事件、消息插件只消费 `message.send`，不反向订阅业务事件 |
| 邮件/短信/webhook | 外部通道 | 非目标，需要时另立任务 |

一句话：**消息插件是「本机、工作台内、面向用户的通知中心」**，不是 IM，也不是推送服务。
