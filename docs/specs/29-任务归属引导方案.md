## 2. 发现入口与四种决策场景

保留通用发现链 `capabilities.list → capabilities.get(domain=tasks) → actions.help`，在静态 capability 明示“创建前调用 tasks.capabilities / tasks.resolveTable；tableId 或 tablePath 必须明确”。primaryAction 仍为 tasks.create；keyArgs、relations、examples、notes 与 actions.help 一起更新，不只写在仓库文档里。

拟新增只读 `tasks.capabilities({ limit?, cursor?, tableId? })`：`tableId` 为精确查询（string/number，与 cursor 互斥），目标不存在或祖先链损坏时明确报错；返回 guidance、tables、total、nextCursor、truncated、tagDomainAvailable。默认 50、最大 200，游标失效明确要求重查；不能把第一页当作所有表。tables 每项包含：

- id、name、完整可读 path、可回传 tablePath、pathSegments（id/name/type）、description。显示完整面包屑含根；可回传路径相对唯一逻辑根，明确区分两者。
- taskCount：未软删任务总数，包括已关闭/完成/重启；可另给 activeTaskCount，不混称“待办数”。
- lastUsedAt：首版定义为该表未删除任务 `MAX(updated_at)`，空表 null；这是最近任务变更的代理值，不是阅读/浏览/访问时间，响应注明 lastUsedBasis。
- commonTags：该表未删除任务的标签频次 Top 5，次数相同按稳定 id 排序；标签域未安装时为空并说明 unavailable，不能当作“没有标签”。

插件能力描述中增加职责边界与归属指引：例如 storage 的物品登记仍走 storage.create；开发 storage 功能的工作项走 tasks。由安装环境中显式配置的 domain→tableId 映射连接实际表，返回时动态求路径；不在插件源码硬编码用户表 id，不因安装插件自动造表。映射缺失/失效返回未配置及 resolve 示例，不能偷偷用同名表替代。该映射的保存入口与 capability schema 扩展需列入后续实施范围，并随宿主版本发布。

| 场景 | guidance 与 help 必须给出的行动 |
| --- | --- |
| 已有表的具体开发/修复/设计任务 | 查职责、路径与描述，明确目标后带 tableId 创建；明确插件映射优先于关键词猜测。 |
| 已确认属于插件的新子模块 | 先核对树形态，明确组/表与描述；无适合表时可在授权范围内 createMissing 建路径，不能为每条任务建一张表。 |
| 一次性问答/临时查询 | 不建任务；物品、站点、标签记录使用各自业务插件。 |
| 目标不确定或多候选 | 展示带路径与描述的候选让用户选择；不按第一项、热度或“分高”自动写入。 |

## 3. resolveTable：候选检索而非替用户做决定

拟新增只读 `tasks.resolveTable({ query, limit? })`，query 必填非空，limit 默认 5、最大 20。只返回存活 TABLE，且祖先链完整、无删除、无环；损坏链返回诊断，不把残缺路径作为合法目标。响应包含 candidates、total、truncated、needsSelection、matchMethod；每个候选含 id、path、tablePath、description、taskCount、score 与 matchedOn/reasons。零结果也成功返回空候选和新建/改词指引，绝不建节点。

首版采用可解释的确定性词项匹配：表名精确 > 表名词项 > 路径词项 > 描述词项 > 常用标签；最近使用只用于同分排序，最终以 id 打破同分。对中文请求做有限的停用短语处理与受控同义词表，例如“存储/storage”，该词表在实现/测试中版本化，不把任意自然语言推断伪装成语义理解。query 包含 SQL 通配符按文字处理，使用绑定参数。

“存储相关的待办”排到 storage 前列的验收必须基于明确 fixture：存在 storage 表、描述包含存储职责、词项规则识别存储；加入无关高频表验证其不会靠热度抢占。其他真实表达只测覆盖，不承诺任意中文都能识别，也不输出概率式“置信度”。即使唯一候选，也只建议 agent 核对，不隐式创建。

## 4. 写入目标契约与路径歧义

拟扩展 tasks.create，bulkCreate 的每条 record 使用完全相同契约：

| 字段 | 拟定规则 |
| --- | --- |
| tableId | 存活 TABLE id，沿用 string/number 接受面；组 id 报错。 |
| tablePath | 名称路径 string，或名称段 string[]（用于名字中含 `/` 的既有节点）；相对于逻辑根。 |
| createMissing | boolean，默认 false；仅 tablePath 模式有效；只有显式 true 才能建节点。 |
| pathDescriptions | 与路径段等长的 string[]，仅 createMissing=true 时使用；新建的每个节点必须给非空职责描述，已有节点不覆盖描述；复用 2000 字符上限。 |

tableId 与 tablePath **恰好提供一个**；两者同时提供返回 TARGET_CONFLICT，不按优先级偷偷忽略一个。两者均空返回 TABLE_REQUIRED；createMissing=true 搭配 tableId 返回 INVALID_TARGET_OPTIONS。更新任务未指定目标时保留原归属，不能把普通标题修改也变成必选表。首版纠正复用 tasks.update({ id, tableId })（省略 type），不新增重复的 reassignTable action；批量复用 bulkUpdate 的 tableId，既有 migrate 的调用面继续保留。

路径规范：

1. 字符串按 `/` 切分，各段 trim；禁止空段、`.`、`..`、首尾斜杠。数组允许名称内 `/`，不得用自动分隔猜测替代；回执遇此名称时 tablePath 返回数组以便无损回传。精确匹配现有名称，不因大小写/Unicode 折叠而擅自合并节点。每段复用现有 20 字符限制；新路径最大 32 段、总输入最大 2048 字符，超过返回限额错误。历史更深节点可用 tableId，不能为此迁移旧树。
2. 根不写入输入，根名称是展示信息；不猜用户第一段是不是根。中间段必须是 GROUP，末段必须是 TABLE；末段为组返回 PATH_TYPE_CONFLICT，不自动进入其第一张表。
3. 同一个父节点下同名组/表都算冲突；遇到多行同名返回 PATH_AMBIGUOUS，列 id/type/path，让人用 tableId 或修正节点。不能以 LIMIT 1 消除歧义。异父节点同名合法，全路径消歧。
4. createMissing=false 遇缺失返回 PATH_NOT_FOUND，指出已解析前缀与第一个缺失段；true 时只创建缺失中间组和末表，已有节点类型不匹配仍报错。软删节点不复活；可按现有软删语义新建同名节点，回执标示创建新 id。
5. 例：若 `DeepseekHarness/插件开发/dsh-workbench` 的末段已经是 TABLE，再请求其下 `/storage` 必须失败。可另建平级的 `dsh-workbench子模块/storage`（前者为组），或另案评审“表改组+原任务迁移”；本方案不自动改类型、不搬已有任务、不改名避冲突。

单次建路径示例（拟，评审后才可调用）：

```json
{
  "action": "tasks.create",
  "args": {
    "title": "设计物品导入校验",
    "tablePath": "DeepseekHarness/插件开发/storage",
    "createMissing": true,
    "pathDescriptions": ["DSH相关工作", "插件开发与维护", "storage插件开发任务，不用于登记物品"],
    "dedupeKey": "feedback:<稳定来源id>"
  }
}
```

## 5. 事务、重复执行与事件

路径节点复用和任务去重是两个不同保证。相同路径重复执行不能重复建节点；没有 dedupeKey 时仍允许创建同名新任务，不能声称整次请求自动幂等。

拟把查找目标、逐段补建、任务写入、标签写入、重启链变更、sync_change_log 纳入一个最外层 BEGIN IMMEDIATE；bulkCreate 继续整批一个事务。抽出不自行 BEGIN、不发事件的节点校验/写入助手，共用于 taskNodes.create、路径创建及相关改名/移动校验。不能循环调用 action 层而产生嵌套 BEGIN。sort 的读取、同级名称复查必须在写锁内。失败时任务、节点、标签和同步日志一并回滚；事件收集到提交后发送，dryRun 不发事件，避免 UI 看见后来回滚的节点。

新 dedupeKey 在事务内查询后再写；已有未删除键时返回原任务及其真实路径、deduped=true，不因请求的新路径补建空节点，不移动原任务。请求目标与原归属不同则附 DEDUPE_TARGET_MISMATCH notice，明确“返回已有任务，未执行归属修改”，给 update 指引；缺少任何目标仍 TABLE_REQUIRED。保留原本“相同键复用已有任务，不校验标题相同”的行为。历史同键多行时返回 DEDUPE_AMBIGUOUS，而不是继续挑第一条。

并发保证限定为同一个 SQLite 库内、所有相关本地写入口采用同一校验事务时的串行化。云端/多设备可各自建出同名不同 id；同步冲突检测必须报告并交人处理，不能承诺跨设备全局 exactly-once。首版不直接加可能使旧库启动失败的唯一索引；后续如加 `(parent_id,name) WHERE deleted_at IS NULL` 或 dedupe 唯一索引，需先检查存量冲突并确认云端同步处理策略，绝不能通过自动删重来让迁移成功。

bulkCreate 的 dryRun 仍可用事务后回滚方案，但明确返回 wouldCreateNodes 与临时节点标识，不能让调用者把回滚后的 id 当成可用目标；同批相同路径应复用一次，第二条失败整批不留空组。复用已有 dedupe 记录不计入实际 created，单列 deduped，修正现有按 records 长度计数的误导。

## 6. 可操作错误与回执

缺目标采用直接报错，不启用“未归类”兜底，不保留隐式默认配置开关。空库返回候选为空与建路径示例，不自动造业务树。已有默认组/表仍可被显式选择，保留启动种子与旧迁移规则，不借本需求清理旧数据。

错误至少包含 code、message、candidateTables（至多 5 条）、nextActions、retryable。TABLE_REQUIRED 候选带 id/path/description/taskCount，按标题/描述的词项候选生成，若无匹配则给清楚标注“可浏览表，非推荐”的列表。还需覆盖 TABLE_NOT_FOUND、TARGET_NOT_TABLE、PATH_NOT_FOUND、PATH_TYPE_CONFLICT、PATH_AMBIGUOUS、INVALID_PATH、DEDUPE_AMBIGUOUS，以及树损坏、并发繁忙的恢复指引。失败不应产生任何业务行变化。

Workbench 目前只暴露文本，因此首版错误 message 必须自含稳定 code、候选和可复制的下一步示例；内部可以有结构化 details，但不得只依赖它。UI RPC 与 Workbench 都要验证信息没有被截断/吞掉。若要在宿主新增结构化错误输出，作为单独的兼容扩展评审，保留旧 text，不能把失败装成普通成功结果。

示例错误文案：`TABLE_REQUIRED：未写入任务。请先选择目标表；候选：…。查询 tasks.resolveTable({query:"…"})；新建请在确认组/表路径后使用 tablePath + createMissing:true + pathDescriptions。拿不准就问用户。` 示例使用动态候选 id，不能给不存在的固定 id 造成二次失败。

创建、更新（包括仅修改标题）、bulkCreate/bulkUpdate、迁移与幂等复用结果统一附 tableId、tablePath、pathSegments、tableDescription；已有 task.path 保持原结构。createdNodes 仅列实际新建节点。文字回执说明“已放入 X 表；若不属于，请告诉我目标表或新节点名”，给任务 id 和 `tasks.update({id,tableId})` 提示；幂等复用必须说“已存在”，不能继续渲染“已创建”。路径是回执当时快照，节点改名/移动后重新读取最新路径。

## 7. UI 必选与纠正体验

所有新建入口（普通、时间线、重启）目标初始为空，选择框有“请选择目标任务表”空选项；未选不能提交。当前树选择/来源任务可作为推荐提示，不自动回填为已确认选择。目标列表展示完整面包屑与描述，组节点不可选；树刷新删除所选目标时清空并提示，不回落第一项。

旁边提供“没有合适的表？新建节点”：展示将建的组/末表、完整路径、各节点职责与冲突；用户明确确认后才创建。优先与任务提交同一事务提交 createMissing，取消弹窗不留空节点；若独立树管理明确点击创建节点，则按该入口独立操作语义，不冒充任务原子提交。错误保留已填写任务正文，允许重新选目标。成功 toast/详情显示路径，纠正入口带当前任务 id，可选新目标后提交 update。

## 8. 历史复查：先清单，后由人确认

不在启动迁移时更改 task.table_id。后续另经授权生成一次性只读复查清单：任务 id/标题、现表路径、标签、建议目标路径、匹配理由、候选冲突、当前 rev/updatedAt、人工决定与确认人/确认时间。旧默认表的任务并不全是错误；没有标签、不确定或跨主题的记录一律标“待人工判断”。不调用 CRUD 为本次方案制造清单。

实施迁移前，用户逐项或按清晰规则确认清单；只移动已确认的明确 id。再次读取并比较 rev、原表和目标有效性，过期项停下复查，禁止拿很久以前的清单盲写。现有 bulkUpdate dryRun 可预览，但当前普通更新不能据此宣称具备原子 rev 前置条件；实施时需增加条件写入或专用受控执行层。实际迁移保留 before/after、审计与同步记录，提供按确认清单逆向恢复的预览；恢复也要检查其后改动，不覆盖人工新选择。

## 9. schema、版本与兼容成本

这是破坏性行为变化，实施版本确定为 tasks 3.0.0、host 0.6.0、SDK 0.2.0；配套 tags 1.6.8、sites 1.9.1、storage 1.3.2。新增 action/schema、required/oneOf、字段描述、help 示例、capabilities 和人读功能清单须同时生效。tasks.create required 保留 title，使用 oneOf 表达 tableId/tablePath 二选一并配运行时校验；不能 required 两个字段。若宿主帮助渲染/参数校验不支持 oneOf，必须补展示与测试，不能只藏在 JSON 里；bulk records.items 也要声明完整目标契约。

插件 package version、wb.addon.version、client registerAddon、lib index 及构建 client 版本统一；如扩展通用 capability 契约，宿主及相关插件一起发布并核对 actionCount/primaryAction/warnings。本方案不强行把 tasks 的职责硬塞进其他业务记录接口。

数据库 schema 版本与插件版本分开：目前 [db.js](../../packages/addons/tasks/lib/db.js) 写 task_schema_version=2。首版查询派生路径、统计与词项无需改 task/task_node 列，因此不为接口更新机械升级库版本。若新增持久映射或唯一索引确需新存储结构，再设计 version=3 的幂等前向迁移，先备份与检测重复、断链/环、软删祖先，冲突只报告不自动修数据。默认树初始化与历史导入不等于运行期创建兜底，保留既有数据行为，分别测试。禁止通过加载生产插件来做“只读检查”，ensureSchema 会写数据。

| 客户端 | 两处默认值、时间线/重启入口、树选择、表单空态、错误展示、toast 都需改；旧 client 若仍主动传第一张表，服务端无法判断是否人选，必须完整重装匹配的 bundle。 |
| 现有测试 | [test-native.mjs](../../scripts/test-native.mjs)、[test-data.mjs](../../scripts/test-data.mjs)、[test-config.mjs](../../scripts/test-config.mjs)、[test-backup.mjs](../../scripts/test-backup.mjs)、[test-nodeps.mjs](../../scripts/test-nodeps.mjs) 大量创建省略 tableId。需在各测试 fixture 显式造/选表后传入，保留专门的缺目标失败用例；不能改通用测试调用器偷偷补目标。 |
| 异常断言 | 标签/优先级等测试若没加目标，会先得到 TABLE_REQUIRED 而掩盖原规则；逐项补合法目标，保留原校验价值。 |
| 批量/幂等 | 所有 records 必须有目标；dryRun 返回节点预览，实际 created/deduped 拆计数会影响现有断言。旧 dedupeKey 异目标不移动，回执新增 notice。 |
| 同步与备份 | 新路径为派生输出，不持久覆盖 ID path；新建节点与任务均按现有同步协议记录。需要验证还原、同步后树与任务关系，跨设备同名冲突不自动合并。 |
| 源文件规模 | [tasks.js](../../packages/addons/tasks/lib/tasks.js) 与 [client.src.cjs](../../packages/addons/tasks/client/client.src.cjs) 当前都超 900 行；后续先拆职责模块，再增加发现/归属/回执逻辑，不能继续往大文件堆。这也是实施成本，不算“几行改默认值”。 |

## 10. 实施顺序与验收矩阵（评审通过后）

1. 独立评审目标互斥、路径语法、组/表冲突、description 输入、搜索范围、错误传递、旧客户端强制升级策略与发布窗口。
2. 拆分超限模块，保留原导出面；提取只读路径/候选与无事务节点助手，补一致校验。
3. 同步实现 capabilities、resolveTable、写入事务、错误/回执与 action schema；同步 UI 和所有调用 fixture。
4. 临时库/临时 profile 验证与完整构建安装验证；用户确认发布/安装范围后才能作用到当前实例。历史迁移独立评审、独立确认，不能与功能发布绑在一起。

| 验收组 | 必须验证 |
| --- | --- |
| 取消默认 | create 与 bulk 每条无目标均 TABLE_REQUIRED；已有第一表、仅一张表、空库、source=1/2 都不得兜底。比对 task/node/tag/sync log 无新增，UI 无假事件。 |
| 显式归属 | 已有 tableId/路径命中；错误 id、组 id、同时传两个目标、缺失路径、末段组、中段表、重名路径、包含斜杠名字数组、空段/超限分别测试。 |
| 原子建路径 | 缺多级组/表一次建好；重复路径不重复节点；中途日期/标签/重启校验失败回滚所有写入；批量第二条失败与 dryRun 不留节点；并发相同路径只建一次。 |
| 幂等 | 稳定 dedupeKey 重试不造空节点、不重复任务；不同目标回执原路径+notice；无 key 同标题仍可重复；历史重复 key 报歧义；软删键复用规则。 |
| 发现检索 | capabilities 分页不漏报；计数/最近变更/常用标签口径固定；无标签插件可用；四场景 help 可见；存储短语 fixture 排序、歧义/零候选、通配符、同分稳定性。 |
| 回执链路 | 直接 action、Workbench 文本、UI RPC 都看得到错误码/Top5/例子；create/update/bulk/迁移/幂等回执含真实路径，现有 task.path 不变。 |
| UI | 所有新建入口为空、表必选、面包屑/描述可见；取消建表不写；树更新使目标失效；提交失败保留正文；旧 bundle 与新服务的升级提示。 |
| 历史与迁移 | 新版启动不重分现有 task.table_id；旧默认数据可显式选；有重复节点/断链的旧库不被自动清理；如启用新库迁移，重复执行幂等、失败不写版本成功标记。 |
| 兼容回归 | 优先级/日期/标签可选域、时间线/重启、批量 rollback、备份还原、同步、原有节点搜索和迁移入口的既有语义保留。 |
