# 工作区统计设计（tasks 5.2.5）

## 1. 目标与边界

统计页新增「工作区排行」，回答三个问题：哪些工作区压着最多未完成的任务、各工作区的完成率如何、有多少任务还没归属任何工作区。

首期只做**当前存量**的聚合排行，不做趋势：趋势按日期范围统计「事件」，排行按现在这一刻统计「存量」，两者混在一张卡片里会出现「合计与总量对不上」的假象（参见 `docs/specs/39-时间线统计设计.md` 对事件与存量的区分）。

不做：工作区趋势曲线、按工作区拆分的难度/优先级分布、工作区之间的人员或目录对比、跨表的工作区合并视图。扩展方向见第 8 节。

## 2. 指标口径

一个任务可关联 0..n 个工作区，因此**同一任务会在它所属的每个工作区各计一次**。这是刻意选择：排行回答「这个工作区压了多少活」，不是「任务去重后如何分配」。

| 指标 | 定义 | SQL/代码口径 |
| --- | --- | --- |
| `total` | 该工作区下的有效任务数 | `task.deleted_at IS NULL` 且存在存活关联（`task_workspace_link.deleted_at IS NULL` 且工作区本身 `deleted_at IS NULL`） |
| `open` | 开启中 | `status='0'` |
| `done` | 已完成 | `status='2'` |
| `overdue` | 逾期 | `status IN ('0','4')` 且 `substr(target_date,1,10) < today` |
| `completion` | 完成率 | `total > 0 ? round(done/total, 3) : 0` |

与既有「任务表排行」「任务组排行」共用同一套字段与计算公式，避免同一页出现两种完成率。

口径一致性要求（验收硬条件）：

- `rankings.workspaces[i].total` 必须等于 `tasks.list {workspaceIds:[该工作区 id]}` 的 `total`；
- `rankings.noWorkspace.total` 必须等于 `tasks.list {noWorkspace:true}` 的 `total`；
- 三个数字都由同一组 `deleted_at IS NULL` 条件得出，不在统计侧另开特例。

### 2.1 状态与软删

- **已重启（status=3）** 计入 `total`，不计入 `open`/`done`/`overdue`。与任务表排行一致：那一行也把重启任务算进总数。
- **已删除任务**不计。
- **已删除工作区**不计：即便关联行还在，工作区本身已软删，行不出现在排行里，其任务回落到「未关联工作区」——与列表筛选 `EXISTS (... AND w.deleted_at IS NULL)` 的口径相同。
- **已删除关联**不计：任务若只剩软删关联，等同未关联。
- **零任务工作区**保留桶（`total=0`），排序后自然沉底；`top` 足够大时可见，用于暴露「建了工作区但没用起来」。

### 2.2 多对多与「未关联」的数值关系

```
sum(workspaces[].total) + noWorkspace.total >= totals.total
```

差值是「被挂在多个工作区上的任务」重复计入的部分。页面在卡片 note 里写明这一点，避免用户拿两处数字相加对不上时误判为 bug。

「未关联工作区」是**正常状态**（很多任务本来就不属于任何目录），与任务表排行里的「未归档」同等对待：独立成行、单独可点、不混在工作区里参与 Top N 排序。

## 3. 聚合实现

在 `packages/addons/tasks/lib/stats/stats.js` 的排行段内完成，一次扫描：

1. 读存活工作区：`SELECT id,title,name,dir FROM task_workspace WHERE deleted_at IS NULL`，建桶 `{id,title,name,dir,total,open,overdue,done}`；
2. 读存活关联：`SELECT workspace_id,task_id FROM task_workspace_link WHERE deleted_at IS NULL`，建 `task_id -> [workspace_id]` 映射，指向已删工作区的映射项直接丢弃；
3. 复用已有的 `allTasks` 扫描循环，对每个任务逐个工作区累加 `total/open/overdue/done`；映射为空的任务累加到 `__none__` 桶；
4. 排序沿用 `rank()`：`(open+overdue)` 降序、`total` 降序，再 `slice(0, top)`；`top` 仍受 `stats.top` 配置与 action 入参约束（1..20）；
5. `noWorkspace` 桶只算 `completion`，不参与切片。

桶字段：`{id, title, name, dir, total, open, overdue, done, completion}`。`dir` 供 tooltip 展示本机路径，可为空串。

## 4. 返回契约

`tasks.statsReport` 的 `rankings` 新增两项（其余字段不变）：

```jsonc
"rankings": {
  "tables": [ /* 原样 */ ],
  "groups": [ /* 原样 */ ],
  "workspaces": [
    { "id": "ws_...", "title": "dsh-workbench 源码", "name": "wb", "dir": "/Users/yyq/code/dsh-workbench",
      "total": 129, "open": 12, "overdue": 3, "done": 118, "completion": 0.915 }
  ],
  "noWorkspace": { "id": "__none__", "title": "未关联工作区", "name": "", "dir": "",
                   "total": 27, "open": 5, "overdue": 1, "done": 21, "completion": 0.778 }
}
```

旧客户端只读 `tables`/`groups`，新增字段不影响它们；新客户端对缺失字段按「无数据」降级，兼容旧后端。

`tasks.statsReport` 的 action description 同步补充这两项，属 agent 可见契约，按 AGENTS.md 升版本号。

## 5. 页面设计

- 卡片 key `workspaces`，`span: 6`，标题「工作区排行」/「Workspaces」，note 写明多对多重复计数。
- 表格列与任务表和任务组排行完全一致：名称 / 任务数 `total` / 开启 `open` / 逾期 `overdue` / 完成率 `completion`（`pct` 渲染）。
- 行序即后端返回序；`noWorkspace` 行追加在末尾，标题「未关联工作区」，用弱化样式区分（不参与排序）。
- 点击工作区行 → 跳任务列表并写 `workspaceIds=[id]`；点击「未关联工作区」→ `noWorkspace=true`。两者都清空另一侧参数，与筛选面板互斥规则一致。
- 无工作区且无任务时显示空态文案（不是错误）；零工作区但有未关联任务时，卡片只显示那一行，仍能点。

## 6. 配置开关

- `packages/addons/tasks/lib/infra/config.js` 的 `SECTIONS` 在 `groups` 之后插入 `{value:"workspaces", zh:"工作区排行", en:"Workspaces"}`；
- `stats.sections` 默认值随 `SECTIONS` 自动包含新项；
- `packages/addons/tasks/client/client.src.cjs` 的 `"stats.sections"` 默认数组同步加 `workspaces`（客户端 fallback，旧 profile 未取到配置时也不至于少一块）；
- 卡片 key 必须与配置 value 同名，才能被既有的 `sectionOn(key)` 过滤。

## 7. 边界与测试矩阵

| 场景 | 期望 |
| --- | --- |
| 空库（无任务、无工作区） | `workspaces: []`，`noWorkspace.total = 0`，页面空态 |
| 零工作区、有任务 | `workspaces: []`，`noWorkspace.total = 任务总数` |
| 单工作区全挂 | 该工作区 `total = totals.total`，`noWorkspace.total = 0` |
| 某工作区无任务 | 桶存在且 `total = 0`，不报错 |
| 任务挂两个工作区 | 两个桶各 +1，`sum > totals.total` |
| 已删关联 | 该任务回落到 `noWorkspace` |
| 已删工作区（关联仍在） | 行不出现，任务回落 `noWorkspace` |
| 重启任务（status=3） | 计入 `total`，不计 `open/done/overdue` |
| 与列表一致 | 桶 `total` == `tasks.list {workspaceIds}` 的 `total`；`noWorkspace.total` == `tasks.list {noWorkspace:true}` 的 `total` |

## 8. 首期与扩展

首期落地：工作区排行（Top N）+ 未关联工作区 + 跳转 + 区块开关。

扩展候选（不在本期）：

- 工作区「逾期率 / 平均难度 / 已接取占比」列，需扩展桶字段；
- 工作区趋势：按 `created_at`/`done_date` 统计范围内事件，与存量排行分卡片呈现；
- 「长期无活动且仍有开启任务」的工作区清单，需要活动时间口径（复用 `tasks.statsReport` 的 `today` 与时间线设计）；
- 工作区覆盖率 KPI（已归属任务占比），可加在 KPI 卡而非排行卡。
