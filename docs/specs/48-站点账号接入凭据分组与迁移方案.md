# 站点账号接入凭据分组（直接切换版，v2）

- 状态：**已拍板，待实现**
- 目标宿主：0.6.7+
- 涉及：`wb-addon-vault` 0.2.x、`wb-addon-sites` 1.11.0
- 更新：2026-11-13

## 0. v2 变更摘要

v1 假设站点里已有真实凭据、必须做可重入迁移与回滚。用户确认：**站点数据目前都是模拟数据，
没有真实凭据，不需要迁移**。因此 v2 删除迁移工具、`site_vault_migration` 进度表、legacy
快照与回滚章节，改为**直接切换**：sites 不再自己加密，账号敏感字段从第一次写入起就只进 vault。

同时记录了三条拍板结论：

| 编号 | 结论 | 来源 |
| --- | --- | --- |
| S1 | 分组粒度＝**一类凭据一组**；同一站点的账号视为一类，默认每站一组 | 用户 2026-11-13 |
| S2 | **做** plugin 写接口（`vault.pluginSecretUpsert`），只允许写自己 subject 已绑定的组 | 用户 2026-11-13 |
| S3 | **不做迁移**：站点是模拟数据，直接切换；不写迁移工具、回滚、legacy 快照 | 用户 2026-11-13 |

## 1. 要解决的问题

当前仓库里有两套保险箱：

- `sites.vault.*`：`packages/addons/sites/lib/domain/vault.js` 自己维护 salt/verifier，
  密钥只在模块内存，账号密码/手机号/证件号内联加密进 `site_account`；
- `vault` 域：`packages/addons/vault`，独立口令、分组、对象绑定、云同步。

后果是用户要记两个口令、两套锁定状态、两套解锁提示；agent 的可见性规则也要学两遍。
本方案把站点账号的敏感字段整体交给 vault，sites 只保留业务字段与到凭据的引用。

## 2. 目标与非目标

**目标**

1. `site_account` 不再存储任何密文与密钥材料，也不再有自己的口令校验值；
2. 站点账号的密码/手机号/证件号写入即进 vault，按「站点 = 一类凭据 = 一个组」组织；
3. 列表只回掩码与 `hasPassword/hasPhone/hasIdentity`；界面显形走 vault 的 ui 门禁；
4. sites 不依赖 vault 的内部表，只通过 `vault.*` action 调用；
5. 未安装 vault 时，站点账号仍可保存非敏感字段，但敏感字段拒绝写入并给出明确错误。

**非目标（v2 明确不做）**

- 不做 `sites.vault.*` 到 vault 的密文搬迁：没有真实数据可搬；
- 不做回滚工具、legacy 快照、`site_vault_migration` 表；
- 不改 vault 的备份口径（密文仍不进出备份），也不在本期做「保险箱加密导出」；
- 不把 sites 的建表/删表搬进 vault，两个域各自持有自己的数据。

## 3. 目标数据模型

### 3.1 分组：一类凭据一组

按 S1，分组表达「一类凭据」，不是「一个账号一组」。站点账号这一类默认一个站点一个组：

```text
vault_group
  name = "站点账号 · <站点名>"            # 展示名，允许重名时自动加序号
  meta = { "subjectType": "site", "siteId": "sit_xxx" }
```

- 组由 sites 在**首次给该站点写凭据**时经 `vault.groupCreate` 创建？不需要：组是 ui 才能建的，
  但 plugin 需要能自动建组才能完成写入。因此本期给 `vault.pluginSecretUpsert` 增加
  「绑定不存在则拒绝」，组的创建由**界面上的一次性动作**完成（见 6.2），或由用户先建组再绑。
  实现上更简单：sites 页面加载时若检测到 `vault.bindingsOf("site", siteId)` 为空，提示
  「为本站点创建凭据组关联」，一次 `vault.groupCreate` + `vault.bind`（均为 ui）。

> 取舍：不让 plugin 隐式建组，避免 agent 通过插件在 vault 里制造任意组；组与绑定是
> 用户可见的授权对象，必须由 ui 产生。

### 3.2 凭据：一个字段一条 secret

```text
vault_secret
  name  = "site.<siteId>.<accountId>.<field>"   # field ∈ password|phone|identity_card
  kind  = "site-account"
  group_id = 该站点的组
  meta  = { "siteId", "accountId", "field" }
```

一条 secret 只装一个字段，便于单独显形、单独删除，也不会把整份账号资料塞进一个密文。
`name` 在同一组内唯一，`pluginSecretUpsert` 按 `(group_id, name)` 幂等 upsert。

### 3.3 sites 侧保留什么

`site_account` 保留：`id, site_id, account_key, label, note, status, last_used_at,
created_at, updated_at, deleted_at, rev` 等业务字段；**删除** `password / phone_number /
identity_card / salt / verifier`。

`packages/addons/sites/lib/domain/vault.js` 删除；`sites.vault.*` 六个 action 下线。

## 4. 读写路径

### 4.1 写（create / update）

```text
sites.accounts.create(ui)
  → 写 site_account 非敏感列
  → vault.groupList/bindingsOf 找到本站点的组（无绑定则报「请先建立凭据组关联」）
  → 对每个非空敏感字段：
      vault.pluginSecretUpsert({
        subjectType: "site", subjectId: siteId, groupId,
        name: "site.<siteId>.<accountId>.password",
        kind: "site-account",
        secret: "…", meta: { siteId, accountId, field: "password" }
      })
```

- `update` 同理；字段传空字符串表示删除该条 secret（`pluginSecretDelete`）；
- 任一敏感字段写入失败 → 回滚刚插入的 `site_account` 行（硬删）并返回错误，避免“半条账号”；
- 未装 vault / vault 未初始化 → 敏感字段一律拒绝，提示先安装并初始化保险箱。

### 4.2 读（list / get）

- `sites.accounts.list`：查 `vault.subjectSecrets`（一次取该站点所有 secret，按 meta.accountId
  聚合）得到每个账号的 `hasPassword/hasPhone/hasIdentity`；对外仍只回掩码字段；
- `sites.accounts.get`：
  - origin=agent：只回掩码与 has 标记；
  - origin=ui：额外回 `secretIds: { password: "sec_x", ... }`，**不回明文**；
- 明文显形：客户端拿 `secretIds[field]` 调 `vault.secretReveal`（ui 门禁、按 reveal_policy
  可能要求口令）。sites 不再提供 `accounts.reveal`。

### 4.3 删除

软删 `site_account`，并对三类 secret 调 `vault.pluginSecretDelete`；secret 不存在视为成功
（幂等）。

## 5. vault plugin 写接口

新增两个 action，origin 仅 `plugin`：

| action | 参数 | 规则 |
| --- | --- | --- |
| `vault.pluginSecretUpsert` | `subjectType, subjectId, name, kind, secret, meta?, groupId?` | `(subjectType, subjectId)` 必须已有绑定；`groupId` 必须在绑定集合内；按 `(group_id, name)` 幂等 upsert；返回 `{ id, created }` |
| `vault.pluginSecretDelete` | `subjectType, subjectId, name` | 同上校验绑定；软删；不存在返回 `{ ok: true, removed: false }` |

安全约束：

- 只能写自己 subject 已绑定的组，不能借 `groupId` 越权写别的组；
- `name` 强制前缀 `site.` 且含三段（本期只服务 sites，未来按 subjectType 放宽）；
- `meta` 复用现有敏感键拒绝规则，不允许塞 `password/token/…`；
- 审计只记 `id/name/subjectType/subjectId`，不记 secret；
- 不提供 plugin 读明文接口：读取仍走 ui 的 `secretReveal`，或业务方用 `lease`（purpose 明确）。

`vault.subjectSecrets` 扩展返回 `meta`（非敏感）与 `groupId`，供 sites 聚合字段。

## 6. 界面

### 6.1 保险箱状态条

sites 账号页顶部状态条改调 `vault.status`（字段映射：`enabled=initialized`、
`unlocked=!locked`、`idleMinutes=idleTimeoutSec/60`），初始化/解锁/锁定调
`vault.setup` / `vault.unlock` / `vault.lock`（均为 ui）。

### 6.2 分组关联

站点详情页提供「凭据组」区：显示当前绑定（`vault.bindingsOf("site", siteId)`），
未绑定时提供「创建并关联本站点凭据组」按钮（`vault.groupCreate` + `vault.bind`）；
已绑定时可进入 vault 的 groups 视图管理成员。

### 6.3 账号弹窗

- 新建/编辑：敏感字段输入框与原来一致，只是提交后由后端转 vault；
- 列表的「显形」按钮改为按字段展示：点击后调 `vault.secretReveal`，拿到的明文只在弹层
  内短暂显示，关闭即丢；锁定状态下按钮禁用并提示先解锁；
- 不再有「解锁站点保险箱」概念，只提示保险箱锁定。

## 7. 同步、备份与版本

### 7.1 同步

- `site_account` 行照旧参与 sites 同步；
- secret 在 vault 域同步（`vault_secret` 已声明 row/lww-tombstone），因此同一用户在另一台
  设备能看到账号条目与掩码，解锁保险箱后也能显形；
- 跨设备未解锁时，站点账号的 has 标记仍可显示（来自同步下来的 secret 行元数据）。

### 7.2 备份

- sites 备份原本就不含 `site_account`（`packages/addons/sites/lib/infra/backup.js` 只导
  site/tag 关系），本期不扩大范围；
- vault 备份不导密文 → **站点账号密码不会出现在任何备份产物里**，在功能清单与界面上明示。

### 7.3 版本

- sites 1.10.x → 1.11.0（破坏性：`site_account` 删列、`sites.vault.*` 与
  `accounts.reveal` 下线）；
- vault 0.2.x 内新增 action，`minShell` 不变；
- 旧库升级：`ensureSchema` 中检测并 `ALTER TABLE site_account DROP COLUMN`（三列），
  失败则保留列但不再读写（SQLite 版本过旧时降级）。

## 10. 验收

1. 新装环境：建站点 → 关联组 → 建账号（含密码/手机/证件）→ 列表只有掩码与 has；
2. `sites.accounts.get`（agent）无明文、无 secretIds；ui 有 secretIds、无明文；
3. 界面显形调用 `vault.secretReveal`，锁定状态下被拒并提示解锁；
4. 未装 vault 时建账号：非敏感字段成功、带敏感字段的请求整体失败并提示；
5. 删除账号后 `vault.subjectSecrets` 不再返回该账号的字段；
6. 删除站点/账号后不残留 secret（软删即可，30 天清理沿用 vault 规则）；
7. 同步：两台设备各自拉到账号与 has 标记；一台改口令后另一台解锁给提示（沿用 LWW）。

## 11. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 删列在旧 SQLite 失败 | 升级中断 | `try/catch` 降级为“保留列不读写”，记录日志 |
| plugin 写接口扩大攻击面 | 插件可写自身授权组 | 绑定校验 + 组不隐式创建 + 审计；不提供 plugin 读明文 |
| 无迁移导致旧账号密码丢失 | 模拟数据可接受 | 发布说明写清；旧密文列保留一版以便人工导出 |
| 未装 vault 时体验中断 | 无法保存敏感字段 | 明确报错文案 + 账号仍可建（仅非敏感） |
| 备份不含凭据 | 用户误以为有备份 | 功能清单与界面明示 |
