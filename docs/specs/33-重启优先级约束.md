# 重启优先级约束

反馈：01a1bebb-a94b-700e-93a6-4caace197d9c。

## 行为契约

- 重启需优先级 >0：source=2 创建时状态固定为进行中（0），priority 必须为 1–10。API 缺省 priority 回落 1；显式 0 报出重启专用错误，且不改变原任务状态。
- 重启弹窗优先继承原任务有效整数优先级，例如 P7。原任务因完成/关闭清零、或原值无效时，使用配置 form.defaultPriority，并限制为 1–10（无效配置回落 1）。
- 标题下提示“重启任务需要优先级 1–10，0 仅用于已完成/已关闭”。输入空值或 0 时立即出现表单错误、标注无效字段并禁用提交；提交函数仍校验，避免绕过按钮发起请求。空值不会被转换成 0 发送。
- 其他有限数值输入向下取整并 clamp 到 1–10；恢复有效值后即时移除错误。提交时明确校验整数范围。
- 正常状态变化保持原规则：进行中变为已完成/已关闭时优先级自动清零，不必手工传 0；已重启旧记录也保持 P0。
- tasks.create 的 priority/source/status 描述与任务域静态 capability 的字段/概念说明同步表达上述契约。通过 actions.help 与 capabilities.get 查看；不新增或声称存在 tasks.capabilities action。

## 模块与兼容

- 服务端优先级函数抽入 task-priority.js；tasks.js 继续导出 priorityForStatus，调用方无须更改。
- 客户端 CreateModal 抽入 create-modal.cjs，入口注入现有 React、日期、任务树及标签工具；插件注册与导出保持兼容。
- 两个冻结大文件行数只降不增，预算同步降低；服务端优先级逻辑与客户端表单拆分分别提交，便于独立审查与回退。
