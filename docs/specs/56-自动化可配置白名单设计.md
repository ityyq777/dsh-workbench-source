# 56 · 自动化「允许调用的 action」改为用户可配置

> 状态：设计草案（2026-11-21），待评审后实施。
> 目标版本：automation `0.3.0`；宿主不变。
> 关联：[02-ActionSchema与页面数据](../AGENTS规范/02-ActionSchema与页面数据.md)、
> [20-配置表与配置页设计](./20-配置表与配置页设计.md)、
> [49-自动化插件UI设计](./49-自动化插件UI设计.md)、[15-数据备份](./15-数据备份.md)。

## 0. 一句话结论

把 `packages/addons/automation/lib/domain/rules.js:5-11` 的 `ALLOWED_ACTIONS` 常量改为
`automation_meta` 里 `config.allowedActions`（**默认空数组**）；设置页从宿主 `actions.list`
拉候选、多选保存；`DENIED` 正则（`rules.js:12`）保持为**不可配置的硬底线**；创建/更新与
执行两处都校验。

## 1. 现状与问题

| 位置 | 现状 |
| --- | --- |
| `packages/addons/automation/lib/domain/rules.js:5-11` | 允许清单是 5 个 action 的常量 |
| `packages/addons/automation/lib/domain/rules.js:12` | `DENIED = /^(vault|automation|audit)\.\|\.(delete\|backup)/i` |
| `packages/addons/automation/lib/domain/rules.js:126-136` | 仅在 `createRule`/`updateRule` 时校验 |
| `packages/addons/automation/lib/domain/rules.js:262` | 执行时直接 `host.call`，不复查 |
| `packages/addons/automation/client/views/stats.cjs:6` | 「不允许调用」是前端硬编码副本 |
| `packages/addons/automation/client/ui/copy.cjs:138` | 文案写死「共 5 个 action」 |

问题：

1. **不给用户授权入口**：想接一个新 action（如 `mail.messageSend`）必须改代码、发版、重装。
2. **默认过大**：一装好就允许 `message.send`（对外发消息）、`connector.sourceRun`，不符合最小授权。
3. **两份白名单**：`stats.cjs:6` 与 `rules.js:12` 各写一份，改一处必漂移。
4. **执行不复查**：规则建好后即使配置收紧也照跑，白名单语义只覆盖“创建那一刻”。

## 2. 目标与非目标

**目标**

1. 允许清单由用户在设置页自由勾选，默认 `[]`——不勾就不允许任何 action。
2. 候选来自宿主真实注册的 action，不再维护第二份硬编码列表。
3. `vault.*` / `automation.*` / `audit.*` / `*.delete` / `*.backup` 永远不可开启（含手动输入）。
4. 概览页、规则编辑器、规则列表都实时反映当前配置；失效规则有可见警示。
5. 配置收紧后老规则立即停跑（记 `skipped`，不静默调用）。

**非目标**

- 不做「每条规则单独授权」（本期是全局一份清单，后续需要再加）。
- 不做任意代码/脚本执行。
- 不改触发方式、模板、条件、限频语义。

## 3. 数据模型

沿用现有 `automation_meta` 的 `config` 键（`rules.js:151-160`），只加一个字段：

```json
{
  "maxRules": 50,
  "perHour": 60,
  "allowedActions": ["tasks.create", "tags.create"]
}
```

约束：

| 项 | 规则 |
| --- | --- |
| 类型 | `string[]`，元素为 `<namespace>.<action>` |
| 默认 | `[]`（键不存在时视为空） |
| 上限 | 100 项 |
| 单项长度 | ≤ 120，字符集同 `SEGMENT`（`rules.js:14`） |
| 去重/排序 | 保存时去重并按字典序排序，保证幂等 |
| 是否要求已注册 | 不要求。允许为“尚未安装的插件”预先配置；执行时宿主会报错并记 `error` |
| 硬底线 | 命中 `DENIED` 的项一律拒绝，任何入口都无法写入 |
| 归属 | **本机配置**：不参与备份导出，也不参与云同步（沿用 `docs/specs/20` 的结论） |

## 4. 后端设计

### 4.1 新增 `lib/domain/whitelist.js`

把白名单逻辑从 `rules.js` 抽出来，避免 `rules.js` 继续膨胀（当前 360 行）：

```js
export const DENIED = /^(vault|automation|audit)\.|\.(delete|backup)/i;
export function isDenied(name) {...}
export function normalizeAllowedList(input, { limit = 100, strict = true }) {...}
// strict=false：静默剔除非法/被拒项（初始化、迁移用）；strict=true：抛 400（configSet 用）
export function assertAllowed(name, list) {...}
// DENIED 优先：抛「该 action 不允许被自动化调用」；不在 list：抛「该 action 未在设置中启用」
export function deniedPatterns() => ["vault.*", "automation.*", "audit.*", "*.delete", "*.backup"]
```

`deniedPatterns()` 是给 UI 的展示文本由后端下发，替代 `stats.cjs:6` 的副本。

### 4.2 action 变更

| action | 变化 |
| --- | --- |
| `automation.configSet` | 入参加 `allowedActions: {type:"array", items:{type:"string"}}`；描述改为「自动化配置：限流与允许调用的 action」；仍 `agentEnabled:false`、仅 `ui` |
| `automation.configGet` | 返回体自带 `allowedActions`（`engine.config()` 已包含） |
| `automation.actionOptions` | 返回 `{actions: config().allowedActions, denied: deniedPatterns(), triggers}`；规则编辑器与概览页继续复用 |
| `automation.actionCatalog`（新） | 候选清单：`api.call("actions.list", {})` → 过滤 `DENIED` 与 `automation.*` → `[{name, domainId, description}]`；只读、允许 agent；`actions.list` 抛错时返回 `{items: [], error}`，不 500 |

注意 schema 契约：`configSet` 声明了 `allowedActions` 就必须真读真写（`docs/AGENTS规范/02`），
`engine.saveConfig` 内用 `normalizeAllowedList(..., {strict:true})`。

### 4.3 校验链

```
createRule/updateRule → normalizeAction(name)
    ├─ isDenied → 400「该 action 不允许被自动化调用」
    ├─ 不在 config.allowedActions → 400「该 action 未在设置中启用：xxx」
    └─ 通过 → 落库
execute(rule) 前再跑一次同样的判断
    └─ 失败 → record(skipped, "action 未启用：xxx")，定时规则重算 next_run_at
```

### 4.4 默认与迁移

- 新装 / 老库无 `allowedActions` 键：一律按 `[]`。
- **不做静默继承**旧 5 个——那等于又一次替用户授权。
- 为减轻升级冲击：设置页顶部在检测到「有规则引用了未启用的 action」时显示提示条，
  并提供「从现有规则导入」按钮：取所有规则 `action_name` 去重、剔除 `DENIED`，
  **预填到勾选状态但不自动保存**，用户点保存才生效。
- 概览页同步显示 `WARN` 条与条数。

## 5. 前端设计

### 5.1 设置页新增「允许调用的 action」卡

位置：限流卡之后、运行约束之前。抽成 `client/views/action-picker.cjs`，设置页只做容器。

- 顶部：搜索框（匹配 name / domainId / description）、已选计数、`清空` 按钮。
- 列表：按 `domainId` 分组，组内 checkbox；已选项置顶或高亮；每行显示 `name` 与描述。
- 被 `DENIED` 命中的 action **不出现在候选里**，底部用一句说明「vault / automation / audit
  与删除、备份类 action 永远不可启用」。
- 手动添加：搜索无结果时给输入框（仅接受 `namespace.action` 且非 `DENIED`），
  用于候选拉取失败或插件未装时预留。
- 保存：仅 dirty 可点，调用 `automation.configSet({allowedActions})`；成功后刷新
  `configGet`、`actionOptions`。
- 空态：说明默认不授权、规则无法创建，给出「从现有规则导入」入口。
- 错误态：`actionCatalog` 失败时展示原文 + 保留手动添加。

### 5.2 概览页

- 「允许调用」chips 继续取 `actionOptions.actions`；为空时渲染空态：
  「尚未启用任何 action」+「去设置」按钮。
- 「不允许调用」chips 改为取 `actionOptions.denied`，删除 `stats.cjs:6` 的常量。
- 有失效规则时在 KPI 下加警告条：「N 条规则的 action 已不在允许列表，运行会被跳过」。

### 5.3 规则编辑器

- 下拉选项 = `actionOptions.actions`；为空时展示引导文案并禁用保存。
- 编辑老规则且其 action 未被启用：下拉保留该值并标注「未启用」，保存时前端先拦。

### 5.4 规则列表

- 行内 action 若不在当前允许列表，追加 warn 级 pill「未启用」；不影响其它列。

## 7. 备份与同步

- `allowedActions` 与 `maxRules`/`perHour` 同属本机配置：不导出、不同步。
- 导入备份里的规则后，若其 action 未启用：列表打「未启用」标记，运行记 `skipped`；
  用户可点「从现有规则导入」重新授权。这与 `docs/specs/20` 的配置定位一致。

## 8. 测试

`packages/addons/automation/test/automation.test.mjs`

1. 默认 `config.allowedActions === []`，`createRule({actionName:"tasks.create"})` 抛「未在设置中启用」。
2. `saveConfig({allowedActions:["tasks.create"]})` 后可建、可跑，`host.call` 收到调用。
3. `saveConfig` 传入 `vault.itemGet` / `tasks.delete` → 400。
4. 传入重复项 → 去重；传入非数组/超长 → 400。
5. 建规则后把清单清空，`runRule` 返回 `{skipped:true}` 且 `automation_run.status="skipped"`。
6. `actionOptions` 与 `configGet` 返回一致；`actionCatalog` 不含 `automation.*` 与 `DENIED` 项。
7. `actionCatalog` 在 `actions.list` 抛错时返回 `{items:[], error}`。

8. 设置页空态、搜索过滤、勾选后保存参数正确；规则编辑器无 action 时禁用保存。
