# 54 弹幕插件设计（danmaku 0.1.0）

> 状态：设计稿 v2，待确认后开发。
> 目标包：`dsh-workbench-danmaku`，域 `wb-addon-danmaku`，action 前缀 `danmaku.*`，前端前缀 `wbdm`。
> v2 依据三条结论修订：①覆盖**整个 DSH 界面**，不局限工作台业务页；②桌面透明置顶窗**同一版做完**，
> 不分期；③**不做快捷发送坞**，改成像标签插件一样自己添加/管理一组弹幕，循环轮播。

## 1. 目标与边界

**产品形态**：一份「弹幕清单」，用户在插件页里增删改、启停、排序；播放器按配置的节奏从清单里取一条，
从屏幕右侧飘到左侧，循环往复。同一份清单同时驱动两个显示端：

- **界面内**：覆盖整个 DSH 窗口（会话、设置、工作台业务页、命令面板背后的所有页面）；
- **桌面上**：独立透明置顶窗，浮在所有应用之上，鼠标完全穿透。

典型用法：把「喝水」「看远处 20 秒」「记得提交」「先跑测试再提交」写成弹幕，工作时在屏幕上方循环飘过；
桌面端让它在写代码、看浏览器时也能看到。

**不做**

- 不做聊天/回复/点赞，不做未读与通知中心（要留痕用 message 插件）；
- 不做快捷发送坞、不做输入框旁的发送按钮（v1 明确去掉）；
- 不做弹幕互动（点选、暂停单条、发送者头像）；
- 不做云端同步与多设备（`sync: { tables: [] }`）；
- 0.1.0 只验证 macOS + DSH 桌面端；Windows/Linux 的 helper 代码保持可运行，但不作为验收项。

## 2. 调研结论（决定了方案形状）

### 2.1 层叠：宿主浮层座位 z20，压不住工作台业务页

| 层 | 实现 | z-index |
| --- | --- | --- |
| 宿主模态框 / 命令面板 / 菜单 | `dsh-client-ui-*` | 900 / 1000 / 1100 / 1200 / 1250 |
| 工作台沉浸页 `.wb-immersive` | `packages/shell/client` | 700 |
| `shell.overlay` 插槽 | `dsh-client-ui-layout` `.PIRFFq_overlayLayer` | **20** |
| dsh-pet 桌宠 | `shell.overlay` 内的 `.dsh-pet-root` | 40 |

`.PIRFFq_overlayLayer{position:absolute;inset:0;z-index:20;pointer-events:none}`；AppFrame
（`.PIRFFq_frame`）与 `.PIRFFq_centerCol` / `.PIRFFq_mainPanel` 都没有 `transform/filter/isolation`
或 z-index，所以 700 与 20 在同一个根层叠上下文里直接比较：**只挂 `shell.overlay` 的弹幕，一进工作台
任何业务页就被整页盖住**。要"整个 DSH 页面"，必须挂到 `document.body`。

### 2.2 桌面：插件宿主没有建窗权限，必须独立 Electron helper

DSH 桌面端（`app.asar/lib/main.js`，`@deepseek-ai/dsh-desktop` 0.2.2-rc.5）用
`spawn(node, ["--expose-internals", node_modules/@deepseek-ai/dsh-desktop-host/lib/index.js, ...])`
拉起 host 子进程，并注入 `ELECTRON_RUN_AS_NODE=1` 与 `DSH_DESKTOP_NODE_EXECUTABLE`（桌面 App 自带的
Electron 可执行文件）。**插件宿主是纯 Node 进程**，`require('electron')` 只返回可执行文件路径字符串，
拿不到 `BrowserWindow`；也没办法让宿主主进程代替插件建窗。

所以"整个桌面"只有一条路：像 dsh-pet 一样，自带一个 Electron helper 子进程：

- helper 是一次性 Electron 应用（`runtime/electron-helper/`），用干净的 Electron 运行时启动；
- **运行时优先复用 `$DSH_HOME/electron`**：本机已有 43.3.0（`~/.dsh/electron/Electron.app/Contents/MacOS/Electron`，
  295MB，dsh-pet 下载），直接以只读方式拉起，不复制、不改写；不存在时才用 `@electron/get` 落盘到
  `$DSH_HOME/danmaku-electron`；
- helper 的窗口参数（dsh-pet 已验证过的组合）：
  `transparent:true, frame:false, hasShadow:false, focusable:false, skipTaskbar:true, show:false`，
  再 `setAlwaysOnTop(true,'screen-saver')`、`setVisibleOnAllWorkspaces(true,{visibleOnFullScreen:true})`、
  `setIgnoreMouseEvents(true,{forward:true})`、`showInactive()`；macOS 调 `app.dock.hide()`；
- 宿主与 helper 走 **stdin/stdout 行协议**，每行一个 JSON；helper 监视宿主 pid，宿主退出/崩溃即自退。

### 2.3 dsh-pet 的显示端抽象值得直接抄

```ts
PET_DISPLAYS = ['web', 'desktop', 'both', 'none']
isWebVisible = web | both
isDesktopVisible = desktop | both
```

一套内容、两个渲染端、一个配置决定谁显示。弹幕用同样的四值（本文叫 `surface`），网页端和 helper 端
共用同一个播放协议。

### 2.4 主题 token 的边界

`--wb-*` 只在 `.wb-root` 作用域里定义（`packages/shell/client/styles.cjs:167`）。body 层和 helper 都不在
`.wb-root` 里，必须从全局 `--dsw-alias-*` 派生局部 token：

```
--dsw-alias-bg-base / bg-layer-1 / bg-layer-2
--dsw-alias-border-l2 / border-l3
--dsw-alias-label-primary / label-secondary / label-primary-inverted
--dsw-alias-brand-primary
--dsw-alias-state-success-primary / state-warn-primary / state-error-primary
```

## 3. 显示端设计

### 3.1 `surface` 四值

| 值 | 含义 |
| --- | --- |
| `dsh`（默认） | 只在 DSH 窗口内飘（body 层） |
| `desktop` | 只在桌面透明窗里飘 |
| `both` | 两边同时飘 |
| `none` | 全关（保留清单与配置） |

`desktop`/`both` 只在桌面端可用：DSH 以 `dsh web` 跑在浏览器里时，host 检测不到桌面运行时，
配置页把两项置灰并提示「桌面弹幕仅 DSH 桌面端可用」。

### 3.2 界面内：body 级固定层（z780）

```
document.body
└─ div.wbdm-layer                 position:fixed; inset:0; z-index:780; pointer-events:none;
   │                              -webkit-app-region:no-drag;
   │                              contain:layout style paint;
   ├─ div.wbdm-stage              泳道舞台（band 区域内 overflow:hidden）
   └─ div.wbdm-chip × N           每条弹幕一个 span，absolute + translate3d
```

**为什么 780**：高于工作台 700（覆盖业务页），低于宿主第一个模态层 900（弹窗、命令面板、确认框始终
在弹幕之上，可读、可点）。700→780→900 之间留出余量，宿主将来插层也不容易撞。

**为什么不挂 `shell.overlay`**：z20 被工作台整页盖住，而工作台是本插件最常见的界面；"开工作台就消失"
不可接受。配置保留 `layer: 'body' | 'overlay'` 作为兼容逃生口（`overlay` 完全符合宿主约定，但只在
非工作台页面可见），默认 `body`。

**不挡点击、不挡拖拽**：

| 风险 | 处理 |
| --- | --- |
| 挡住底层按钮/输入 | 层根 `pointer-events:none`，层内没有任何可交互元素（v1 无悬浮坞），全层点击穿透 |
| macOS 标题栏拖拽死区 | 全层 `pointer-events:none` + `-webkit-app-region:no-drag`；弹幕带默认从窗口高度 15% 起，物理上不覆盖 48px 标题栏；验收含"全宽拖拽"实测 |
| RTL / 滚动条 | `direction:ltr`、`html` 横向不溢出（层 `overflow:hidden`） |
| 遮住宿主弹窗 | 780 < 900，弹窗天然在上层；弹幕不抢焦点（层内无可聚焦元素） |

**死区兜底**：若 macOS 仍出现拖拽死区，配置切 `layer: 'overlay'` 退回 z20；或把层根缩到
`top:48px; bottom:0`，彻底不碰标题栏（配置 `avoidTitlebar`，默认 true 的等效行为）。

### 3.3 桌面上：透明置顶 helper 窗

- **每块显示器一个窗**（`desktopDisplays: 'all'`），或只在主屏（`'primary'`）；窗口铺满显示器
  `bounds`，透明背景，`type:'panel'`（macOS 不抢焦点、不进 Mission Control 堆叠）；
- 纯展示：整窗 `setIgnoreMouseEvents(true,{forward:true})`，鼠标事件穿到下面的应用；
  没有可点区域，所以不需要命中区域补偿；
- 置顶层级 `'screen-saver'` + `visibleOnFullScreen:true`，验证"全屏的浏览器/IDE 上也可见"；
- **托盘菜单**（macOS 菜单栏图标）是桌面端唯一的操作入口：`暂停/继续`、`打开 DSH`、
  `退出桌面弹幕`。托盘动作发给宿主，宿主改 `enabled` 再广播，保证两边状态一致；
- helper 生命周期：随 `surface` 变为 `desktop|both` 启动；`dsh|none` 停止；崩溃按 1s/2s/4s…最多 30s
  退避重启，连续 5 次失败标记 `error` 并在配置页显示原因与「重试」；宿主退出时 helper 自杀。

### 3.4 一个调度器，两个哑渲染器

**不在两个渲染端各跑一套调度**——那会出现网页和桌面不同步、以及改配置后节奏漂移。播放节奏只有一处：

```
宿主 lib/player.js（setInterval 链，按 intervalMs）
  ├─ 选下一条：enabled 清单 → 顺序或洗牌袋 → 分配泳道 lane = seq % lanes
  ├─ 生成 play 消息 {id, body, tone, lane, at, durationMs, fontSize, speed, opacity}
  ├─ 广播 SSE 事件 domain-event {domainId:'wb-addon-danmaku', event:'play', data}
  └─ 写入 helper stdin（同一份 JSON 一行）
```

- `at` 是宿主时钟的计划入场时刻，带 200ms 提前量；渲染器用 `at - Date.now()` 延迟入场，
  两边同一台机器，误差在几十毫秒内；
- 渲染器只做四件事：按 `lane` 算 `top`、测文本宽、起 WAAPI 动画、结束移除；
- 网页层隐藏/切后台时丢弃积压（`at` 超过 2s 的 play 直接跳过），恢复后不补播；
- 暂停/继续发 `control {paused}`：渲染器 `animation.pause()/play()`，不重建。

### 3.5 暂停语义

| 触发 | 范围 |
| --- | --- |
| `enabled=false` | 两端停播，当前动画平滑停住 |
| 网页 `document.hidden` | 只暂停网页层动画（不改变调度；桌面端照常） |
| `pauseOnInput` 且正在 `input/textarea/contenteditable` 里打字 | 只暂停网页层；停手 3 秒或移开焦点后继续，单纯点进输入框不暂停（桌面端照常） |
| 托盘「暂停」 | 等同 `enabled=false`，两端停 |
| 减少动效（`prefers-reduced-motion` 或 `motion:'static'`） | 两端改为右上角淡入淡出堆叠 4s，不横向滚动 |

## 4. 信息架构

插件在侧边栏注册一张卡，四个视图（全部全宽，遵守界面红线 1）：

| 视图 | 内容 |
| --- | --- |
| **弹幕库**（默认） | 顶部：总开关 + 新增表单（文本/语气/添加）；下方表格：文本（行内编辑）、语气、启用开关、顺序（上移/下移）、删除（二次确认）；右上「试播一条」 |
| **配置** | §6 全部配置；改一项立即 `configSet` 并回填权威值；底部显示桌面端状态（未启动/运行中/错误原因/重试） |
| **数据** | `data-view.cjs`，表 `danmaku`，只读浏览/导出 |
| **Action** | `action-schema-view.cjs`，`danmaku.actionSchema` 自注册 |

**没有悬浮坞、没有快捷发送**：发送=在「弹幕库」里新增一条；试播只用于当场看效果（不落库、不改变顺序）。
总开关放在库页顶部和配置页各一份（同一 `enabled`）。

交互与标签插件对齐：行内新增/编辑、乐观更新、失败回滚并 toast、删除二次确认、空态引导
（"还没有弹幕，先加一条"）。表格用共享 `client-common.cjs` 的按钮/字段/开关/空态，不另造一套。

## 5. 数据模型

### 5.1 表 `danmaku`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | `dm_` + 时间戳 + 随机 |
| `body` | TEXT NOT NULL | 单行正文，1–100 码点，控制字符已清洗 |
| `tone` | TEXT NOT NULL DEFAULT `'normal'` | `normal` / `accent` / `ok` / `warn` / `danger` |
| `enabled` | INTEGER NOT NULL DEFAULT 1 | 是否进轮播 |
| `card` | INTEGER NOT NULL DEFAULT 1 | 是否画卡片背景；0 = 纯文字（0.1.1 新增） |
| `font_size` / `speed` / `opacity` | INTEGER / INTEGER / REAL | 单条覆盖；NULL = 跟随全局（0.2.0） |
| `font_weight` / `font_family` | INTEGER / TEXT | 字重（400–700）与字体（空 = 系统，rounded/serif/mono） |
| `band` | TEXT | 泳道区域：空 = 跟随全局，full/upper/lower |
| `prefix` | TEXT | 可选前缀（emoji 等，≤8 字） |
| `chance` | INTEGER NOT NULL DEFAULT 1 | 出现权重 1–5，越大越常出现 |
| `sort_order` | INTEGER NOT NULL | 顺序，新增 = max+10 |
| `created_at` / `updated_at` | INTEGER NOT NULL | UTC 毫秒 |
| `deleted_at` | INTEGER NULL | 软删除 |
| `rev` | INTEGER NOT NULL DEFAULT 1 | 更新 +1 |

```sql
CREATE INDEX IF NOT EXISTS idx_danmaku_order ON danmaku(deleted_at, sort_order);
CREATE UNIQUE INDEX IF NOT EXISTS idx_danmaku_body
  ON danmaku(body) WHERE deleted_at IS NULL;
```

- `body` 唯一：重复添加不报错，返回已有记录 + `existing:true`（与 tags 一致）；
- **没有颜色/字体/坐标列**：视觉只由 `tone`、`card` 与全局配置决定（界面红线 3）；
- **没有 expires/保留期**：这是用户维护的清单，不是日志；软删后数据页仍可查，硬清理手动。

### 5.2 Action

| action | input | 说明 |
| --- | --- | --- |
| `danmaku.create` | `body`* (1–100)、`tone?`、`card?`、`fontSize?`、`speed?`、`opacity?`、`fontWeight?`、`fontFamily?`、`band?`、`prefix?`、`chance?` | 同一内容唯一；外观/动效/轮播参数均可逐条覆盖 |
| `danmaku.update` | `id`*、`body?`、`tone?`、`card?`、`enabled?`、`fontSize?`、`speed?`、`opacity?`、`fontWeight?`、`fontFamily?`、`band?`、`prefix?`、`chance?` | 只传要改的字段；文本唯一冲突会报错 |
| `danmaku.remove` | `id`* | 软删 |
| `danmaku.list` | — | 按 `sort_order` 返回全部（含 `card`、`enabled`） |
| `danmaku.reorder` | `ids`*（完整数组） | 事务内写 `sort_order = 10,20,30…` |
| `danmaku.preview` | `id?` 或 `text`+`tone?` | 立刻播一条，不落库、不改顺序；`enabled=false` 也播 |
| `danmaku.configGet` / `configSet` / `configReset` | `values?` | 白名单键，宽松回退默认 |
| `danmaku.desktop` | `op`*：`status` / `restart` / `stop` | 桌面端诊断与手动重试 |
| `danmaku.dataTables` / `dataQuery` | 共享视图协议 | 数据页 |
| `danmaku.actionSchema` | — | Action 页 |

**事件**（`emit` → `/workbench/api/events` 的 `domain-event`）：

| event | data | 客户端行为 |
| --- | --- | --- |
| `changed` | `{reason}` | 刷新库列表/配置 |
| `play` | `{id,body,tone,lane,at,durationMs,fontSize,speed,opacity,preview?}` | 起动画 |
| `control` | `{paused}` | 暂停/继续动画 |
| `desktop` | `{state,error?}` | 配置页状态刷新 |

### 5.3 轮播选择

- `order: 'shuffle'`（默认）：把启用项洗牌成一个袋，依次取，取完重洗；重洗时保证首条不等于上一条；
- `order: 'sequence'`：按 `sort_order` 循环；
- 只有一条时就是单条反复飘；
- 清单为空或全部禁用时不播放，配置页显示「清单为空」。

## 7. 渲染实现

### 7.1 网页层

- 单文件职责：`client/overlay/mount.cjs` 建层与订阅，`layer.cjs` 做舞台/泳道/动画，`style.cjs` 出样式；
- 测宽：`canvas.measureText`（`500 ${fontSize}px` + 继承字体栈），不触发布局；失败退回一次性
  `span.offsetWidth`；
- 动画：`el.animate([{transform:'translate3d(100vw,0,0)'},{transform:'translate3d(-'+w+'px,0,0)'}],
  {duration, easing:'linear'})`，`duration = (vw + textWidth + 24) / speed * 1000`；
- `translate3d` + `will-change:transform`，只跑合成层；动画 `onfinish` 即 `el.remove()`；
- 卸载时 `cancel()` 所有动画并移除层（HMR/卸载插件不残留）。

### 7.2 桌面 helper

- `main.js`：`app.whenReady()` 后按 `screen.getAllDisplays()` 建窗、建托盘、读 stdin、转发给各渲染器；
- `preload.cjs`：`contextBridge.exposeInMainWorld('danmaku', {onPlay(cb), onControl(cb), onConfig(cb)})`；
- `renderer/main.js`：与网页层同一套泳道/动画逻辑（独立实现，约 150 行），按自己屏的 `bounds.height`
  把 `band` 换算成像素，泳道超高时 `lane % lanes` 兜底；
- `renderer/style.css`：token 不依赖 DSH 主题时改用内置浅/深两套值？**不**——helper 读不到 DSH 主题
  token，改用**由宿主下发的主题快照**：宿主从 DSH 主题读取 `bg-layer-2/label-primary/border-l2/brand`
  等实际颜色值，随 `config` 消息下发；helper 只做 `color-mix`。主题切换时宿主重发。这样桌面端和
  DSH 深浅色同步，且不写死色板。

### 7.3 性能预算

| 指标 | 目标 |
| --- | --- |
| 同屏弹幕 | ≤ lanes（默认 7） |
| 空闲 CPU | 网页层 0 rAF/0 定时器（只靠事件）；宿主调度器 1 个 1.4s 定时器 |
| helper | 每屏 1 窗，常驻 ~120MB；`backgroundThrottling:false` |
| 包体积 | `lib/client.js` ≤ 25KB（React 用宿主共享） |
| 内存 | 动画结束即移除节点；事件积压 >2s 丢弃 |

## 8. 视觉规范

一条弹幕 = 胶囊 chip（网页层与桌面端同一套值）：

```
padding: 4px 12px; border-radius: 999px; font: 500 15px/1.4 <DSH 字体>;
background: color-mix(in oklab, var(--dsw-alias-bg-layer-2) 90%, transparent);
border: 1px solid color-mix(in oklab, var(--dsw-alias-border-l2) 85%, transparent);
color: var(--dsw-alias-label-primary);
box-shadow: 0 2px 10px color-mix(in oklab, var(--dsw-alias-label-primary) 12%, transparent);
```

- 语气只染圆点与边框，不改文字色：`normal` 无点，`accent` 品牌色，`ok` 成功色，`warn` 警告色，
  `danger` 错误色——深浅色都可读；
- 桌面端为了浮在任意壁纸/窗口上，底色不透明度 90% + 上边一条 1px 高光（同样的 token mix），
  不开 `backdrop-filter`（合成开销）；
- 弹幕层 `aria-hidden="true"`、不可聚焦，纯装饰，不进 Tab 序列与读屏；
- 深浅色验收：同一条弹幕在两套主题下背景、文字、边框、语气点对比度达标。

## 9. 安全与降噪

| 项 | 规则 |
| --- | --- |
| XSS | 只渲染纯文本，React 转义；不解析 Markdown/HTML/链接 |
| 输入清洗 | 去 `\u0000-\u001f\u007f`，换行转空格，trim；按码点截断 100（不切 emoji） |
| 去重 | `body` 部分唯一索引：重复添加返回已有 id，不新增 |
| 刷屏 | 只有一份清单 + `intervalMs` 下限 500ms，天然限流；`preview` 10s 内最多 3 次 |
| 打扰 | 总开关、`surface:none`、托盘暂停、减少动效 |
| 隐私 | 不采集屏幕/剪贴板/前台应用；桌面窗只读用户自己写的清单 |

## 12. 验收清单

**界面内**

1. 会话页、设置页、工作台业务页、宿主命令面板打开时，弹幕都在正确层级（弹窗压在弹幕上）；

3. macOS 顶部标题栏全宽拖拽正常（`layer:body` 与 `overlay` 各测一次）；
4. 深浅色两套主题、字号缩放 100%/125% 下 chip 正常；
5. 输入框聚焦暂停、失焦继续；页面隐藏暂停、恢复不补播；`prefers-reduced-motion` 不横滚；
6. 连发/试播 20 条不卡顿、动画结束无残留 DOM。

**桌面端**

7. `surface:desktop` 时 DSH 窗口内不出现弹幕，桌面上出现；`both` 两边同时出现且内容同步；
8. 覆盖全屏浏览器/IDE 仍可见；DPI 不同的双屏位置正确；鼠标点击完全穿透；
9. 托盘暂停/继续/退出即时生效，与配置页状态一致；
10. 杀宿主进程，helper 5 秒内自退；杀 helper，宿主按退避重启；连续失败在配置页可读；
11. 首次在无 Electron 缓存的机器上能下载并启动，失败有明确错误与重试。

**交付**

12. `pnpm build && pnpm dist:shell`、桌面 CLI 安装到 desktop profile、`pnpm audit:profile` 退出码 0；
13. 重启后 `capabilities.list` 版本/`actionCount` 与源码一致。

## 14. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| body 层 macOS 拖拽死区 | 无法拖窗口 | 三层兜底（§3.2），验收 3 前置 |

| 多屏 DPI 缩放 | 文字模糊/错位 | 用 `screen.getAllDisplays()` 的 `bounds`（DIP）建窗，渲染器按 `devicePixelRatio` 无级缩放 |

## 11. 落地记录（0.1.0 / 0.1.1）

- 按本文实现，三处与草案不同：① `surface` 取值用 `dsh` 而不是 `ui`（更直观），默认 `dsh`，桌面层不默默下载 Electron；② 界面层落在 `body` 固定层 `z-index:780`，`layer` 保留 `body/overlay` 逃生口；③ `band` 默认 `full`（整屏铺开），`lanes 7`、`intervalMs 1400`、`shuffle`、`speed 150` 与本文一致。
- 桌面层复用 `~/.dsh/electron`（本机已有 43.3.0）；缺失才用 `@electron/get` 下载到 `~/.dsh/danmaku-electron`。
- 代码：`packages/addons/danmaku/`（`lib/{index,player,config}.js`、`lib/db`、`lib/actions/*`、`lib/desktop/*`、`runtime/electron-helper/*`、`client/{client.src.cjs,overlay/*,views/*}`）。
- 0.2.0：每条弹幕可单独设置字号、速度、不透明度、字重、字体、泳道区域、前缀与出现权重；库页点正文打开「弹幕详情」面板（内容/外观/动效/轮播四段，可保存并预览）。
- 0.1.1：每条弹幕新增 `card`（卡片背景）属性，关闭后只画带描边的文字；`lanes` 按可用高度均分（原先 `laneH` 上限 72px 导致整屏只剩上半部分有弹幕）；气泡去掉左侧圆点；输入暂停从「焦点进入输入框」改为「真的在打字」，停手 3 秒或移开焦点自动恢复。
