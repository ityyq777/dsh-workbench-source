# 54 弹幕插件设计（danmaku 0.1.0）

> 状态：设计稿，待确认后开发。
> 目标包：`dsh-workbench-danmaku`，域 `wb-addon-danmaku`，action 前缀 `danmaku.*`，前端前缀 `wbdm`。
> 一句话：在 DSH 界面之上铺一层不挡点击的弹幕，任何插件和 agent 都能发一条短句从右向左飘过。

## 1. 目标与边界

**要解决的**

1. 用户随时随地能发一条弹幕（右下角悬浮坞，或弹幕页输入），立刻从屏幕右侧飘过；
2. 其他插件、宿主事件、agent 能通过 `danmaku.send` 往同一层弹幕里丢短句（例如任务完成、构建失败）；
3. 弹幕内容留档、可回看、可撤回，有保留期，不无限膨胀；
4. 弹幕层永不拦截鼠标点击，不遮挡标题栏拖拽，不干扰输入。

**不做**

- 不做聊天：弹幕没有会话、没有回复、没有未读计数（要"留痕 + 回看"用 message 插件）；
- 不做屏幕录制/截屏/OCR，不读用户屏幕内容；
- 不做云端同步与跨设备（`sync: { tables: [] }`，本地库）；
- 0.1.0 不做「整个桌面」级弹幕（理由与成本见 §3.4，P2 单独立项）。

## 2. 调研结论（决定了方案形状）

### 2.1 DSH 宿主只有一个"全应用浮层座位"，而且很矮

| 层 | 实现 | z-index |
| --- | --- | --- |
| 宿主模态框 / 命令面板 / 菜单 | `dsh-client-ui-*` | 900 / 1000 / 1100 / 1200 / 1250 |
| 工作台沉浸页 `.wb-immersive`（我们自己的全屏业务页） | `packages/shell/client` | 700 |
| `shell.overlay` 插槽 | `dsh-client-ui-layout` `.PIRFFq_overlayLayer` | **20** |
| dsh-pet 桌宠 | `shell.overlay` 内 `.dsh-pet-root` | 40 |

`.PIRFFq_overlayLayer{position:absolute;inset:0;z-index:20;pointer-events:none}`，子元素默认恢复
`pointer-events:auto`。AppFrame（`.PIRFFq_frame`）自身没有 `transform/filter/isolation`，
`.PIRFFq_centerCol` / `.PIRFFq_mainPanel` 也没有 z-index，所以 700 和 20 在同一个根层叠上下文里
直接比较：**只挂 `shell.overlay` 的弹幕，一进工作台任何业务页就被整页盖住**。

### 2.2 dsh-pet 给出的两条成熟经验

- **显示端用四值枚举**：`PET_DISPLAYS = ['web','desktop','both','none']`，`isWebVisible = web|both`，
  `isDesktopVisible = desktop|both`。一套内容、两套渲染端，用配置决定谁显示——弹幕直接沿用这个抽象。
- **"整个桌面"必须另起 Electron 透明窗**：`runtime/electron-helper` 创建
  `transparent:true, frame:false, alwaysOnTop:true, skipTaskbar:true, hasShadow:false` 的
  BrowserWindow，`setVisibleOnAllWorkspaces(true,{visibleOnFullScreen:true})`，
  `setIgnoreMouseEvents(true,{forward:true})` 实现穿透；宿主与 helper 之间走 stdout/stdin +
  `dsh-pet-bridge:` 协议。首次使用经 `@electron/get` 下载与宿主同版本 Electron。
  这部分有重启退避、看门狗、多显示器、DPI 矫正，成本远高于界面内层。
- **dsh-pet 不走 `document.body`**：其注释记录 body 直接子级会命中 macOS 的 no-drag 规则、把标题栏
  拖成死区，因此宁可接受 z20 的天花板。我们这次要覆盖工作台业务页，必须越到 700 之上，所以
  要把它的顾虑当成**验收项**处理，而不是当成禁令（§3.2）。

### 2.3 主题 token 的边界

`--wb-*` 只在 `.wb-root` 作用域里定义（`packages/shell/client/styles.cjs:167`）。弹幕层在
`.wb-root` 之外，不能直接用 `--wb-*`，必须从全局 `--dsw-alias-*` 派生自己的局部 token：

```
--dsw-alias-bg-base / bg-layer-1 / bg-layer-2
--dsw-alias-border-l2 / l3
--dsw-alias-label-primary / label-secondary / label-primary-inverted
--dsw-alias-brand-primary
--dsw-alias-state-success-primary / state-warn-primary / state-error-primary
```

## 3. 显示层设计（本方案的核心）

### 3.1 显示端 `surface`

配置项 `surface` 四值，与 dsh-pet 对齐：

| 值 | 含义 | 0.1.0 |
| --- | --- | --- |
| `ui`（默认） | 只在 DSH 窗口内飘 | ✅ |
| `desktop` | 只在桌面透明置顶窗里飘 | P2 |
| `both` | 两边同时飘 | P2 |
| `none` | 全关（保留发送与留档） | ✅ |

### 3.2 界面内挂载：body 级固定层（推荐）

```
document.body
└─ div.wbdm-layer            position:fixed; inset:0; z-index:780;
   ├─ (pointer-events:none)  contain:layout style; -webkit-app-region:no-drag
   ├─ div.wbdm-lane × N      泳道容器
   └─ div.wbdm-dock          右下角悬浮坞（唯一 pointer-events:auto 的元素）
```

**为什么是 780**：高于工作台 700（覆盖业务页），低于宿主第一个模态层 900（弹窗、命令面板、
确认框始终压在弹幕之上，语义正确）。留出 700→780→900 的余量，也不用猜宿主未来会不会插层。

**为什么不用 `shell.overlay` 作主挂载**：z20 会被工作台业务页整页盖住，而工作台正是本插件的主
使用场景；把弹幕做成"一开工作台就消失"的功能没有意义。

**合规对照**：`shell.overlay` 是宿主给插件的官方座位，但它是**层叠座位**，不是**唯一合法座位**。
本方案越级到 780 的代价必须在验收里换回来（见 §3.3 与 §12）。

**备选（配置 `layer: 'body' | 'overlay'`）**：

- `overlay`：挂 `shell.overlay`（`ctx.slots.register`），行为 100% 符合宿主约定，但工作台业务页上
  不可见；给"只想在会话页看"的用户；
- `body`（默认）：本文方案。

如果宿主后续提高 overlay 层级或提供更高座位，默认值切回 `overlay`，其余代码不动。

### 3.3 不挡点击、不挡拖拽、不挡输入

| 风险 | 处理 |
| --- | --- |
| 挡住底层按钮 | 层根 `pointer-events:none`；只有悬浮坞与坞内面板 `pointer-events:auto`（面积 ≤ 200×44px） |
| macOS 标题栏拖拽死区 | 全层 `-webkit-app-region:no-drag` + `pointer-events:none`；弹幕带默认从 `top:15%` 起，物理上不覆盖 48px 标题栏；验收含"全宽拖拽"实测 |
| 输入时干扰阅读/抢焦点 | 层内没有任何可聚焦元素（坞按钮 `tabindex=-1`）；`pauseOnInput` 时监听 `focusin`，焦点在 `input/textarea/contenteditable` 上暂停滚动 |
| 遮住宿主弹窗 | 780 < 900，宿主弹窗天然在上；弹幕不拦截弹窗点击 |
| 全屏 / 沉浸 | 工作台沉浸页由本层覆盖；DSH 全屏时仍 `fixed`，无影响 |

**死区兜底**：若 macOS 实测出现拖拽死区（`pointer-events:none` 不生效的极端情况），配置切
`layer: 'overlay'` 即可退回 z20；另一条兜底是把层根再缩到 `top:48px; bottom:0`，彻底不碰标题栏。

### 3.4 整个桌面（P2，不在 0.1.0）

要做的话复用 dsh-pet 的形状，但**独立 helper**（不共享它的进程，避免两个插件互相拖垮）：

- `runtime/electron-helper/`：透明、无边框、置顶、跳过任务栏、全工作区可见，整层
  `setIgnoreMouseEvents(true,{forward:true})`（纯展示，不需要命中区域）；
- 宿主侧 `src/host/helper/`：spawn、重启退避、看门狗、多显示器/DPI、退出清理；
- 通信：stdin/stdout 行协议 + 本地端口回执，弹幕只下发 `{text,tone,speed}`，渲染复用同一套泳道代码；
- 成本：首次下载 Electron（100MB+），常驻一个 helper 进程（约 100–150MB 内存），需要开机自启与
  崩溃恢复。**必须用户显式开启，默认关闭**。

## 4. 信息架构

插件在侧边栏注册一张卡，四个视图（与 message/salary 一致，复用共享组件）：

| 视图 | id | 内容 |
| --- | --- | --- |
| 弹幕 | `wall` | 顶部发送框 + 快捷语气；最近 50 条列表（时间/来源/语气/正文，可撤回）；右上"全屏预览"开关（在弹幕页本地预览，不受其他页影响） |
| 配置 | `config` | §6 的全部配置项，改一项立即生效（`configSet` 返回权威值回填） |
| 数据 | `data` | `data-view.cjs`，表 `danmaku`，支持筛选/导出当前页 |
| Action | `actions` | `action-schema-view.cjs`，`danmaku.actionSchema` 自注册 |

**悬浮坞（dock）**：右下角 36px 圆钮，`opacity:.55`，hover 到 1；点击展开 320px 面板：
文本框（100 字计数，Enter 发送、Shift+Enter 换行）、语气三选（普通/强调/提醒）、暂停/继续、
"打开弹幕页"。`Esc` 关闭；配置可关掉坞（`dock: 'off'`）或挪到左下。

**不放在 `conversation.input.left`**：那个座位只存在于会话输入区，工作台页里没有；弹幕坞要做到
"任何页面都在"，只能自己挂。

## 5. 数据模型

### 5.1 表 `danmaku`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | `dm_` + 时间戳 + 随机 |
| `body` | TEXT NOT NULL | 单行正文，1–100 字，控制字符已清洗 |
| `kind` | TEXT NOT NULL DEFAULT `'note'` | `note` 人工 / `event` 事件 / `alert` 提醒 |
| `source` | TEXT NOT NULL DEFAULT `'user'` | `user` / `agent` / `plugin:<addonId>` / `system` |
| `tone` | TEXT NOT NULL DEFAULT `'normal'` | `normal` / `accent` / `ok` / `warn` / `danger` |
| `dedupe_key` | TEXT NULL | 去重键；部分唯一索引 |
| `meta` | TEXT NOT NULL DEFAULT `'{}'` | JSON：`{action?, ref?}`，给"从哪来"留线索 |
| `created_at` | INTEGER NOT NULL | UTC 毫秒 |
| `expires_at` | INTEGER NULL | 到点不再飘，列表仍可见；NULL 表示永久 |
| `deleted_at` | INTEGER NULL | 软删 |
| `rev` | INTEGER NOT NULL DEFAULT 1 | 更新 +1 |

```sql
CREATE INDEX IF NOT EXISTS idx_danmaku_created ON danmaku(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_danmaku_deleted ON danmaku(deleted_at);
CREATE UNIQUE INDEX IF NOT EXISTS idx_danmaku_dedupe
  ON danmaku(dedupe_key) WHERE dedupe_key IS NOT NULL;
```

**无颜色、无字体、无坐标列**：视觉一律由 `tone` + 全局配置决定（界面红线 3）。

### 5.2 Action（`agent` 可见的 schema 契约）

| action | input | 说明 |
| --- | --- | --- |
| `danmaku.send` | `text`* (1–100)、`kind?`、`tone?`、`source?`、`dedupeKey?`、`ttlMs?` (1000–600000) | 发一条；重复 `dedupeKey` 返回已有 id 且 `duplicate:true`；超频抛 `RATE_LIMITED` |
| `danmaku.list` | `limit?` (1–200，默认 50)、`before?`、`kind?`、`includeDeleted?` | 倒序分页 |
| `danmaku.remove` | `id`* | 软删（撤回） |
| `danmaku.clear` | `before?` | 软删全部或早于某时间 |
| `danmaku.stats` | `days?` (1–90，默认 7) | 按 kind/tone/日聚合 |
| `danmaku.configGet` / `configSet` / `configReset` | `values?` | 白名单键，宽松回退默认 |
| `danmaku.dataTables` / `dataQuery` | 共享视图协议 | 数据页 |
| `danmaku.actionSchema` | — | Action 页 |

实现细节：

- 所有写操作先校验 `text`：去控制字符、`\r?\n` → 空格、trim、按码点截断到 100；
- 限流：滑动 60 秒内最多 30 条（含 agent），超限 `RATE_LIMITED`；同秒内相同 `text` 视为重复；
- `source` 默认 `user`；agent 调用时不传则记 `agent`（按调用方识别不可靠，就按 action 入参默认）；
- 事件：写入成功后 `emit("posted", row)`，撤回 `emit("removed",{id})`，清空 `emit("cleared",{})`，
  配置变更 `emit("config",{values})`——客户端经 `/workbench/api/events` 的 `domain-event` 收到。

### 5.3 保留期

启动清一次 + 每小时最多清一次（`lastPruneAt` 内存节流）：硬删 `expires_at < now - 1d` 或
`deleted_at < now - retentionDays` 的行。保留期默认 7 天，1–30 可配。

## 6. 配置项（`config.danmaku.*`）

| id | 类型 | 默认 | 范围/枚举 | 说明 |
| --- | --- | --- | --- | --- |
| `enabled` | bool | true | — | 总开关 |
| `surface` | enum | `ui` | `ui/desktop/both/none` | 显示端 |
| `layer` | enum | `body` | `body/overlay` | 界面内挂载点（§3.2） |
| `band` | enum | `upper` | `top/upper/full` | 弹幕带：8–30% / 15–55% / 8–88% |
| `speed` | number | 150 | 60–400 | 像素/秒，恒定速度 |
| `fontSize` | number | 15 | 12–22 | px |
| `opacity` | number | 0.9 | 0.3–1 | 整体透明度 |
| `density` | number | 8 | 1–24 | 同屏最多条数 |
| `maxQueue` | number | 40 | 10–100 | 待发队列上限，超出丢最旧 |
| `pauseOnInput` | bool | true | — | 输入框聚焦时暂停 |
| `motion` | enum | `auto` | `auto/scroll/static` | auto 跟随系统减少动效 |
| `dock` | enum | `bottom-right` | `bottom-right/bottom-left/off` | 悬浮坞位置 |
| `retentionDays` | number | 7 | 1–30 | 保留期 |
| `allowSources` | multi | `user,agent,plugin` | 三选 | 哪些来源允许上屏（`system` 永远只留档） |

配置写在宿主 meta 表 `config.wb-addon-danmaku.<id>`，不新建配置表。

## 7. 渲染引擎

### 7.1 泳道与调度

```
laneHeight = fontSize * 1.6 + 10
lanes      = clamp(3, floor(bandHeight / laneHeight), 12)
lane.freeAt = 该泳道尾部完全离开屏幕的时间 + 24px 安全间距
入队时选 freeAt 最早且 <= now 的泳道；都不空闲则排队，density 满则丢最旧
```

### 7.2 动画

- Web Animations API：`el.animate([{transform:'translate3d(100vw,0,0)'},
  {transform:'translate3d(-<width>px,0,0)'}], {duration, easing:'linear'})`；
- 恒定像素速度：`duration = (viewportWidth + textWidth + 24) / speed * 1000`，长文本只占更久，不变慢；
- 测宽：`canvas.measureText`（字体 `500 ${fontSize}px <DSH 字体>`），不触发布局；失败退回
  `span.offsetWidth`（每次一次性，不循环读）；
- `will-change:transform` + `translate3d`，只跑合成层；
- 复用现有动画对象做 `pause()/play()`（输入暂停、页面隐藏、手动暂停），不重建；
- `prefers-reduced-motion: reduce` 或 `motion: 'static'`：不横向滚动，改为右上角淡入淡出堆叠 4s；
- `document.hidden` 暂停，恢复后继续（WAAPI 保 `currentTime`）；
- 卸载时 `cancel()` 全部动画并移除节点，避免 HMR/切页后残留。

### 7.3 性能预算

| 指标 | 目标 |
| --- | --- |
| 同屏弹幕 | ≤ 24（默认 8） |
| 空闲 CPU | < 2%（无弹幕时零 rAF/零定时器） |
| 单条 DOM | 1 个 `span`，无嵌套图标（语气用 `::before` 圆点） |
| 包体积 | `lib/client.js` 增量 ≤ 25KB（React 用宿主共享，不打包） |
| 内存 | 队列 ≤ 100、DOM ≤ 24，断开事件源即释放 |

## 8. 视觉规范

- 一条弹幕 = 胶囊 chip：`padding:4px 12px; border-radius:999px; font:500 15px/1.4 inherit`；
- 背景 `color-mix(in oklab, var(--dsw-alias-bg-layer-2) 88%, transparent)`；
  边框 `color-mix(in oklab, var(--dsw-alias-border-l2) 85%, transparent)`；
- 文字 `var(--dsw-alias-label-primary)`；
- 语气只染圆点与边框，不改文字色（保证深浅色可读）：`normal` 无点，`accent` 品牌色，
  `ok` 成功色，`warn` 警告色，`danger` 错误色；
- 阴影不写死黑色：`box-shadow: 0 2px 10px color-mix(in oklab, var(--dsw-alias-label-primary) 12%, transparent)`；
- 悬浮坞与面板复用同一批 token，面板背景 `var(--dsw-alias-bg-layer-1)` + `border-l2`；
- 深浅色验收：同一条弹幕在两套主题下背景、文字、边框、语气点都对比度达标；
- 不使用 `backdrop-filter`（合成开销大，且透明层叠在低端机上掉帧）。

## 9. 安全与降噪

| 项 | 规则 |
| --- | --- |
| XSS | 只渲染纯文本；React 转义；不解析 Markdown/HTML/链接 |
| 控制字符 | 去 `\u0000-\u001f\u007f`，换行转空格，trim |
| 长度 | 100 码点（按码点截断，不切 emoji） |
| 刷屏 | 60s 内 ≤ 30 条；队列上限；density 上限 |
| 重复 | `dedupeKey` 唯一索引；无 key 时同秒同文去重 |
| 打扰 | `enabled` 总开关、`allowSources` 来源过滤、`surface:none` 静默 |
| 隐私 | 不采集屏幕/剪贴板；`meta` 只存调用方给的 action/ref |

## 11. 与 agent / 其他插件的集成

- **agent**：能力清单里登记 `danmaku.send`，`description` 写明"短提示用弹幕；需要回看/未读用
  `message.send`；不要用它刷屏"。agent 通过 `actions.help` 看到 schema 即可调用；
- **其他插件**：任何插件里的 `api.call("danmaku.send", {...})` 都能发（跨域前缀路由已支持）；
  也允许直接 POST `/workbench/api/domains/wb-addon-danmaku/actions/danmaku.send`；
- **P1 事件订阅**：配置里加规则表（`domain.event → 模板`），客户端订阅 `domain-event` 后自动弹，
  例如 `tasks.task.completed → "✅ {title}"`。0.1.0 只留接口，不开放规则编辑。

## 12. 验收清单（必须逐条过）

1. 会话页、设置页、工作台业务页（`.wb-immersive`）三种页面都能看到弹幕；
2. 宿主命令面板/确认框打开时，弹幕在其下方、不遮挡；
3. 弹幕飘过时，底层按钮、输入框、滚动条照常可点可用；
4. macOS 顶部 48px 区域全宽拖拽窗口正常（`layer:body` 与 `overlay` 各测一次）；
5. 深浅色两套主题下 chip 背景/文字/边框/语气点正常；
6. 输入框聚焦暂停、失焦继续；页面隐藏暂停、回来继续；手动暂停/继续；
7. `prefers-reduced-motion` 下不横向滚动；
8. 连发 100 条：队列上限生效、不卡顿、无残留 DOM；
9. 服务重启/断线重连后事件源恢复，不重放历史弹幕；
10. `danmaku.send` 重复 key 返回 duplicate、超频返回 `RATE_LIMITED`；
11. 安装后 `capabilities.list` 版本、`actionCount` 与源码一致（`pnpm audit:profile` 退出码 0）。

## 14. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| body 层在 macOS 造成拖拽死区 | 无法拖窗口 | §3.3 三层兜底；验收第 4 条前置 |
| 宿主升级改了 700/900 层级 | 弹幕被盖或盖住弹窗 | z 值集中在一个常量 + 注释；升级后跑验收 1–2 |
| 其他插件也用 body 高层 | 互相覆盖 | 780 留余量；文档约定插件浮层 ≤800 |
| 动画在低端机掉帧 | 卡顿 | 密度上限、纯合成动画、隐藏即暂停、static 模式 |
| agent 误用弹幕刷屏 | 打扰 | 限流 + 队列 + `allowSources`，描述里写清边界 |
