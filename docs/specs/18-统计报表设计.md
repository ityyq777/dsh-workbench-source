# 18 · 统计报表设计（tasks / tags / sites）

> 状态：**已实施（2026-11-08）**，设计确认记录见 §14、实施记录见 §15。
> 影响包：`dsh-workbench-tasks` / `dsh-workbench-tags` / `dsh-workbench-sites`；宿主 `dsh-workbench` 不改。
> 目标版本：tasks **2.5.0**、tags **1.4.0**、sites **1.4.0**（均为 minor，新增视图与只读 action）。
> 关联文档：[03-UI设计](./03-UI设计.md)、[04-子插件体系](./04-子插件体系.md)、[插件功能清单](../插件功能清单.md)。

## 1. 背景与目标

### 1.1 现状

- 三个业务插件目前都只有 **1 个客户端视图**：任务记录、标签、站点。
- 宿主已经支持"一个插件多个视图"：视图数 > 1 时全页顶部自动出现 `wb-page-tabs`，路由形如
  `addon:<addonId>:<viewId>`（`packages/shell/client/client.js:794-822`），首页卡片标题取 domain
  标题、点击打开 `views[0]`（`client.js:734-738`）。
- 统计能力只有两个面向角标的轻量 action：
  - `tasks.stats`：7 个计数器（open/active/shutdown/done/restarted/overdue/today）+ `groupBy`（`packages/addons/tasks/lib/tasks.js:1058-1104`）；
  - `sites.stats`：`{total, tagged, nodes}`（`packages/addons/sites/lib/sites.js:545`）；
  - 标签插件没有任何统计 action。

### 1.2 目标

1. 三个模块各自向宿主注册**第二个视图**（统计报表页），宿主自动出 tab，不改宿主代码。
2. 每个模块只统计**自己拥有的数据**；跨模块只做只读聚合，且以能力探测为前提。
3. 每个统计页提供多维度：总量、结构分布、时间趋势、排行、健康度/明细。
4. 同步提供只读 `*.statsReport` action，agent 可直接拿到结构化统计与简短文本摘要。
5. 不引入图表库，全部自绘 SVG/CSS，跟随宿主主题与 zh/en。

### 1.3 非目标（一期）

- 不做独立统计站点、不做大屏模式、不做 iframe。
- 不做 CSV/PNG 导出、不做定时报表、不做跨模块联合报表。
- 不做图表点击钻取到列表（需要宿主新增导航 API，见 §14）。
- 不新增数据库表，只补索引。

## 2. 总体方案

### 2.1 视图注册

每个插件的客户端模块从 1 个视图扩为 2 个，**统计视图放在 `views[0]`，列表视图第二**；
首页卡片标题改用 domain 标题，不再依赖第一个视图标题：

```js
// packages/addons/tasks/client/client.src.cjs（tags/sites 同构）
host.registerAddon({
  id: "wb-addon-tasks",
  version: "2.5.0",
  views: [
    { id: "stats", title: { zh: "统计", en: "Stats" }, component: TasksStatsView },
    { id: "tasks", title: { zh: "任务记录", en: "Tasks" }, component: TasksView },
  ],
});
```

服务端 `registerDomain` 的 `views` 同步声明两项，供 `/workbench/api/domains`、文档与 agent 读取：

```js
views: [
  { id: "tasks", title: { zh: "任务记录", en: "Tasks" } },
  { id: "stats", title: { zh: "任务统计", en: "Task stats" } },
],
```

`package.json` 的 `wb.addon.views` 也补上 `"stats"`（客户端模块未加载时的兜底 tab）。

### 2.2 路由与交互

- 进入插件默认落在列表视图；点顶部「统计」tab 切到 `addon:wb-addon-tasks:stats`。
- 统计页**不重复大标题**，沿用宿主沉浸式顶栏；页内第一行是快捷范围、手选起止日期、刷新与数据时间。
- 快捷范围（近 7 天 / 近 30 天 / 近 90 天 / 近 1 年 / 全部）与手选起止日期互斥：
  选中预设会清空手选区间；手选日期只填一半或起始晚于终止时给出提示、不发请求，
  保留上一份结果；两端都有效后立即按闭区间 `[from, to]` 重新拉取。
- 一期不在列表页加"查看统计"按钮：宿主未暴露视图切换 API，tab 已是唯一入口；
  若后续需要，给宿主补 `__WB_HOST__.navigate(route)` 再接线（二期）。

### 2.3 数据通道

- 视图拿到的 props 仍是 `{ api, lang, addonId, t }`（`client.js:816`）。
- 每个统计页**只发 1 个请求**：`api.call("<module>.statsReport", { range })` 或
  `{ from, to }`（手选起止日期时），
  一次返回全部区块，避免十几个 action 串联与部分失败。
- 订阅既有 SSE 事件做防抖刷新：
  - tasks：`tasks-changed`、`task-nodes-changed`；
  - tags：`tags-changed`，外加 `tasks-changed`、`sites-changed`——任务与站点会直接写
    `tag_mapping`（`item_type` 分别为 `task` / `site`），但只广播自己的 `*-changed`，
    不会广播 `tags-changed`；
  - sites：`sites-changed`、`site-nodes-changed`、`tags-changed`（标签侧删除/解绑会影响覆盖率）。
- `api.subscribe(fn)` 是全局监听（`client.js:254-261`，不按 domain 过滤），统计页按
  `payload.domainId` 过滤或直接防抖重拉。
- 现有 `tasks.stats` / `sites.stats` 保持原样（角标、旧客户端、agent 兼容），
  报表走新 action，互不影响。

### 2.4 包内结构

```
packages/addons/<name>/client/
├── client.src.cjs      # 入口：COPY、图标、列表视图、registerAddon（改这里）
├── charts.cjs          # 新增：自绘 SVG 图表与统计页通用小组件
└── stats.cjs           # 新增：该模块的统计视图（数据拉取 + 区块编排）
```

esbuild 会把相对 `require("./charts.cjs")` 打进 `lib/client.js`，无需改构建脚本。
`charts.cjs` 在三个插件各存一份（约 200 行）：业务包发布时只带自己的 `lib/`，
跨包相对引用在 npm 安装后会失效；等第四个消费者出现再抽公共包。

### 2.5 兼容与版本

- 旧客户端（只有 1 个 view）连新服务端：正常，看不到统计 tab；新 action 不被调用。
- 新客户端连旧服务端：统计 tab 在，请求返回 404 → 页内错误态"统计服务未就绪，请升级插件"。
- 现有 action 签名、返回结构一律不改；只新增 `*.statsReport`（tags 另加轻量 `tags.stats`）。
- 三个插件的 `package.json.version`、`wb.addon.version`、`registerAddon.version`、
  `registerDomain.version` 四处必须一致（当前 tasks 的 domain 还是 2.4.1，顺手修正）。

## 3. 通用约定

### 3.1 时间范围

请求参数：

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `range` | `"7d"\|"30d"\|"90d"\|"365d"\|"all"` | `"30d"` | 快捷范围，与 from/to 二选一 |
| `from` | `YYYY-MM-DD` | — | 起始日（含），与 to 同时给 |
| `to` | `YYYY-MM-DD` | 今天 | 结束日（含） |
| `top` | number | 10 | 排行/明细条数，夹在 1–20 |

- 日期一律用**服务器本地时区**的自然日；SQLite 侧用
  `date(created_at/1000,'unixepoch','localtime')` 分桶，与前端显示一致。
- 分桶粒度：跨度 ≤ 120 天按日；≤ 730 天按周（周一起始）；更久按月。
  `range=all` 时从最早记录起算，空库回退 30 天。
- 非法 from/to（格式错、from > to、只给一端）返回明确错误，不静默纠正。
- 前端手选区间的日期选择器限制 `max=今天`、`to` 的 `min=from`，避免明显无效区间；
  区间语义始终是**闭区间**：`from`、`to` 两天自身的数据都计入。

### 3.2 范围语义（重要）

**范围只影响"流量"指标，不影响"存量"指标**，每个区块标题会标注口径：

| 类别 | 受 range 影响 | 例子 |
| --- | --- | --- |
| 存量 | 否 | 总数、状态构成、标签分布、逾期、账龄、标签使用分布、目录分布、Top 排行、明细清单 |
| 流量 | 是 | 每日/周新增、每日完成、每日到期、新增标签/关联、新增站点/目录 |

这样切范围时 KPI 不会突然从"总任务 128"变成"30 天新增 12"，避免误读。
区块标题统一写「当前」或「近 30 天」，图例/脚注给出定义。

### 3.3 返回包络

所有 `*.statsReport` 共享外层结构：

```json
{
  "generatedAt": 1762600000000,
  "range": { "from": "2026-10-10", "to": "2026-11-08", "days": 30, "bucket": "day" },
  "totals": {},
  "rates": {},
  "breakdowns": {},
  "trend": [{ "bucket": "2026-10-10", "created": 3, "done": 1, "due": 2 }],
  "rankings": {},
  "lists": {},
  "warnings": [{ "code": "tag_domain_missing", "message": "标签插件未启用，标签相关区块已隐藏" }]
}
```

- `generatedAt` 为毫秒时间戳；前端显示 `HH:mm:ss`。
- 可选区块在依赖缺失时返回 `null` 并给 `warnings`，**不报错、不返回半截数组**。
- 数值一律 number；比例是 0–1 的小数，前端格式化百分比。
- 所有查询排除 `deleted_at IS NOT NULL`。

### 3.4 图表规范

遵循 [03-UI设计](./03-UI设计.md)："卡片 + 微图表（自绘 SVG，避免引重型图表库）"。

| 图形 | 用途 | 实现 |
| --- | --- | --- |
| KPI 数字卡 | 总量/比率 | 大数字 + 单位 + 一句口径提示 |
| 环形图 Donut | 状态构成（3–5 类） | SVG circle + stroke-dasharray，中心放总数 |
| 横向条形 BarList | Top 排行 | 纯 div/SVG 条 + 右侧数值，条长按最大值归一 |
| 折线/面积 Trend | 每日新增/完成/到期 | SVG path，2–3 条 series，横轴抽 4–6 个刻度 |
| 直方图 Histogram | 逾期账龄、优先级（0–10）、难度（0.5–5）单值分桶 | 等宽竖条 + 桶标签 |
| 表格 DataTable | 逾期清单、目录树、沉睡标签 | 语义 `table`，首列可省略 |

- 颜色只用语义 token：`--dsw-alias-brand-primary`、`--dsw-alias-state-*`、
  `color-mix(...)` 派生；不写死色值。每页固定 6 色顺序，色盲友好（同时有文字/数值）。
- 每张图 `role="img"` + `aria-label`（如"任务状态构成：进行中 42，已完成 61…"）；
  悬浮提示用原生 `<title>`，不做自绘 tooltip。
- 尊重 `prefers-reduced-motion`；无入场动画，只有 hover 高亮。
- 窄屏 < 900px 单列；< 600px KPI 两列、图表高度降为 160px。

### 3.5 页面骨架

```
┌ 统计 ────────────────────────────────────────────────┐
│ [近7天] [近30天] [近90天] [近1年] [全部]   刷新 · 截至 12:34 │
├ KPI ─────────┬─────────────┬─────────────┬───────────┤
│ 总任务 128   │ 进行中 42    │ 逾期 7      │ 完成率 48% │
├──────────────┴─────────────┴─────────────┴───────────┤
│ 趋势（新增/完成/到期）                    │ 状态构成   │
│                                          │ 环形图     │
├──────────────────────────────────────────┴───────────┤
│ 优先级（单值直方图）      │ 难度（单值直方图）          │
├───────────────────────────┴──────────────────────────┤
│ 逾期账龄 + 逾期清单        │ 任务表/组排行             │
├───────────────────────────┴──────────────────────────┤
│ 最近完成（按完成日期）     │ 最近关闭（按关闭日期）     │
└──────────────────────────────────────────────────────┘
```

- 区块顺序按"先结论后明细"：KPI → 趋势 → 结构 → 风险 → 排行/明细。
- 每个区块是独立卡片，内部自己处理空态；单块失败不拖垮整页（服务端一次算完，
  前端只在整体失败时显示错误条）。

### 3.6 刷新与状态

- 首次进入/切范围：骨架屏（KPI 灰块 + 图表占位），不闪白。
- SSE 事件：800ms 防抖后静默刷新；`document.visibilityState !== "visible"` 时跳过，
  回到前台再补一次。
- 请求竞态：组件内自增 `reqId`，只接受最后一次响应。
- 错误：保留上一次成功数据，顶部显示细错误条 + 「重试」；无数据时显示完整错误态。
- 空库：不画空坐标轴，显示引导文案（"还没有任务。在「任务记录」里创建后，这里会自动汇总"）。

### 3.7 i18n 与格式化

- 每个插件自带 `COPY.zh` / `COPY.en`，新增键统一 `stats_` 前缀。
- 数字用 `Intl.NumberFormat(lang)`；百分比保留 0–1 位小数；天数保留 1 位。
- 日期展示 `MM-DD`（趋势轴）与 `YYYY-MM-DD`（明细）。

## 4. 任务统计（wb-addon-tasks）

### 4.1 可展示的维度

1. **总量与状态结构**：总数、进行中、已完成、已关闭、已重启、完成率、重启率、关闭率。
2. ~~标签结构（标签 × 状态堆叠图）~~：**2026-11-08 移除**。标签筛选已覆盖这个场景，
   多标签任务会在多个分组里重复出现、总和大于任务数，图注解释成本高于信息价值；
   标签能力仍保留在记录页与 `tasks.list`（`tags` / `tagIds`）。
3. **优先级结构**：0、1、2…10 **单值分桶**（每个整数一桶，0 即未设置）。不再合并区间，
   区间会把 9 和 10 糊在一起，看不出卡点。
4. **难度结构**：0.5、1、1.5…5 **单值分桶**（0.5 步进）；0/空值单列「未设置」。
5. **时间趋势**：每日新增（created_at）、每日完成（done_date）、每日到期（target_date）。
6. **逾期风险**：逾期总数、账龄分桶（1–3 / 4–7 / 8–14 / 15–30 / >30 天）、逾期清单 Top 10。
7. **任务表/任务组排行**：按当前存量统计总数、进行中、逾期、完成率；支持"按任务表"与
   "按任务组（一级组）"两种视角。
8. **流转效率**：平均完成周期（created_at → done_date）、平均交付周期
   （publish_date → done_date）、近 N 天完成量。
9. **焦点数字**：今日到期、未来 7 天到期、近 7 天新增。
10. **近期流水**：最近完成任务（`status='2'`，按 `done_date` 倒序）与最近关闭任务
    （`status='1'`，按 `shutdown_date` 倒序）；条数各自独立配置，默认 10，取值 1–50。

### 4.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 总任务 | `task` 未删行数 |
| 进行中/已关闭/已完成/已重启 | `status` = `'0'` / `'1'` / `'2'` / `'3'` |
| 逾期 | `status='0' AND target_date IS NOT NULL AND target_date < today` |
| 今日到期 | `status='0' AND target_date = today` |
| 未来 7 天到期 | `status='0' AND target_date BETWEEN tomorrow AND today+7` |
| 完成率 | `done / total`（分母含关闭/重启，脚注注明） |
| 逾期率 | `overdue / active`（无进行中时为 0） |
| 平均完成周期 | 范围内完成任务的 `AVG(julianday(done_date) - julianday(date(created_at/1000,'unixepoch','localtime')))`（`created_at` 为毫秒） |
| 平均交付周期 | 范围内完成任务的 `AVG(julianday(done_date) - julianday(publish_date))` |
| 账龄 | `today - target_date` 的自然日差 |
| 任务组 | 任务表 `task_node.path` 的第一段（根 `'1'` 之下的一级组）；路径缺失时回退 `parent_id` 上溯 |
| 最近完成 | `status='2'` 且未删除；`ORDER BY (done_date 为空), done_date DESC, updated_at DESC`；`daysAgo = today - done_date` |
| 最近关闭 | `status='1'` 且未删除；`ORDER BY (shutdown_date 为空), shutdown_date DESC, updated_at DESC`；`daysAgo = today - shutdown_date` |

注意：

- `done_date` 为空的已完成任务（历史/同步数据）不计入完成趋势与周期均值，响应里用
  `warnings` 报数量，不猜日期。
- `priority` 缺省为 0，0 单独占一桶（"未设置"），不并入其他桶。
- `difficulty` 为 REAL，按 0.5 步进取整到最近的桶；0/空值计入「未设置」。
- 任务不再有 `type`：`breakdowns.type` 已移除；`breakdowns.tags` 也已移除（2026-11-08），
  统计页不再有「标签 × 状态」区块，标签域未安装也不会再产生 `tag_domain_missing` warning。
- 任务表已被删除但任务仍在：label 用"已删除任务表"，不丢行。

### 4.4 查询与索引

- 总量/结构：状态一条 `GROUP BY status`；标签一条 `tag LEFT JOIN tag_mapping(item_type='task') LEFT JOIN task`（`COUNT(DISTINCT t.id)` 由 join 结构保证），再补一条 `NOT EXISTS` 的未打标签查询。
- 标签域缺失（`hasDomain('wb-addon-tags')` 或表不存在）时跳过标签查询并给 warning。
- 趋势：三条 `GROUP BY date`（created/done/due），JS 合并 zero-fill。
- 账龄/逾期清单：一条带 `julianday` 的查询 + `ORDER BY target_date`。
- 最近完成/关闭：各一条 `LIMIT` 查询，走 `status + done_date` / `status + shutdown_date`；
  日期为空的行排在末尾，不丢弃（前端日期列留空）。
- 排行：`task LEFT JOIN task_node` 后 JS 归组；任务表数量通常 < 100，可全量载入节点树。
- 新增索引（`ensureSchema` 里 `CREATE INDEX IF NOT EXISTS`）：
  - `idx_task_created_at(created_at)`：新增趋势；
  - `idx_task_done_date(done_date)`：完成趋势与周期均值。
- 现有 `idx_task_open(status,target_date)` 覆盖逾期；不重复建。

## 5. 标签统计（wb-addon-tags）

### 5.1 可展示的维度

1. **总量**：标签总数、已使用、未使用（孤儿）、关联对象数、关联总数、平均每对象标签数。
2. **使用分布**：按使用次数分桶（0 / 1–2 / 3–5 / 6–10 / >10），看长尾与头部。
3. **Top 100 标签**：统计页左列固定展示使用次数最多的 100 个标签（不足 100 个按实际数量），替代原 Top 标签榜；长列表在卡片内滚动，窄屏堆叠。返回含占比与最近使用时间，按使用次数降序、最近使用时间降序、id 升序排序。卡片显示共 N 个标签、排名/名称/次数，行高 28px，滚动容器上限 `min(64vh,720px)`，表头吸顶；名称省略并保留 title，横条按最大值归一，单标签条不铺满。每行单按钮，整个榜单仅一个 Tab 停靠点，可用上下/Home/End 移动，Enter/Space 或点击跳转标签记录页并按名称筛选。`stats.sections` 的 `top` 开关沿用。
4. **关联对象类型**：`tag_mapping.item_type` 分布，现有 `site`（站点）与 `task`（任务）两类；未知类型归入“其他”。
5. **增长趋势**：每日/周新增标签数、新增关联数。
6. **活跃度**：最近 30 天被使用的标签、长期未使用标签（>90 天或从未使用）。
7. **健康度**：孤儿率、单次使用标签占比；疑似重复名称（二期，见 §14）。

### 5.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 标签总数 | `tag` 未删行数 |
| 已使用/未使用 | 存在/不存在未删 `tag_mapping` 的标签数 |
| 关联对象数 | 按 `(item_type, item_id)` 去重计数（任务与站点 id 可能重号，不能只按 `item_id` 去重） |
| 关联总数 | 未删 `tag_mapping` 行数 |
| 平均每对象标签数 | `关联总数 / 关联对象数`（无对象时为 0） |
| 使用次数 | 某标签未删 `tag_mapping` 行数 |
| 最近使用 | 某标签未删 `tag_mapping` 的 `MAX(updated_at)` |
| 新增标签/关联趋势 | 按 `created_at` 分桶，**包含后来解除的关联**（历史新增），图例注明 |
| 沉睡标签 | 无关联，或最近关联 `updated_at` 早于 90 天前 |

注意：

- 标签与关联都是毫秒时间戳，分桶用 `localtime`。
- 不统计"站点覆盖率"：那需要读 `site` 表，属于站点模块；放在站点报表（§6）。
- `item_type` 现有 `site` / `task` 两类（tasks 直接写 `tag_mapping`，`TAG_ITEM_TYPE='task'`）；出现未知类型时归入"其他"，不丢数据。

## 6. 站点统计（wb-addon-sites）

### 6.1 可展示的维度

1. **总量**：站点总数、可绑定/不可绑定、目录数、有标签/无标签、标签覆盖率、
   有链接/无链接/多链接。
2. **目录分布**：目录树表（直接数 / 含子树），Top 10 横向条形。
3. **标签 Top**：按站点数排序的标签 Top 10（依赖标签域）。
4. **增长趋势**：每日/周新增站点、新增目录。
5. **新鲜度**：最近更新分桶（≤7 / 8–30 / 31–90 / >90 天）、最久未更新 Top 10。
6. **链接健康**：无链接数、单链接、多链接；重复 URL 组（去重候选）Top 5。
7. **数据质量**：无目录站点数、空目录数（含子树 0 站点）、深目录数（depth ≥ 3）。
8. **最近动态**：最近新增/最近更新各 Top 10。

### 6.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 站点总数 | `site` 未删行数 |
| 可绑定 | `bindable = 1` |
| 目录数 | `site_node` 未删行数（不含虚拟根 0） |
| 有标签 | `tag_mapping` 中 `item_type='site'` 的 DISTINCT `item_id`，且标签域可用 |
| 标签覆盖率 | `有标签 / 站点总数` |
| 链接分桶 | 解析 `site_link` JSON 数组长度：0 / 1 / ≥2；非法 JSON 记 0 并 warning |
| 目录直接数 | `site_node_mapping.node_id = 目录 id` 的站点数 |
| 目录子树数 | 目录自身 + 所有 `site_node.path LIKE 目录path || '%'` 的后代 |
| 空目录 | 子树站点数为 0 的目录 |
| 深目录 | `depth >= 3` 的目录（根 0，一级目录 depth=1） |
| 重复 URL | 归一化（trim、小写 scheme/host、去末尾 `/`）后计数 > 1 的 URL 组 |
| 新鲜度 | `today - date(updated_at/1000,'unixepoch','localtime')` 分桶 |

注意：

- 站点必须归属目录（`sites.create` 强制 `dirIds`），但同步/历史数据可能缺失映射；
  无目录站点单独计数，不强行归入"未分类"。
- 标签域不可用时：`tagged/untagged/topTags` 返回 `null`，`warnings` 加
  `tag_domain_missing`，页面隐藏标签区块并显示一条提示。
- 站点多链接存在 `site_link` JSON 里，解析失败不抛错，按 0 链接计。

## 10. 性能与上限

| 项 | 约束 |
| --- | --- |
| 单次报表查询数 | ≤ 10 条聚合 SQL |
| 趋势桶数 | 日 ≤ 120、周 ≤ 104、月 ≤ 60；超出自动降粒度 |
| 排行/明细 | `top` 夹在 1–20，清单最多 10 行 |
| 目标耗时 | 1 万任务 / 1 千标签 / 1 千站点 p95 < 80ms（本地 SQLite） |
| 前端请求 | 每次切范围 1 个请求；SSE 刷新 800ms 防抖；页面隐藏时暂停 |
| 缓存 | 不做服务端缓存，避免事件后读到旧值；前端只保留"上一次成功数据"用于错误兜底 |
| 内存 | 目录树/站点全量载入仅用于聚合，单次请求内释放，不跨请求持有 |

若未来单模块数据超过 10 万行，再把趋势/排行下推到 SQL 并加分页；一期不做过度设计。
