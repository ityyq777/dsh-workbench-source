## 0. 结论速览

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| M1 | 六个服务商预设：QQ、网易（163/126/yeah 统一入口）、微软（outlook/hotmail/live）、Gmail、iCloud、其他 | 覆盖国内主流 + 国外主流；「其他」兜底长尾 |
| M2 | 预设常量表只放 `packages/addons/mail/lib/domain/providers.js`（纯数据、无 import），通过只读 action `mail.providerList` 暴露给客户端 | 一处硬编码；加服务商只改一个文件，客户端不复制数据 |
| M3 | 域名识别在客户端完成，规则来自预设表的 `domains` 字段；识别不到自动落「其他」并展开主机输入 | 不新增识别 action，识别逻辑随表走 |
| M4 | 授权码内联录入，`type=password` + 小眼睛，复用 `packages/addons/lib/secret-field.cjs` | 共享控件已存在（任务 C 抽出），不再造第二份 |
| M5 | 凭据类型用 `kind: "app_password"`，`meta: { username, provider }` | 授权码本质是应用专用密码；`KINDS` 已有该枚举，无需改 schema；`meta` 键名不命中脱敏正则 |
| M6 | 保存顺序：客户端先 `vault.secretCreate` 再 `mail.accountCreate`；后者失败默认**回滚删除**凭据 | 服务端不接收明文密码，避免明文进入 host 调用链与审计 |
| M7 | 新增 `mail.accountProbe`（仅 UI）：草稿参数直接做 IMAP LIST + SMTP AUTH 自检，保存前就能发现填错 | 「先保存后测试」要用户删了重来；probe 的 `password` 键名命中审计脱敏正则 |
| M8 | IMAP 一律 993 隐式 TLS；143 STARTTLS 暂不支持，遇到时明确提示 | `lib/infra/imap.js` 目前只做隐式 TLS，无 STARTTLS 升级（见 5.4） |
| M9 | 不加数据库列：自检结果只在界面会话内保留；「最近邮件」由 `MAX(mail_message.date_at)` 聚合派生 | 零迁移成本；连接状态本就不该长期可信 |
| M10 | 错误按 `auth / dns / refused / timeout / tls / starttls / unknown` 分类，禁止统一「保存失败」 | 用户原话：要能判断是授权码错还是网络/端口错 |
| M11 | 保险箱三态降级：未安装 → 降级到「已有 secretId」高级路径；未初始化 → 内联初始化；锁定 → 内联解锁 | mail 包未声明 vault 依赖，运行时才失败，必须提前处理 |

## 2. 目标与非目标

**目标**

1. 把「新增账户」从 5 个手填框变成「选服务商 → 填邮箱与授权码 → 自检 → 保存」；
2. 固定预设隐藏主机/端口/TLS，用户改不了也就不用改；只有「其他」才展开；
3. 授权码内联录入并直接落保险箱，用户不再接触 `secretId` 字符串；
4. 保存前能自检，失败给出可操作的分类原因；
5. 账户可编辑、有连接状态与最近邮件时间。

**非目标**

- 不改 IMAP/SMTP 协议实现（`lib/infra/imap.js`、`lib/infra/smtp.js` 只加一个 probe 导出，不改现有收发路径）；
- 不做 OAuth 授权流程（本次只用授权码；文案里留「若失败请改用应用密码/OAuth」）；
- 不改保险箱本身的加密与解锁机制；
- 不做「离线草稿」（未通过自检的账户仍允许保存，但状态显示「未测试」，见 4.2-B9）。

## 4. 交互流程

### 4.1 主流程（状态机）

状态：`idle`（列表）→ `form`（新增/编辑）→ `probing` → `probed-ok` / `probed-fail` → `saving` → `idle`。

| 步骤 | 触发 | 结果 |
| --- | --- | --- |
| S1 | 点「添加账户」 | 进入 `form`，服务商默认「其他」以外的**空选**（等邮箱输入后自动识别） |
| S2 | 输入邮箱失焦 | 按域名识别 → 选中预设 + 回填主机端口 TLS + 显示「已识别为 QQ 邮箱」；识别不到 → 选「其他」+ 展开条件区 + 提示 |
| S3 | 手动点某个服务商 chip | 覆盖识别结果，回填该预设；再点「其他」展开条件区 |
| S4 | 填授权码 | 显示该服务商的获取帮助（QQ/网易/Gmail/iCloud 有专门文案） |
| S5 | 点「连接自检」 | `probing`：先 IMAP LIST，再 SMTP AUTH（不发信）；成功 → `probed-ok`「连接正常，发现 12 个文件夹」；失败 → `probed-fail` + 分类文案 |
| S6 | 点「保存」（自检未通过也允许，二次确认「未通过自检，仍要保存吗？」） | `saving`：`vault.secretCreate` → `mail.accountCreate` |
| S7 | 保存成功 | 清空表单回 `idle`，卡片出现，状态徽章 = 本次自检结果（`正常` / `未测试` / `失败：原因`） |
| S8 | 卡片「编辑」 | 进入 `form` 并预填（含服务商与主机），授权码留空 = 不轮换 |

## 5. 服务商预设表

### 5.1 数据结构（`packages/addons/mail/lib/domain/providers.js`）

纯数据 + 两个纯函数，无 import，服务端 ESM 与客户端都能安全消费（客户端经 action 取表）。

```js
export const PROVIDER_SCHEMA = 1;
export const PROVIDERS = [
  {
    id: "qq",
    label: { zh: "QQ 邮箱", en: "QQ Mail" },
    domains: ["qq.com", "foxmail.com", "vip.qq.com"],
    imapHost: "imap.qq.com", imapPort: 993, imapTls: true,
    smtpHost: "smtp.qq.com", smtpPort: 465, smtpTls: true,
    usernameMode: "full",            // full | local | custom
    secretKind: "app_password",
    hint: {
      zh: "在 QQ 邮箱「设置 → 账号 → POP3/IMAP/SMTP 服务」开启服务并获取 16 位授权码；登录密码不可用。",
      en: "Enable POP3/IMAP/SMTP in QQ Mail settings and use the 16-character authorization code.",
    },
    helpUrl: "https://service.mail.qq.com/detail/0/75",
  },
  // … 其余见 5.2
];

export function detectProvider(email) { /* 返回 provider 或 null */ }
export function providerById(id) { /* 返回 provider 或 null */ }
```

`usernameMode` 语义：`full` = 登录名等于完整邮箱；`local` = 取 `@` 前的主名（iCloud 的 Apple ID 常是主名）；`custom` = 由用户在条件区自己填。

### 5.3 域名识别规则

1. 取邮箱 `@` 之后的部分，转小写、去尾点；
2. 精确匹配 `domains`；不命中再做**后缀匹配**（`user@mail.qq.com` → `qq.com`），只在后缀是 `.<domain>` 时成立；
3. 命中多个（如 `qq.com` 与 `vip.qq.com` 同时命中）取最长域名；
4. 都不命中返回 `null` → 界面落「其他」并展开条件区（B3）；
5. 用户手动选择后**不再**被后续输入覆盖（记住 `touchedProvider` 标记），只在用户清空邮箱或点「重新识别」时恢复自动。

### 5.4 IMAP STARTTLS 的现状与处理

`lib/infra/imap.js` 的 `connect()` 只做 `tls.connect`（隐式 TLS）或 `net.connect`（明文），没有 STARTTLS 升级；`imapList` 也不会发送 `STARTTLS`。因此：

- 所有预设的 IMAP 一律 993 + TLS；
- 「其他」里用户若填 143 或关闭 TLS，保存前提示「当前版本 IMAP 仅支持 993 隐式 TLS，143 + STARTTLS 尚未支持」，并且**不阻止保存**（保存后自检会明确报 `starttls`/`tls` 分类）；
- 若后续要支持 143，属于 `lib/infra/imap.js` 的独立改动，不在本设计范围。

SMTP 侧无此限制（`lib/infra/smtp.js` 已实现 STARTTLS，`:59-62`）。

### 5.5 单一来源与暴露方式

- 物理上只有 `providers.js` 一份数据；
- 新增只读 action `mail.providerList`（origin 任意，含 agent），返回 `{ schema, providers }`；
- 客户端在 `accounts.cjs` 首次渲染时 `C.call(api, "mail.providerList")` 并缓存到模块级变量（跨视图切换不重复请求）；取不到时只保留「其他」一个选项，**不内置任何主机数据**（避免第二份硬编码）；
- 这样加服务商 = 改 `providers.js` + 发版，客户端零改动。

## 6. 「其他通用邮箱」字段清单与校验

| 字段 | 控件 | 默认 | 校验 |
| --- | --- | --- | --- |
| IMAP 主机 | 文本 | 空 | 必填，1–255 字，不含空格与 `://` |
| IMAP 端口 | 数字 | 993 | 1–65535 整数 |
| IMAP TLS | 开关 | 开 | 关闭时提示 5.4 的限制 |
| SMTP 主机 | 文本 | 空 | 必填，规则同上 |
| SMTP 端口 | 数字 | 465 | 1–65535 整数；填 587 时自动提示 STARTTLS |
| SMTP TLS | 开关 | 开 | 关闭时走 STARTTLS（587），再失败报 B10 |
| 登录名 | 文本 | 完整邮箱 | 可空（空则用邮箱）；不含空格 |
| 账户名称 | 文本（高级区） | 邮箱 `@` 前的主名 | 1–100 字 |

校验时机：失焦校验单字段，提交前整体校验；错误文案就地显示在字段下方（`Field` 的 `error` 位）。

## 7. 凭据内联与保险箱降级

### 7.1 保存顺序与补偿

```
1) vault.secretCreate({ name, kind: "app_password", secret, meta: { username, provider } })
   → 得到 secretId
2) mail.accountCreate({ name, email, imapHost, imapPort, imapTls, smtpHost, smtpPort, smtpTls, username, secretId })
3) 若 2) 失败：
   a. 默认：vault.secretDelete({ id: secretId }) 回滚 → 提示 B14 前半句
   b. 回滚失败：保留凭据 → 提示 B14 后半句（名称可复用，用户在保险箱页能看到）
```

`name` 规则：`邮箱 · 服务商`（如 `me@qq.com · QQ 邮箱`），重名时追加序号（`vault.secretCreate` 要求名称唯一，1–100 字）。

**为什么服务端不收明文密码**：`mail.accountCreate` 的入参会被宿主审计（`packages/shell/lib/infra/audit.js`），虽然 `password` 键会被脱敏成 `***`，但明文仍会经过 host 调用链与可能的日志；客户端直连 `vault.secretCreate` 符合 vault「明文只在 UI 层出现」的门禁设计（`vault.lease` 只给 plugin，`secretCreate` 只给 ui）。

### 7.2 三态降级（`VaultGate`）

| 状态 | 判定 | 界面 |
| --- | --- | --- |
| 未安装 | `vault.status` 抛「没有业务插件注册 action：vault.status」 | 表单④位置显示说明 + 「改用已有凭据 id」开关；打开后条件区追加 `secretId` 输入框（B11） |
| 未初始化 | `vault.status` 返回 `initialized: false` | 内联主口令 + 确认口令（两个 `SecretField`，各自独立切换明文）+「初始化并继续」→ `vault.setup({ passphrase, mode: "A" })`（B12） |
| 锁定 | `initialized: true` 且 `unlocked: false` | 内联解锁框 +「解锁并继续」→ `vault.unlock({ passphrase })`（B13） |
| 正常 | `initialized: true` 且 `unlocked: true` | 不显示任何额外控件，授权码框可直接用 |

初始化/解锁成功后**继续原保存动作**（不要求用户再点一次保存）。

站点插件 `packages/addons/sites/client/ui/accounts-modal.cjs:180-226` 已有一套同样的三态处理，视觉与文案保持一致的措辞（「保险箱尚未初始化」/「保险箱已锁定」），但不复制代码：本次把判定逻辑写进 mail 自己的 `vault-gate.cjs`（约 60 行），若后续第三个插件也要用，再按 `AGENTS.md` 的红线抽到 `packages/addons/lib/`。

### 7.3 凭据 kind 与 meta

- `kind: "app_password"`：`packages/addons/vault/lib/domain/secret-input.js` 的 `KINDS` 已包含，无需改 schema；
- `meta: { username, provider }`：键名不命中 `META_BAD` 正则（`/(pass(word|wd)?|pwd|token|secret|api[_-]?key|private[_-]?key|credential)/i`），合法；
- 不在 `meta` 里存主机/端口（非敏感但易过期），主机信息以 `mail_account` 为准。

## 8. 保存前自检：`mail.accountProbe`

### 8.1 两个方案

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| A. 新增 `mail.accountProbe`（仅 UI，草稿参数） | 保存前就能验证；不写库；错误分类最准 | 明文密码进 action 入参（靠键名脱敏 + origin 门禁） |
| B. 先保存后 `mail.accountTest` | 零新 action | 填错要先落库再删；账户表里出现脏数据；用户抱怨的正是这个流程 |

### 8.2 选择：A

理由：用户原话的核心诉求是「便捷」，先保存后测试把错误成本转嫁给用户；明文风险可控——入参键名固定为 `password`（命中 `SECRET_KEY` 正则，审计里是 `***`），origin 只允许 `ui`，且 probe 不落库、不写日志、执行完即丢弃引用。

### 8.3 契约草案

```js
api.action("mail.accountProbe", {
  description: "连接自检（仅 UI）：用草稿参数登录 IMAP 并列出文件夹、SMTP 认证，不保存任何数据。",
  input: {
    type: "object",
    properties: {
      imapHost: { type: "string" }, imapPort: { type: "number" }, imapTls: { type: "boolean" },
      smtpHost: { type: "string" }, smtpPort: { type: "number" }, smtpTls: { type: "boolean" },
      username: { type: "string" },
      password: { type: "string", description: "明文授权码，仅内存使用，审计中显示为 ***" },
      secretId: { type: "string", description: "已有凭据 id，二选一" },
    },
    required: ["imapHost", "username"],
    additionalProperties: false,
  },
  execute: (args, ctx) => { deny(ctx.origin); return mail.probeAccount(args); },
});
```

返回：

```js
{
  ok: false,
  imap: { ok: false, errorClass: "auth", message: "IMAP 登录失败：a1 NO [AUTHENTICATIONFAILED] …", ms: 812 },
  smtp: { ok: true, ms: 340 },          // 未配置 smtpHost 时为 null
  errorClass: "auth",                    // 取第一个失败步骤的分类，便于界面一条文案
}
```

`probeAccount` 实现要点：

1. `password` 为空且 `secretId` 非空 → 走 `vault.lease`（plugin 门禁，domain 侧合法）取明文，再走同一路径；
2. IMAP：复用 `imapList`（`lib/infra/imap.js:61`），`secure = imapTls !== false`；
3. SMTP：新增 `probeSmtp({ host, port, secure }, user, secret)` 导出（connect + EHLO + 可选 STARTTLS + AUTH LOGIN，**不发信**）；
4. 每一步 `try/catch`，把底层错误映射成 `errorClass`（见 8.4），保留原始 `message` 前 200 字；
5. 不做重试（15s 超时已在 infra 层），总预算 20s。

### 8.4 错误分类映射

| errorClass | 识别特征（`e.code` / `e.message`） | 文案 |
| --- | --- | --- |
| `auth` | `AUTHENTICATIONFAILED`、`LOGIN failed`、`IMAP 登录失败`、`535`、`535 5.7.8` | B7 |
| `dns` | `ENOTFOUND`、`EAI_AGAIN` | 「找不到主机 {host}，请检查主机名」 |
| `refused` | `ECONNREFUSED`、`ECONNRESET` | 「{host}:{port} 拒绝连接，请检查端口」 |
| `timeout` | `IMAP 连接超时`、`ETIMEDOUT`、`IMAP 响应超时` | 「连接 {host}:{port} 超时，请检查网络」 |
| `tls` | `ERR_TLS_CERT_ALTNAME_INVALID`、`self signed certificate`、`certificate has expired`、`wrong version number` | B9 |
| `starttls` | `服务器不支持 STARTTLS` | B10 |
| `unknown` | 其余 | 「自检失败：{message}」 |

分类函数放 `providers.js` 同目录的 `probe-error.js`（纯函数，单测直接覆盖），客户端只消费 `errorClass`，不重复写判断。
