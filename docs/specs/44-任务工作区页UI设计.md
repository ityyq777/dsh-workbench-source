# 任务「工作区」页 UI 设计（tasks 5.2.8）

## 1. 背景与结论

「工作区」页是任务插件里唯一自带一套 `wbt-ws-*` 内联样式、没有接入共享外壳的视图：标题用 `strong`、
条数挤在标题行、搜索框与「新建」同处一行、列表行是自定义 `article.wbt-ws-row`，没有 hover/focus 过渡，
也不使用 `.wbt-content` 与 `.wbt-item`。与「记录」「时间线」「统计」「配置」四页并排时，字号、间距、
圆角与按钮尺寸都对不上。

本设计把工作区页收敛到现有共享体系上：**不改数据与 action，只重排结构与复用共享类**。首期目标是
「看起来是同一个插件的页面」，不是重做信息架构。

## 2. 现状对照

| 维度 | 工作区页（改造前） | 记录页 / 时间线页 / 配置页 |
| --- | --- | --- |
| 标题 | `strong` + 说明 + 条数 + 新建按钮挤在 `.wbt-ws-head` 一行 | 记录页用页签标题 + `.wbt-pathrow` 工具栏；配置页用 `h2`（17px）+ `.note` 说明 |
| 工具栏 | 搜索框与新建按钮分两行，无刷新入口外的分组 | `.wbt-pathrow`：左侧信息、右侧 `wbt-btn` 组（图标 + 文案），`.wbt-grow` 撑开 |
| 列表容器 | `.wbt-ws-list` 自定义滚动区 | `.wbt-content`（边框 + 圆角 + 溢出裁剪）> `.wbt-list-scroll` |
| 行卡片 | `article.wbt-ws-row`，自定义 border/padding，无 hover | `.wbt-item`：`--wb-radius-card`、`--wb-space-md`、hover 边框与阴影过渡 |
| 操作 | 纯文字 `wbt-btn ghost` | 图标 + 文字（`pencil` / `trash` / `plus` / `refresh`） |
| 状态 | 自定义 `.wbt-ws-empty` / `.wbt-ws-error` | `.wbt-empty`（虚线）、`.wbt-err`（danger 色） |
| 数据 | `taskWorkspaces.list { pageSize: 100 }` 全量拉取，前端过滤 | 同左（本次保留，见 §7） |

## 3. 设计原则

1. **复用优先**：容器、按钮、输入框、空态、错误态一律用共享类（`.wbt-root` / `.wbt-pathrow` / `.wbt-content` /
   `.wbt-list-scroll` / `.wbt-item` / `.wbt-btn` / `.wbt-input` / `.wbt-empty` / `.wbt-err`），新增 CSS 只补
   工作区独有的结构间距，不覆盖全局 token。
2. **信息分层**：标题与说明属于页面级（`h2` 17px + 12px 次级说明），条数与搜索属于工具栏，
   单个工作区的标题/标识/目录/描述/任务数属于行级。
3. **动作可达**：顶部主操作（新建）为 `primary`，行内操作用 `ghost` + 图标；删除仍是行内二次确认，
   不弹系统对话框。
4. **不改语义**：`taskWorkspaces.*` 的 action、参数与返回不变；「任务数」继续跳到记录页并带 `workspaceIds`。

## 6. 交互与状态

- **加载**：首次进入 `taskWorkspaces.list` 未返回时，`.wbt-content` 内显示「正在读取工作区…」，工具栏按钮不禁用（刷新可重入）。
- **错误**：`.wbt-err` 显示「工作区加载失败：<原因>」+「重试」按钮，重试重新拉取。
- **空 / 无匹配**：分别提示「还没有工作区…」「没有匹配的工作区。」，搜索不请求服务端。
- **搜索**：受控输入，前端按键名/标题/目录/描述做大小写不敏感包含匹配；清空即恢复全量。
- **刷新**：工具栏「刷新」按钮与订阅事件（`task-workspaces-changed` / `tasks-changed`）都触发重新拉取。
- **新建 / 编辑**：复用现有模态（标题必填、目录须本机绝对路径、`name`/`description` 可空），保存后关闭并刷新。
- **删除**：行内二次确认，文案带关联任务数并说明「任务本身不会被删除」；确认后调用 `taskWorkspaces.delete`。
- **任务数**：按钮带 `aria-label`，点击 `onNavigate("tasks", { workspaceIds: [id] })`。
- **键盘可达**：所有操作都是原生 `button`/`input`，焦点环走共享 `:focus-visible`；模态为 `role="dialog"` + `aria-modal`。
- **响应式**：`.wbt-ws-toolbar` 换行，搜索框 `flex:1 1 200px`；窄屏下由共享 `@media (max-width:760px)` 让 `.wbt-content` 占满宽度。
- **中英文**：沿用页面内 `COPY.zh / COPY.en`，新增 `refresh` 键（刷新 / Refresh）。

## 7. 首期取舍

- **不做服务端搜索分页**：`taskWorkspaces.list` 已支持 `keyword` / `pageNumber`，但工作区规模是「几十个」级别，
  首期保留 `pageSize: 100` 全量 + 前端过滤，避免与任务列表的筛选语义纠缠；数据量或用户诉求上来后再切服务端分页
  （届时只改 `list` 调用与空态文案，不动行结构与类名）。
- **不加排序/分组**：工作区没有状态与优先级，加排序价值低，先保持 `updated_at` 倒序。
- **不引入新依赖**：不新增 UI 框架或图标库，图标继续走已有 `lucide-react` 映射。
