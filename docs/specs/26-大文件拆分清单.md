## 建议切法

### tasks/lib/tasks.js（1921）

`registerTaskActions(api)` 从第 1458 行到最后约 464 行，全是 action schema 与 `execute` 适配，
和 CRUD 实现挤在一起。切法：

1. `tasks/lib/tasks-actions.js`：整体搬走 `registerTaskActions`，`tasks.js` 只保留
   `export * from "./tasks-actions.js"`；execute 需要调用的私有函数改成具名导出，
   两边循环引用（ESM 函数声明在调用期解析，安全）。
2. 其余按职责继续拆：`tasks/lib/query.js`（`listTasks` 的筛选/分页/排序 + `renderList`）、
   `tasks/lib/tags-view.js`（`tasks.tags` / 标签筛选）、`tasks/lib/deps.js`（依赖视图）。
3. 迁移与批量（`bulk*`）可以留在 `tasks.js`，目标是 ≤600。

### tasks/client/client.src.cjs（1774）

单文件同时承载：`COPY` 文案、`ICONS`、CSS、组件（列表/卡片/编辑弹窗/树）、API 调用。
`pnpm build:clients` 目前只把 `client.src.cjs` 包成 `lib/client.js`，不含模块系统，
所以**先确认构建脚本支持多文件**（`scripts/build-clients.mjs`），再按
`client/views/{list,card,editor}.cjs` + `client/copy.cjs` + `client/styles.cjs` 拆；
否则先抽「纯数据/常量」到同目录 `.cjs` 并在构建时拼接，再逐步搬组件。

### tasks/client/data.cjs、tags/client/data.cjs、sites/client/data.cjs（各 788）

三份高度重复（表格列、行格式化、导出、筛选状态）。第一步不是拆，而是**抽公共**：
`packages/addons/shared-client/data-kit.cjs`（列定义工具、行渲染、CSV 导出、筛选状态机），
三份各自只留域特有列与接口，通常能直接掉到 400 行以内。

### sites/lib/accounts.js（669）、sites/lib/sites.js（631）

- `accounts.js`：账号 CRUD、外联校验、vault 挂靠守卫分开；`vault.js` 已独立，
  剩下按 `accounts/crud.js` + `accounts/guard.js` + `accounts/link.js` 拆。
- `sites.js`：目录/站点 CRUD 与标签映射、备份导出分开。

## 执行约定

- 纯结构调整、不改行为；一次一个文件、一个提交，便于回滚；
- 拆完立刻跑该插件测试（任务：`test:native test:data test:nodeps test:config`；
  站点：`test:sites test:data`；标签：`test:tags test:tags-ui`），再跑
  `node scripts/audit-actions.mjs` 确认 action 导出面没变；
- 旧文件保留原导出面（`export * from "./xxx.js"`），调用方不跟着改；
- 每拆完一个文件，把 `scripts/line-budget.json` 里的上限下调到新行数，全部拆完则删条目。
