# 35 · 客户端视图图标契约

工作台沉浸页的多视图标签支持可选图标。图标只用于辅助辨识，视图标题始终显示，并继续作为按钮的可访问名称。无图标的旧插件无需修改。

## 注册方式

浏览器侧 `window.__WB_HOST__.registerAddon` 的 `views[]` 提供可选 `icon` 函数组件。SDK 的 `WbClientModule` 声明为 `icon?: any`，避免 SDK 增加 React 类型依赖；宿主运行时严格检查 `typeof icon === "function"`。

```js
const { Box } = require("lucide-react");
function StorageViewIcon(props) { return h(Box, props); }
host.registerAddon({
  id: "wb-addon-example",
  views: [{ id: "list", title: { zh: "物品", en: "Items" },
    component: ItemsView, icon: StorageViewIcon }],
});
```

lucide 图标导出通常是 React forwardRef 对象，不能直接填到 icon：必须像示例一样提供函数包装，并转发 props。图标实现随业务插件现有 bundle 分发，宿主不依赖 lucide、不维护图标名称映射，也不执行字符串、HTML 或远程图标代码。

## 渲染与退化

- 函数组件通过 React 元素正常渲染，收到 `size: 14`、`strokeWidth: 2`、`aria-hidden: true`。插件须转发这些属性；lucide 使用自身路径和 currentColor。
- 宿主同时将图标容器设为 aria-hidden，按钮的 aria-label 明确取本地化标题，标题为空时回退 view.id。装饰图标不参与读屏名称。
- undefined、null、string（含未知名称及 HTML 文本）、number、boolean、普通对象、forwardRef 对象等所有非函数值均忽略，只显示原有文字；不会为这些值创建元素或执行其属性。
- 函数组件属于受信任插件代码，与 view.component 相同；此契约不隔离主动抛错的函数组件，也不执行字符串来生成组件。
- 标签顺序、激活 class、`addon:<addonId>:<viewId>` 路由保持原行为；零个或一个视图仍不显示标签栏。服务器 manifest 的视图声明不增加可执行字段。

## 源码与打包

原宿主客户端由 DSH 原生模块加载器直接执行，内部 require 只能取已注入模块；仅把辅助函数移到独立文件并新增相对 require，会使浏览器找不到该模块。

沿用仓库已有 esbuild 依赖与原生模块 wrapper，将宿主源入口打包到原来的客户端出口。手写源拆为入口、静态文案、静态样式、管理页组件工厂及纯视图标签工厂，各文件不超过 600 行。账号、备份、审计代码为机械提取，工厂注入 react、jsx 和 useApi，无循环依赖。React 和 react/jsx-runtime 继续由宿主提供，不打入另一个 React 副本。生成客户端仍由发布流程复制到原路径；不新增构建依赖。

## 验证

执行 `node packages/shell/client/view-tabs.test.mjs` 验证源模块；构建完成后执行同命令加 `--bundle` 验证最终原生单文件。测试通过真实宿主注册桥注册 fixture 并使用仓库元素渲染 harness 展开图标组件，检查 SVG 子节点、尺寸线宽、aria 属性、中英文标签、错误值退化、每个标签点击后的视图及激活状态、旧 manifest 与单视图行为。该测试是确定性元素树测试，不替代浏览器像素/读屏验证。

同时运行既有 `node scripts/test-clients.mjs`，确认宿主桥及现有业务插件注册不变；完整构建、发布目录和临时实例验证由主流程统一执行。
