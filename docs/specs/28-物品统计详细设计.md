## 2. 两条量化路线的实测比较与推荐

### 2.1 明确解析边界

测算规则 v1：NFKC 全半角归一、trim；非负十进制；同单位数字后缀；有序范围 a~b/a-b 返回上下界；“半+当前单位”返回 0.5；“+”两侧必须全部同单位可解析；只识别明确白名单 0（待补充）。负数、反向范围、任意备注截取、混单位、约数不猜测；拒绝 eval、从首个数字硬提取。范围识别是区间成功，不是单值成功。文本上“半瓶”可解析也不证明瓶容量相同。

| 对比项 | A 数值列 + 阈值（推荐） | B 仅解析文本 |
| --- | --- | --- |
| 初始可确认量 | 现在 0/16；迁移全 NULL | 9/16 纯数字；加半量/复合/零备注得到 12/16 单值候选 |
| 范围识别与风险 | 4/16 必须盘点或人工选择后填数值 | 16/16 可识别，4/16 仍歧义；取上/下限会改变结果 |
| 存量工作量 | 16 条数量确认，至少 4 条盘点；16 条阈值需用户选择（可留空） | 无 schema 迁移，但仍有 4 条歧义；无阈值列，不能实现可靠低库存 |
| 迁移触点 | DB nullable 列、action/schema、表单、同步/备份/导入导出与兼容均需改 | 规则版本、异常列表、置信标注、每次文本编辑重新解析；每种新表达增规则与回归 |
| 后续维护 | 数值校验、单位变更失效、阈值维护；规则不进入真值链 | 语言规则持续增长，规则升级可让同一库存值变化；必须记录 parserVersion |
| 估算实现成本 | 库存核心 5–8 人日 + QA 2–3 人日，含兼容验证 | 解析展示 2–3 人日 + QA 1–2 人日；不含真正阈值预警 |
| 新增持久列 | 库存核心 2 个（另见单位/维度方案） | 0；若加阈值即已不是“仅解析” |
| 可审计性 | 数值由人确认；原文保留，修正显式 | 只能知道规则如何算，不能证明现场库存 |

成本是设计级估算，不是实测工时；按一名熟悉代码的开发者、不含评审等待估计。两者功能不等价，不用更便宜的 B 冒充完整预警方案。

范围敏感性必须分单位看：充电器 1–2 个，使“个”组合 7–8；数据线 3–5 根；抽纸 2–3 提；电池 1–2 盒。上下限差分别 1 个/2 根/1 提/1 盒，绝不求跨单位的“总误差”。假设这些记录各自 min_stock=1（仅说明规则，非真实阈值），充电器/电池用下限会预警、用上限不会，说明不能替用户拍板取端点。

推荐 A 的决定性理由：用户要的是可解释的库存和预警，不是更高的正则命中率。B 作为迁移辅助和一期质量诊断保留；本次脚本从不回填真实数据。

### 2.2 二期字段与兼容设计

- stock_qty、min_stock：可空有限非负小数，最多 3 位小数，最大 999999999.999；NULL=未确认/未设阈值，0 是有效值。数量和阈值同 unit；建议 SQLite REAL 存储、应用统一转换为整数千分单位比较/汇总，展示再除以 1000，避免浮点误差。所有输入/同步入口校验一致。
- 数量状态互斥：未知 stock_qty=NULL；缺货 qty=0；低库存 0<qty<=min_stock 且阈值有效；正常 qty>min_stock；无阈值 qty>0 且 min_stock=NULL。低库存 KPI 不重复计入缺货，补货清单合并两者并给原因。缺货不依赖阈值。
- stock 文本保留供阅读，只有明确确认操作设置 qty；修改 stock 而未同时显式提交 qty 时清空旧 qty，避免文本与数值脱节；qty 更新不强制覆盖备注性质的原文。修改 unit 必须重新确认 qty/min_stock，未提供则置 NULL。页面显示“当前文本未确认数值”。
- 迁移全 NULL，不把空库存当 0，不自动应用候选。可批量预览 12 个单值候选，逐条勾选确认；4 个范围进入盘点列表。字段缺失的旧同步客户端不能覆盖已有值为 0；旧客户端修改 stock/unit 应使新字段失效，兼容策略须通过双端回归后上线。
- unit 维持字符串语义，常用下拉 +“其他”输入只改善录入；“其他”不能作为聚合键，必须保留实际文本（如“箱”）。一期归一 NFKC+trim，不做“包=袋”等语义合并；二期同规则。空单位仍可计算记录数，但库存合计排除并列出“待补单位”。同单位不同规格只代表计数，不代表质量/体积或可互换性。
- category_id/location_id 可空，分别引用拟新增 storage_category/storage_location 的 id/name/created_at/updated_at/deleted_at/rev。字典属于 storage，不借 tags 保存；标签多选是横切属性，分类/位置是单选互斥维度。用户手工建立字典，初始不从现有“办公/数码/日用品”标签自动迁移。
- 有引用的字典只允许归档，保留 id/name，归档项仍出现在存量统计并标识；新物品不能选归档项。空值不进图、单列未设置计数；失效引用列入质量问题，不静默转为新类别。位置只支持一个主位置；若一个物品跨多处存放，二期不假装能统计分仓库存，需后续位置库存明细模型。
- 新列/字典后续必须同步 SQLite 迁移、云端 schema 与 DTO、变更日志、备份/还原、导入导出、action schema/capabilities/版本；本次全部未执行。分类与位置不能在缺字段时由名字“算出来”。

## 3. 统计集合、时间、空值与已删口径

设 S=当前已落库的 storage 记录；默认 deleted_at IS NULL，含已删除开关打开时纳入仍存在的软删行。N=|S|。这里的“截至”是读取快照时刻，不是历史库存回放。标签从当前有效映射和有效标签读取（m.item_type='storage'，m.deleted_at/t.deleted_at 均 NULL），DISTINCT item_id/tag_id 防止重复映射放大。

- “当前”区域：KPI、品牌/单位/标签/图片/质量/二期库存和维度分布都以 S 为全集，不随 7/30/90 时间按钮改变；卡片副标题固定“当前记录（不受时间范围影响）”。含已删除会改变 S，显示“当前记录含已删除 X 条”，库存文字改为“记录值汇总，含已删除”，禁止作为现实库存口径。
- “期间”区域：新增只按 created_at，最近更新只按 updated_at 过滤；时间切换的影响仅此两块，明确标记“所选期间”。updated_at 只代表最后修改，不能推导修改次数、消费/补货趋势。软删会改 updated_at，含已删时最近列表要标记“已删除”。
- 产品默认 30 天，提供 7/30/90/全部。采用客户端显式传 IANA timeZone，服务端统一计算边界并返回 from/to/asOf/timeZone。近 N 天含当天，从当地当天 00:00 减 N-1 个自然日，截止 asOf；日期范围内部 [from,nextDayStart)，再截断到 asOf。不能简单用 N×24h 计算 DST 地区的日界。本测算固定 Asia/Shanghai (+08:00)；不是推断浏览器时区。
- 新增趋势支持自然周（周一 00:00 开始）/自然月切换，7 天可默认日、30/90 天默认周、全部默认月。先裁范围再分桶，首尾不足完整周期标“部分”；图表按时间升序补齐范围内零发生桶以保证连续性。这些零事件桶有统计意义；分类/品牌等空维度桶、零频分类桶不画。脚本输出稀疏原始分桶，图表层补零，不把未发生事件误写成未知。
- 90 天未更新：updated_at <= asOf − 90×24h，精确经过时长，等于边界也算；停滞图分 0–29/30–89/90–179/180+ 天。这个指标与“近90天新增”无关。它表示记录没有更新，不意味着物品没使用或已过期。
- 缺失/无效/未来时间不落入趋势或账龄桶，质量计数单列；updated_at<created_at 标异常，实施时应从时间图中排除。本16样例无此类异常。
- 文本空值定义为 NULL 或 NFKC+trim 后空串；品牌不做大小写/同义词合并。重名按 NFKC+trim+小写的 name 判断，按同名组列清单，不自动合并。
- JSON 图片解析失败/非数组/非 HTTP(S) 或含凭据 URL 计入图片异常；有效链接数>=1 为有图，>=2 为多图。只检查格式，不向外请求 URL，因此“有图”不是“图片可访问”。备注仅测是否非空，不输出原文。
- N=0 时计数 0、比例 NULL 展示“—”，不显示 0/0=0%。标签能力不可用时 tagged/rate/topTags=NULL，显示“标签插件不可用”，而非“所有物品没标签”。测算工具只能验证表存在，不代表运行中插件能力；生产必须用 tagsOn 等能力判断。
- 软删不是归档。物理清理后无法重建已删数字；删除时标签映射已清除，含已删的标签统计仅表示“当前仍保留的有效关联”，不会恢复旧标签。可导出静态快照留证，但不承诺历史回放。

## 6. 接口、导出与归档设计

一期拟增加只读 storage.statsReport，保持现有 storage.stats 兼容。输入 range=7d/30d/90d/all（默认30d）、timeZone（IANA必填）、includeDeleted（默认false）、top（5/10/20）；输出 meta(asOf/from/to/timeZone/includeDeleted/metricVersion)、current、period、quality、warnings、availability。数据库一次只读事务确保各块同一快照；每个新增指标有value/denominator/available/reason，NULL不得序列化为0。后端分页明细/导出需沿用同一过滤定义，未来实现时再确定独立action名称并同步schema；不宣称现已注册。

CSV导出设计：

| 范围 | 阶段 | 列（公共元数据外） |
| --- | --- | --- |
| 汇总指标/品牌单位标签分布/趋势 | 一期 | metricKey、label、value、denominator、unit、bucket、available、reason |
| 文本无法解析、范围待确认 | 一期 | id、name、stock原文、unit、parseKind、lower、upper、parserVersion |
| 重名清单 | 一期 | duplicateKey、groupSize、id、name、brand、unit |
| 90天未更新 | 一期 | id、name、updatedAt、ageDays |
| 低库存/缺货清单 | 二期 | id、name、stock_qty、min_stock、unit、category、location、status |

每行附 asOf/timeZone/range/from/to/includeDeleted/metricVersion/deletedAt；保证过滤和可见页面快照一致。导出全部匹配行，摘要Top限制不截断原始清单。UTF-8 BOM、RFC4180引号/换行转义；对以=、+、-、@、制表/回车等危险前缀开头的文本做电子表格公式注入防护；数值列按数值输出，不人为拼单位。未知数值留空并输出reason，零保留0。零命中清单可以下载仅表头（配套元数据摘要标rowCount=0），不虚构数据行。

默认不导出图片URL与备注正文；需要时后续显式字段选择，避免把私人数据当报表副产品。归档仅指用户主动下载快照文件，命名storage-report-时间-范围，保存到用户选择位置；不新增后台归档任务、不自动上传、不持久化整库副本。CSV快照不能恢复已物理清理数据，也不是库存历史账本。
