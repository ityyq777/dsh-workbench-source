# 工作区实体与任务关联（tasks 5.1.0）

## 1. 目标与边界

任务域新增独立的「工作区」实体，与任务构成多对多关系：一个任务可关联 0..n 个工作区，一个工作区可挂 0..n 个任务。工作区目录是可选的**本机绝对路径**，本期只保存与回显，不据此创建会话或终端。

不做：根据 `dir` 自动创建 DSH 会话、解析符号链接、校验目录存在性、独立工作区管理页、自动把当前会话目录写入工作区。

## 2. 数据模型

`task_workspace`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | 工作区 id |
| `title` | TEXT NOT NULL | 标题；不设唯一约束（不同机器可能有同名工作区） |
| `name` | TEXT NOT NULL DEFAULT '' | 简称/标识 |
| `description` | TEXT NOT NULL DEFAULT '' | 详细描述；非本机工作区可在此说明为什么没有路径 |
| `dir` | TEXT | 本机绝对路径，可空 |
| `created_at` / `updated_at` / `deleted_at` / `rev` | INTEGER | 与任务域其它表一致 |

`task_workspace_link`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | 确定性规则 `workspace_id + ":" + task_id`，便于多设备同步幂等 |
| `workspace_id` / `task_id` | TEXT NOT NULL | 关联两端；与 `task_timeline_link` 不同，`task_id` **不能**唯一——多对多允许多行 |
| `created_at` / `updated_at` / `deleted_at` / `rev` | INTEGER | 软删保留行 |

索引：`idx_task_workspace_updated`、`uk_task_workspace_link(workspace_id, task_id) WHERE deleted_at IS NULL`、`idx_task_workspace_link_task`、`idx_task_workspace_link_ws`。

## 3. 迁移与版本

- `createSchema` 追加 `WORKSPACE_DDL`，`CREATE TABLE IF NOT EXISTS` + `CREATE INDEX IF NOT EXISTS`，重复启动幂等。
- `task_schema_version` 升到 `6`。
- 只新增表与索引，不改既有列。

## 4. 生命周期与可见性

- 删除任务：同一事务内软删该任务的全部工作区关联。
- 删除工作区：软删工作区并同事务软删全部关联，任务不动；`dryRun` 返回将要影响的关联数与任务数。
- 不做级联硬删。
- 查询一律三向 live join：`link.deleted_at`、`task.deleted_at`、`task_workspace.deleted_at` 任一非空即不可见。

## 5. 目录语义

`dir` 非空时只允许本机绝对路径：

- POSIX：以 `/` 开头；
- Windows：盘符 `X:\\` 或 `X:/`，或 UNC `\\\\host\\share`。

只做 `trim`，不做 `realpath`、不校验存在性、不解析符号链接。非法值返回 `WORKSPACE_DIR_INVALID`。

## 6. Action 契约

| Action | 入参 | 回执 |
| --- | --- | --- |
| `taskWorkspaces.create` | `title`, `name?`, `description?`, `dir?` | `{workspace}` |
| `taskWorkspaces.get` | `id` | `{workspace, taskCount}` |
| `taskWorkspaces.update` | `id`, `title?`, `name?`, `description?`, `dir?`（`null` 清空） | `{workspace}` |
| `taskWorkspaces.delete` | `id`, `dryRun?` | `{ok, dryRun, id, workspace, affectedLinks, affectedTasks, taskIds}` |
| `taskWorkspaces.list` | `keyword?`, `directoryOnly?`, `pageNumber?`, `pageSize?`（上限 100） | `{records(含 taskCount), total, returned, pageNumber, pageSize, filter}` |
| `taskWorkspaces.attach` | `workspaceId`, `taskIds[]` | `{workspace, attached, existing, failed:[{taskId, reason}]}` |
| `taskWorkspaces.detach` | `workspaceId`, `taskIds[]` | `{workspace, detached, missing[]}` |
| `tasks.workspaces` | `id` | `{taskId, workspaces}` |

错误码：`WORKSPACE_ID_REQUIRED`、`WORKSPACE_NOT_FOUND`、`WORKSPACE_DELETED`、`WORKSPACE_TITLE_REQUIRED`、`WORKSPACE_DIR_INVALID`、`WORKSPACE_LINK_INVALID`、`WORKSPACE_LINK_ID_MISMATCH`。

任务侧接入：

- `tasks.create` 的 `workspaceIds`：创建任务后同一事务写关联；任一 id 不存在/已删则整体回滚。
- `tasks.update` 的 `workspaceIds`：整体替换（先软删旧关联再建新关联），未传不动；与状态/接取等字段更新同一事务。
- `tasks.get`：`workspaces: [{id,title,name,dir}]`，文本回执加一行「工作区：A（dir=…）、B」。
- `tasks.list`：`workspaceIds`（OR）与 `noWorkspace`（NOT EXISTS）互斥，记录批量附带 `workspaces`，避免 N+1；`export` 的 JSON/CSV/Markdown 增加工作区列。
- 删除任务时连带软删关联。

## 7. 同步与备份

- `taskSync.tables` 顺序：`task` → `task_timeline` → `task_timeline_link` → `task_workspace` → `task_workspace_link` → `task_node`。父表先于子表；父行未到时 link 不丢行，由查询侧 live join 过滤。
- `task_workspace_link` 的 `normalizeIncoming` 校验 `id === workspace_id + ":" + task_id`，不一致返回 `WORKSPACE_LINK_ID_MISMATCH`，整批拒绝而不是写入坏行。
- 备份 `SCHEMA_VERSION` 升到 5，新增两张表的定义；恢复接受 1..5，旧备份缺少两个键时按空数组处理；写入顺序 workspace 先于 link。

## 8. 客户端

- 任务创建/编辑弹窗：工作区多选（chips + 搜索 + 候选列表），支持内联新建（标题/目录/描述），创建后自动选中；编辑保存走 `tasks.update` 的 `workspaceIds` 整体替换。
- 任务卡片：显示工作区 chips，无目录的工作区带 `◦` 前缀，鼠标悬停显示目录全路径。
- 筛选面板：工作区多选 + 「未关联工作区」开关，二者互斥；筛选条件随会话存储一起保存与还原。
- 数据页表清单自动包含两张新表（来自 `tasks.dataTables`）。
