# 邮件自动同步设计（host 0.8.4 起）

本机邮件插件默认只在你打开邮件视图、切文件夹时抓一页信头。这份设计把"收信"从界面动作变成域内后台能力：
开着应用就按配置自动同步，收到新信推给消息中心（装了消息插件时）。

## 1. 目标与非目标

目标：

1. 后台自动同步，**默认开启**，用户可关。
2. 两种模式：**定时循环**（默认）与 **IMAP IDLE**（服务器推送）。
3. 一切自动同步都过**保险箱闸门**：保险箱锁着就不执行，不弹错、不刷日志。
4. 新信推送到消息中心（业务软依赖消息插件，没装就只更新本地）。

非目标：

- 不做 OAuth2；不加后台常驻进程；不改宿主调度器。
- 不在锁定态缓存明文密码（内存里也不留，每轮重新租借）。
- 不自动下载正文与附件（只抓信头，与现有同步语义一致）。

## 2. 配置项（`mail.configGet`）

新增分组 `autosync`，默认值写在代码里，只把覆盖项存 `meta` 表（键 `config.mail.<id>`）。

| id | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `autosync.enabled` | bool | `true` | 自动同步开关（默认开） |
| `autosync.mode` | multi `interval\|idle` | `interval` | 定时循环 / IMAP IDLE |
| `autosync.intervalSec` | int 60–1800 | `300` | 定时循环间隔，也是 IDLE 的兜底探测间隔 |
| `autosync.notify` | bool | `true` | 新信推送到消息中心（需消息插件） |

改配置立即生效：`mail.configSet` / `mail.configReset` 成功后通知自动同步模块重启调度（`onConfigChange`）。四项的 `apply` 声明为 `background`（写完后台立即重新排期），其余配置项仍是 `mount`（下次视图挂载生效）。

枚举项带 `valueLabels`：`interval` = 定时循环 / Interval，`idle` = IMAP 推送 / IMAP push，界面与回执共用这一份标签。

## 3. 保险箱闸门

每轮开始前调 `vault.status`（plugin origin）：

- `locked !== false` 或调用失败 → 本轮**跳过**，不发出任何 IMAP 连接，不报错；只在状态里累计 `skippedLocked`。
- 用户解锁后，下一轮自然恢复；IDLE 模式下同样每轮重连前检查。

理由：密码明文只经 `vault.lease` 按需租借（30–300 秒），锁定态拿不到密码，任何"缓存密码硬撑"都会破坏保险箱模型。

## 4. 定时循环（默认）

`lib/domain/auto-sync.js` 用一个 5 秒粒度的调度器给每个启用账户排期，避免多账户同时握手：

1. 到期的账户先过闸门，再 `mail.probeRecent`（新增，只发 `STATUS INBOX (MESSAGES UIDNEXT UNSEEN)`）。
2. 与本地比较：`remote.uidNext > local.maxUid + 1` 或 `remote.exists > local.count` 判为有新信。
3. 有新信才调现有 `mail.sync`（`limit` 取 `list.pageSize`），只抓信头。
4. `inserted > 0` → 发事件 + 推送消息中心。

没有新信时只花一次连接一条 `STATUS`，不读信头；有变化才走完整同步。

## 5. IMAP IDLE

`lib/infra/imap-idle.js` 为每个启用账户维持一条常驻连接：

1. 连接、`SELECT INBOX`，发 `IDLE`。
2. 服务器回 `* n EXISTS` → 退出 IDLE（`DONE`），对该账户跑一次第 4 节的同步，然后重新 IDLE。
3. 每 25 分钟主动 `DONE` 重发一次 IDLE（RFC 2177 要求 29 分钟内重发，留余量）。
4. 断线、`BYE`、服务器不支持 IDLE（`NO`/`BAD`）→ 记一条错误并按 5s→5min 指数退避重连；等待期间靠兜底探测（`autosync.intervalSec`）保证不收不到信。
5. 兜底：即使 IDLE 正常，也按 `autosync.intervalSec` 跑一次探测，防止服务器漏推。

## 6. 新信通知

`inserted > 0` 时：

- 域内发 `api.emit("mail.synced", { accountId, mailbox, inserted, exists })`，界面订阅后自动刷新列表。
- 若 `api.hasDomain("wb-addon-message")`：`api.call("message.send", {...})`（setupApi 固定 plugin origin），标题 `新邮件（账户名）：主题`，正文最多三条 `发件人 · 主题`，`level: "info"`，`source: "mail"`，`meta: { accountId, inserted }`，`dedupeKey: "mail:new:<accountId>:<最大uid>"`（同一批信只提醒一次）。
- 没装消息插件时只发事件，不报错（业务软依赖）。

## 7. 状态与可见性

新增只读 action `mail.autoSyncStatus`：返回是否启用、模式、间隔、每个账户的 `lastAt` / `lastInserted` / `lastError`，以及 `skippedLocked`、`lastAt`。配置页顶部显示一行摘要，失败只显示"上次自动同步失败：…"，不弹全局提示。

## 10. 风险

| 风险 | 处理 |
| --- | --- |
| 多账户同时握手被服务器限流 | 5 秒调度器 + 每账户独立到期时间 |
| IDLE 长连接被中间设备掐断 | 25 分钟重发 + 断线退避 + 定时兜底 |
| 服务器不支持 STATUS UIDNEXT | 退回只比较 `exists` |
| 每次轮询都租密码 | 只在真正发连接前租借，租约随连接结束丢弃 |
